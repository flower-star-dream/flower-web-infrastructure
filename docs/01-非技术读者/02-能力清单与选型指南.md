# 能力清单与选型指南（写给业务、产品与决策者）

> 本文面向**不写代码**的读者，用表格把框架的全部能力讲清楚，并给出「什么场景该选什么」的判断依据。
> 每项能力标注：解决什么问题、默认状态、是否需要外部服务、成本提示。

---

## 1. 能力总览（一图看懂框架能做什么）

框架把后端系统的能力分为四大类：

| 类别 | 包含能力 | 一句话 |
| ---- | -------- | ------ |
| **地基** | 应用装配、配置管理、统一响应与错误码、日志、请求上下文 | 系统怎么启动、怎么读配置、怎么对外说话、怎么留痕迹 |
| **数据与中间件** | 数据库、缓存、消息队列、对象存储、注册中心、定时任务、异步任务 | 数据怎么存、怎么加速、怎么异步、文件怎么放、服务之间怎么找 |
| **安全与业务** | 认证登录、权限、验证码、防爆破、多租户、幂等、状态机、支付、搜索 | 你是谁、你能干什么、业务状态怎么流转 |
| **智能与运维** | AI 模型网关、RAG 检索、容量评估、监控指标 | 接大模型、私域知识库问答、系统撑不撑得住、哪里有问题 |

## 2. 能力明细表

> 图例：🟢 开箱即用（无需外部服务）｜🟡 可选（需要安装组件 + 配置）｜🔴 默认关闭（按需开启，通常需要外部服务）

### 2.1 地基类

| 能力 | 解决什么问题 | 状态 | 需要外部服务？ |
| ---- | ------------ | ---- | -------------- |
| 应用装配 | 一套配置自动启动全部组件，不用手写初始化代码 | 🟢 | 无 |
| 配置管理 | 一份配置文件管所有开关；支持环境变量、加密敏感信息、多环境切换 | 🟢 | 无（可选 Nacos 配置中心） |
| 统一响应格式 | 所有接口返回统一结构，前端对接零歧义 | 🟢 | 无 |
| 错误码体系 | 报错有统一编码（参数错/没权限/系统忙…），可排查可追踪 | 🟢 | 无 |
| 日志与链路追踪 | 一次用户操作从头到尾能串起来查 | 🟢 | 无 |
| 健康检查 | 系统活着吗？依赖组件正常吗？（供容器/平台探活） | 🟢 | 无 |

### 2.2 数据与中间件类

| 能力 | 解决什么问题 | 默认→生产 | 外部服务 |
| ---- | ------------ | ---------- | -------- |
| 数据库访问 | 读写 MySQL / MongoDB / SQLite，自动管理事务与连接 | SQLite → MySQL / MongoDB | 🟡 MySQL 或 MongoDB |
| 缓存 | 高频数据加速读取，防止数据库被压垮；防穿透、防雪崩 | 内存 → Redis | 🟡 Redis |
| 消息队列 | 业务解耦：订单创建后发消息，后续环节异步处理 | 内存 → RocketMQ | 🟡 RocketMQ |
| 可靠投递（Outbox） | 保证「数据库已写入的消息」一定不丢（支付回调、关键事件） | 内存表 → MySQL 表 | 🟡 随数据库 |
| 对象存储 | 文件/图片/视频上传下载、断点续传 | 本地目录 → MinIO | 🟡 MinIO 或 S3 兼容服务 |
| 服务注册发现 | 微服务之间互相找到对方（电话簿） | 内存 → Nacos | 🟡 Nacos |
| 服务间调用（Feign） | 微服务互相调接口，自带重试、熔断、降级 | 内存注册表直接可用 | 🟡 配合注册中心 |
| 定时任务 | 每天/每 X 秒执行的事：对账、清理、报表 | 🟢 | 无（多实例防重复需分布式锁） |
| 异步任务 | 后台跑耗时任务（导出、批量处理），可跟踪进度 | 🟢 | 无 |

### 2.3 安全与业务类

| 能力 | 解决什么问题 | 状态 | 说明 |
| ---- | ------------ | ---- | ---- |
| JWT 登录态 | 用户登录后签发令牌，后续请求携带即可识别身份 | 🟢 | 需配置密钥 |
| 密码加密 | 密码不以明文存储 | 🟢 | bcrypt 算法 |
| 图形验证码 | 防机器人刷接口 | 🟢 | 内存或 Redis |
| 登录防爆破 | 同一账号/同一 IP 连续失败自动锁定 | 🟢 | Redis 版需 Redis |
| 权限控制（RBAC） | 不同角色只能访问授权的接口 | 🟢 | 需业务提供用户系统 |
| OAuth2 客户端凭证 | 机器与机器之间的授权令牌 | 🟢 | 无 |
| 社交登录 | 微信等三方登录（扫码/授权） | 🟡 | 需对接三方开放平台 |
| 多租户 | 一套系统服务多个客户，数据严格隔离 | 🔴 | 按需开启 |
| API 幂等 | 防止重复提交（重复下单、重复转账） | 🟡 | 中间件开关 |
| 通用状态机 | 业务状态流转（待支付→已支付→已退款）规范化 | 🟢 | 无 |
| 支付 | 统一下单/回调/退款/对账/风控，已内置微信支付 | 🔴 | 需微信商户号 |
| 全文搜索 | 站内搜索（商品、文章） | 内存 → Elasticsearch | 🟡 Elasticsearch |
| 隐私保护 | 手机号/身份证脱敏，防止泄露 | 🟢 | 无 |

### 2.4 智能与运维类

| 能力 | 解决什么问题 | 状态 | 说明 |
| ---- | ------------ | ---- | ---- |
| AI 模型网关 | 统一接入多家大模型（OpenAI 兼容协议），场景路由、故障切换、配额管控、计费 | 🔴 | 需模型 API Key |
| RAG 检索 | 基于自家知识库的问答：文档切片→向量化→检索→结合大模型回答 | 🔴 | 可选向量库 |
| Prompt 模板管理 | 提示词模板化、参数化、防注入 | 🟢 | 无 |
| 内容安全 | 输入/输出内容审核（涉政、暴力等关键词拦截） | 🟢 | 内置规则可扩展 |
| 容量评估 | 预测系统能扛多少并发、哪里是瓶颈 | 🔴 | 无 |
| 监控指标 | 请求量/延迟/错误率/连接池状态等可视化 | 🟢 | 对接 Prometheus + Grafana |

## 3. 选型指南：什么场景选什么

### 3.1 第一步：确定系统形态

```
团队规模小 / 业务刚起步 / 想快速验证 → 单体（min-monolith）
团队大 / 模块独立演进 / 需要独立扩容 → 微服务（min-microservice）
不确定 → 先单体，保持规范一致，日后可拆
```

### 3.2 第二步：按业务需求勾选能力

| 如果你的业务…… | 需要的能力 | 需要准备的外部服务 |
| --------------- | ---------- | ------------------ |
| 需要用户注册登录 | 认证、密码加密、验证码、防爆破 | 无（Redis 可选） |
| 有订单/交易 | 支付、状态机、幂等 | 微信商户号（可选） |
| 需要保证关键消息不丢 | Outbox 可靠投递 | 数据库 + 消息队列 |
| 有多家客户且数据隔离 | 多租户 | 数据库（按租户分库） |
| 想接入大模型能力 | AI 网关、Prompt、内容安全、RAG | 模型 API Key |
| 有站内搜索需求 | 全文搜索 | Elasticsearch |
| 有文件上传 | 对象存储 + 分片上传 | MinIO（本地目录开发可用） |
| 要拆分服务 | 注册中心、Feign 调用、网关 | Nacos + 消息队列 |
| 要监控线上 | 监控指标 + 容量评估 | Prometheus + Grafana |

### 3.3 第三步：成本估算（决策者视角）

| 项目 | 成本类型 | 说明 |
| ---- | -------- | ---- |
| 框架本身 | 免费开源 | MIT 协议，可商用 |
| 外部服务 | 部署与运维成本 | MySQL/Redis/MinIO 均可自建；云厂商也有托管版本 |
| 人力成本 | 学习成本低 | 团队会 Python 即可上手；文档体系完整 |
| 风险 | 低 | 所有能力遵循同一套标准，换组件只改配置不动代码 |

## 4. 默认「开箱即用」与「需要按需开启」的边界

框架的设计原则：**越轻越好**——只装你要用的。

| 开箱即用（最小安装自带） | 需要主动开启/安装 |
| ------------------------ | ----------------- |
| 应用装配、配置、日志、统一响应、错误码 | 认证/鉴权/支付能力链（依赖业务用户系统） |
| 健康检查、监控指标 | MySQL/Redis/Mongo 数据访问（装 extras） |
| 内存缓存、内存消息队列、本地文件存储 | Nacos/RocketMQ/MinIO（装 extras + 配置） |
| 重试、熔断、限流、分布式锁（内存版） | AI 网关、多租户、容量评估、搜索 |
| JWT 等安全工具类 | 微信支付 |

> 提示：业务可选能力（用户系统 → 认证 → 鉴权 → 支付）存在**依赖链**：选支付会自动带出鉴权、认证、用户系统，框架自动处理，业务侧无需操心顺序。

## 5. 常见误区

- ❌ **「用框架就得用微服务」**——单体模式同样受支持，且是默认推荐起步形态。
- ❌ **「组件越多越好」**——框架按需裁剪，装什么用什么，避免维护负担。
- ❌ **「内存版组件能上生产」**——内存缓存/内存消息队列/本地文件仅用于开发测试或单机场景，生产请切换到 Redis/RocketMQ/MinIO。
- ❌ **「不用框架就是安全」**——安全能力默认关闭依赖业务用户系统，需显式开启并完成业务实现。
