              把 `/capacity` 加入 AuthMiddleware 默认白名单并同步各 application.yml
              （框架默认配置 + 两个脚手架活模板），为后续 capacity 模块装配铺路。

## 背景

设计文档 §8 装配硬性约束：`/capacity` 必须加入 AuthMiddleware 默认白名单，否则启用
auth 中间件后该端点被 401 拦截。阶段 0 只做配置与代码默认值同步（不实现 capacity 模块本身），
独立可测试、可提交。`scaffold/versions/v0.1.0` 为历史基线快照，按项目约定**不改**；
脚手架派生源为 `services/` 活模板（new_project.py 从 services/ 复制）。

## 目标

1. 框架 `AuthMiddleware` 默认白名单（代码默认值）加入 `/capacity`；
2. 框架 `application.default.yml` auth.whitelist 加入 `/capacity`；
3. 单体脚手架根 `application.yml` auth.whitelist 加入 `/capacity`；
4. 微服务脚手架 `user-service` / `order-service` 的 application.yml 加入 `/capacity`；
5. 框架测试断言白名单含 `/capacity`，全量回归通过。

## Tech Stack

Python 3.10+ / FastAPI / Starlette 中间件 / yaml 配置 / pytest
