## 目标

1. 新建 `web_infra/capabilities/capacity/` 模块（10 文件）；
2. 新建 `web_infra/infra/web/diagnostic_access.py`（DiagnosticAccessGuard）；
3. Application 装配 `_setup_capacity()` + lifespan 采样任务启停；
4. application.default.yml 新增 app.capacity / app.diagnostics 配置段默认值；
5. 5 个测试文件（静态估算 / 运行时采样 / 远程探针 / 编排输出 / 访问守卫），全量回归通过；
6. 文档同步（使用说明.md / 常量与错误码.md）。

## 任务分解（按依赖顺序）

### Task 1: report.py —— 报告数据模型（无依赖）
- `CapacityReport`（静态/运行时/集群三区 + 建议）、`ComponentCapacity`（逐组件并发上限）、
  `RuntimeSnapshot`（窗口均值/峰值）、`ClusterSnapshot`（实例状态）、`CapacitySuggestion`。

### Task 2: capacity_config.py —— 配置模型
- `CapacityConfig`（app.capacity 段：enabled/cpu_cores/memory_mb/workload_type/io_concurrency_factor/
  assumed_avg_latency_ms/safe_ratio/slo_alert_ratio/sample_window/sample_interval/remote/remote_targets）、
  `RemoteProbeConfig`（connect/read/write/pool/timeout/max_retries/diff_interval/max_response_bytes）、
  `DiagnosticAccessConfig`（app.diagnostics.access 段：enabled/allowed_cidrs）。

### Task 3: static_estimator.py —— 静态估算器（依赖 config）
- 逐组件并发上限（Web/MySQL/Redis/Mongo/CPU 按负载类型）、min 瓶颈、Little's Law 理论 QPS、
  安全水位、限流/SLO 反推。读取 Settings 与硬件探测（os.cpu_count + 配置覆盖）。
- 复用 `IPAddressUtil` 不涉及；数据来源经 Settings 读取各池配置。

### Task 4: runtime_sampler.py —— 运行时采样器（依赖 config）
- 直读 `prometheus_client.REGISTRY.collect()`：QPS 差分、in_flight 并发、histogram 分位数近似。
- 滑动窗口 deque；`sample()` 即时采样；`snapshot()` 窗口均值/峰值。
- 跨平台 CPU 采样：Linux /proc/stat、Windows ctypes GetSystemTimes、其他 psutil/None。

### Task 5: remote_probe.py —— 远程探针（依赖 config）
- httpx 拉取 /metrics + prometheus 文本解析；快照差分（diff_interval=0）/ 独立差分（>0）；
  asyncio.gather 并发拉取；asyncio.wait_for 总耗时；max_response_bytes 限制；单实例失败隔离。

### Task 6: capacity_metrics.py —— Prometheus Gauge
- capacity_theoretical_max_qps / safe_qps / current_qps / current_concurrency /
  utilization_ratio / bottleneck（label=component）。

### Task 7: assessor.py —— 评估编排（依赖全部）
- `CapacityAssessor`：组合 StaticEstimator + RuntimeSampler + RemoteProbe → CapacityReport；
  采样任务 run（asyncio 循环）与 stop；刷新 Gauge。

### Task 8: capacity_endpoint.py —— /capacity 端点 + HTML（依赖 assessor）
- GET /capacity：内容协商 JSON/HTML（复用 should_render_html 模式 + BigIntJSONResponse）；
  access_guard 参数（None 不限制）；render_capacity_html 页面。

### Task 9: cli.py —— CLI（依赖 assessor）
- `python -m web_infra.capabilities.capacity [--json] [--remote]`；退出码 0/2（全部不可达）。

### Task 10: __init__.py —— 模块导出
- 导出 CapacityAssessor / CapacityReport / CapacityConfig / DiagnosticAccessConfig 等。

### Task 11: infra/web/diagnostic_access.py —— DiagnosticAccessGuard
- 生产 IP 白名单守卫：fail-closed（get_client_ip 返回 None 拒绝）、精确白名单 5 段 +
  allowed_cidrs、复用 `_parse_ip`/`_in_any_network`（IPv4-mapped 自动转 IPv4）、403 JSON + 日志溯源。

### Task 12: application.py 装配 + lifespan
- `_setup_capacity()`（_setup_tenant 与 _setup_health 之间）；`_start/_stop_capacity_sampler`；
  DiagnosticAccessGuard 构造并传入 health 端点（/metrics 共用）。

### Task 13: application.default.yml 配置段
- app.capacity.* 与 app.diagnostics.access.* 默认值（收敛于默认配置文件）。

### Task 14: 测试文件 + 文档同步
- tests/test_capacity_static_estimator.py / test_capacity_runtime_sampler.py /
  test_capacity_remote_probe.py / test_capacity_assessor.py / test_diagnostic_access.py；
- docs/使用说明.md capacity 章节、docs/常量与错误码.md 403 错误码登记。
