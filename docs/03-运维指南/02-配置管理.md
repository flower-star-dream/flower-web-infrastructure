## 1. 配置加载优先级

框架配置统一收敛于 `src/web_infra/infra/config/application.default.yml`（禁止在代码内嵌默认值），业务通过 `application.yml` 或环境变量覆盖。加载优先级（源码 `Application._resolve_settings` / `Settings.default_source`）：

```
代码 dict（create_app({...}) 覆盖层） > 进程/容器环境变量（含 .env 加载的值） > 项目根 application.yml > 框架默认 application.default.yml
```

- `create_app({"app.name": "demo"})`：dict 覆盖层经 `CompositeConfigSource(DictConfigSource(settings), default_source)` 置于最高优先级，用于启动期代码覆盖；
- `Settings.default_source()` 组合顺序（越靠前优先级越高）：`EnvConfigSource` → `YamlConfigSource("application.yml")` → `YamlConfigSource(application.default.yml)` → 空 `DictConfigSource`；
- `.env` 文件在包导入时经 `load_env_file()` 加载进环境变量（不覆盖已存在变量），其值**等效于环境变量层**参与优先级判定；
- YAML 支持 `${ENV}` / `${ENV:default}` 占位符：环境变量已定义取其值，未定义取默认值，均无则保留原样。

```python
from web_infra import create_app

# dict 覆盖层优先级最高（仅覆盖指定键，其余回落 yml/默认）
app = create_app({"app.name": "demo"})
```

```bash
# 等效覆盖：环境变量 > application.yml
$env:APP_NAME="demo"
```

**配置溯源**（排查"配置不生效"时按序核对）：

1. 代码里是否硬编码覆盖（`create_app({...})` dict 层优先级最高）；
2. 进程/容器环境变量是否已注入同名 `APP_*`（优先于 yml）；
3. 项目根 `application.yml` 是否存在且键拼写正确（点分隔）；
4. 框架默认 `application.default.yml` 是否被误改（随包安装，改不生效）。

> 常见误判：修改了 `application.yml` 但启动 cwd 不在项目根（`.env`/yml 未加载）；或环境变量与 yml 同时配置时误以为 yml 优先。

## 2. .env 文件使用

- **包导入自动加载**：`import web_infra` 时即加载当前工作目录 `.env`（`load_env_file`，早于 `create_app`），保证 `SNOWFLAKE_WORKER_ID` / `LOCAL_STORAGE_PRESIGN_SECRET` 等模块级读取能拿到值。
- **不覆盖已存在环境变量**：`load_dotenv(override=False)`——进程/容器注入的变量优先，`.env` 仅填充缺失项（部署注入优先级高于 .env，见 [部署与 Docker](./01-部署与Docker.md) §8）。
- `.env` 已被 `.gitignore` 忽略；复制 `.env.example` 填写即可。未安装 python-dotenv 时跳过加载并告警（不影响配置读取，仅敏感值缺失）。

```bash
# 项目根目录
cp .env.example .env
# 编辑填写敏感值：数据库密码、Nacos 账号、支付密钥等
```

```dotenv
# 完整 .env 示例（微服务形态，摘自脚手架 .env.example 要点）
APP_ENV=prod                                   # 生产环境标识（§5）
APP_DB_MYSQL_HOST=10.0.8.20
APP_DB_MYSQL_PORT=3306
APP_DB_MYSQL_USERNAME=app_user
APP_DB_MYSQL_PASSWORD=prod_pwd_xxx
APP_DB_USER_MYSQL_DATABASE=flower_user         # 服务分库（user-service）
APP_CACHE_REDIS_HOST=10.0.8.21
APP_CACHE_REDIS_PASSWORD=
APP_REGISTRY_NACOS_SERVER=10.0.8.22:8848
APP_REGISTRY_NACOS_NAMESPACE=public
APP_REGISTRY_NACOS_PASSWORD=prod_nacos_pwd
NACOS_REGISTER_IP=10.0.8.10                    # 注册对外 IP（容器部署必配，见 部署与Docker §7）
CONFIG_ENCRYPT_KEY=xxx                         # enc: 加密值密钥（§4.2）
SNOWFLAKE_WORKER_ID=1                          # 雪花 ID worker_id（多实例唯一）
JWT_SECRET_KEY=xxx                             # 启用 auth 中间件时必填
DATABASE_URL=mysql+aiomysql://app_user:prod_pwd_xxx@10.0.8.20:3306/flower_user   # Alembic 迁移
LLM_API_KEY=sk-xxx                             # AI 模型 Key（env:LLM_API_KEY 引用）
```

> 启动命令约定在项目根目录执行（`cwd` 决定 `.env` 与 `application.yml` 的解析路径）；容器内挂载 .env 或经 `--env-file` 注入（[部署与 Docker](./01-部署与Docker.md) §8）。

## 3. 环境变量映射规则

配置 key（点分隔）与环境变量按「大写 + 点转下划线」互转（源码 `config_utils._to_env_name`），带 `APP_` 前缀：

| 配置 key | 环境变量 |
| ---- | ---- |
| `app.db.mysql.host` | `APP_DB_MYSQL_HOST` |
| `app.cache.redis.password` | `APP_CACHE_REDIS_PASSWORD` |
| `app.registry.nacos.server_addresses` | `APP_REGISTRY_NACOS_SERVER_ADDRESSES` |

- 环境变量源直接以 `contains/get` 命中配置 key（`os.environ` 查找 `APP_DB_MYSQL_HOST`），与 yml 合并时按 §1 优先级覆盖；
- 映射规则为**双向**：yml 中写 `${APP_DB_MYSQL_HOST:127.0.0.1}` 占位符，环境变量注入即覆盖；非敏感默认值（host/port/database）在 `application.default.yml` 中保持字面默认，同样可经环境变量覆盖。

常用映射速查（完整清单见 [配置参考](../02-开发者指南/03-配置参考.md)）：

| 配置 key | 环境变量 | 注入值示例 |
| ---- | ---- | ---- |
| `app.db.mysql.host` | `APP_DB_MYSQL_HOST` | `10.0.8.20` |
| `app.db.mysql.password` | `APP_DB_MYSQL_PASSWORD` | `prod_pwd_xxx` |
| `app.cache.redis.host` | `APP_CACHE_REDIS_HOST` | `10.0.8.21` |
| `app.registry.nacos.server_addresses` | `APP_REGISTRY_NACOS_SERVER_ADDRESSES` | `10.0.8.22:8848` |
| `app.storage.minio.access_key` | `APP_STORAGE_MINIO_ACCESS_KEY` | `minioadmin` |
| `app.mq.rocketmq.name_server` | `APP_MQ_ROCKETMQ_NAMESERVER` | `10.0.8.23:9876` |
| `app.logging.file` | `APP_LOGGING_FILE` | `logs/app.log` |

> 注：脚手架 yml 占位符可自行定义别名（如 `${APP_REGISTRY_NACOS_SERVER:...}`），框架自动映射则固定为 `APP_` + key 大写化；两者并存时以各自 yml 写法为准，避免混用造成困惑。

## 4. 敏感信息三法

### 4.1 方法一：环境变量注入（推荐，首选）

敏感配置一律经 `${ENV:default}` 占位符外置，值写入 `.env` / 容器注入，**禁止明文随 yml 提交仓库**。框架默认配置中 MySQL/Redis/MongoDB 账号密码、MinIO/Nacos 访问密钥均已内置该写法，业务只需在 `.env` 填值。

```yaml
# application.yml（框架默认已内置同样写法）
app:
  db:
    mysql:
      username: ${APP_DB_MYSQL_USERNAME:root}
      password: ${APP_DB_MYSQL_PASSWORD:}
```

### 4.2 方法二：enc: Fernet 加密值（ConfigCipher / SecureConfigLoader）

配置值以 `enc:base64密文` 存储（Fernet 对称加密），运行时经 `CONFIG_ENCRYPT_KEY` 解密（`SecureConfigLoader` 读取 JWT 等安全密钥时自动解密；`ConfigCipher.decrypt` 对 `enc:` 前缀值处理，非加密值原样返回）。密钥缺失/解密失败时降级为原样返回（不阻断启动，但值不可用需告警排查）。

生成密钥与密文：

```bash
# 1) 生成 Fernet 密钥（cryptography 为框架核心依赖）
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
# 输出示例：Abc123...（url-safe base64 的 32 字节）

# 2) 加密明文值
python -c "from cryptography.fernet import Fernet; k=Fernet(b'<上一步输出的密钥>'); print('enc:'+k.encrypt(b'prod_pwd').decode())"
# 输出示例：enc:gAAAAAB...

# 3) 密钥经环境变量注入（禁止落盘代码/配置文件）
# .env: CONFIG_ENCRYPT_KEY=<密钥>
```

```python
# 业务读取（SecureConfigLoader）：enc: 前缀自动解密，非加密值原样返回
from web_infra.capabilities.security import SecureConfigLoader

secret = SecureConfigLoader.get_jwt_secret()   # 必须来自环境变量 JWT_SECRET_KEY，支持 enc: 密文
```

验证加密值可解密（密钥一致时输出原明文，密钥错误/缺失时降级返回原样并告警）：

```bash
python -c "from web_infra.infra.config.config_cipher import ConfigCipher; print(ConfigCipher().decrypt('enc:gAAAAAB...'))"
```

> 降级语义（`ConfigCipher`）：密钥缺失/格式非法/解密失败（InvalidToken/base64 非法/非 UTF-8）时**告警并原样返回密文，不抛错**——避免配置加载导致启动失败；若业务拿到 `enc:` 开头的"明文"，按日志告警核对 `CONFIG_ENCRYPT_KEY`。

### 4.3 方法三：AI 模型 api_key 的 env:VAR 引用

AI 模型配置（yml 或数据库 `ai_model_config` 表）的 `api_key` 列**仅存 `env:VAR` 引用**，真实密钥经环境变量注入，禁止明文落盘（AI 规范 §3.1/AI-7）。运行时 `ModelConfig.resolved_api_key` 以 `env:` 前缀解析 `os.environ`。

```yaml
# application.yml（app.ai.store.type=yml 时）
app:
  ai:
    enabled: true
    models:
      - model_code: deepseek-chat
        provider: openai_compatible
        api_base: https://api.deepseek.com/v1
        api_key: "env:LLM_API_KEY"     # 仅存引用，禁止明文
```

```sql
-- 数据库模型配置（app.ai.store.type=db 时，db/init/dml/002 示例）
INSERT IGNORE INTO ai_model_config (...) VALUES (..., 'env:LLM_API_KEY', ...);
```

```dotenv
# .env
LLM_API_KEY=sk-xxx
```

## 5. 多环境管理

环境标识 `app.env`，环境变量 `APP_ENV` **优先于** yml 配置（源码 `Settings._resolve_app_env`）；合法值 `dev/test/stage/prod`，未显式指定或非法值时按 `dev` 兜底并告警（规范 §19.3：生产环境必须显式指定 `APP_ENV=prod`）。

| 行为 | dev / test / stage | prod |
| ---- | ---- | ---- |
| 诊断端点访问控制（`/capacity`、`/metrics`） | 放行（`app.diagnostics.access.enabled` 配置在非 prod 不生效） | 默认启用 IP 白名单（内网 5 段 + `allowed_cidrs`），外部 IP 403（`E4-SYS-004`），详见 [监控与告警](./03-监控与告警.md) §5 |
| `Settings.is_production()` | False | True |

```yaml
# application.yml
app:
  env: prod
# 或环境变量（优先）：APP_ENV=prod
```

### 5.1 多环境 profile（application-{profile}.yml）

框架配置基类支持 Spring 风格 profile（`BaseConfig.from_yaml_with_profile`）：加载 `application.yml` 后按 profile 合并 `application-{profile}.yml`（profile 文件覆盖基础文件），再叠加环境变量与 Nacos 远程配置。profile 解析优先级：显式参数 > 环境变量 `SPRING_PROFILES_ACTIVE` > `application.yml` 中 `spring.profiles.active` > dev。

```bash
# 按 stage profile 启动（合并 application-stage.yml）
$env:SPRING_PROFILES_ACTIVE="stage"
```

```yaml
# application-stage.yml（可选，覆盖基础配置）
app:
  logging: { level: INFO, format: json }
```

> 与 `APP_ENV` 的关系：`APP_ENV` 是框架 Settings 的环境标识（驱动 prod 行为开关），`SPRING_PROFILES_ACTIVE` 是 profile 文件选择机制，二者独立；生产建议 `APP_ENV=prod` 显式设置。

> 规范 §19.3 要求启动必须显式指定环境：未配置 `APP_ENV` 时日志输出 warning，生产部署漏配将导致 prod 行为（诊断白名单等）不生效，务必在部署编排中注入。

## 6. Nacos 配置中心接入

### 6.1 配置

配置中心与注册中心复用同一 Nacos 客户端（`app.registry.nacos` 段，需安装 `[nacos]` extras），启用配置中心需设置 `config_enabled: true` 与 `data_id`：

```yaml
app:
  registry:
    type: nacos
    nacos:
      server_addresses: ${APP_REGISTRY_NACOS_SERVER:127.0.0.1:8848}
      namespace: ${APP_REGISTRY_NACOS_NAMESPACE:public}
      group: ${APP_REGISTRY_NACOS_GROUP:DEFAULT_GROUP}
      # 配置中心（config 组件）与注册中心复用同一 Nacos 客户端，启用时加：
      config_enabled: true
      data_id: ${APP_CONFIG_NACOS_DATA_ID:}
      # username: ${APP_REGISTRY_NACOS_USERNAME:nacos}
      # password: ${APP_REGISTRY_NACOS_PASSWORD:}
```

### 6.2 加载与合并（NacosConfigLoader）

`NacosConfigLoader` 从 Nacos 拉取 YAML 配置并解析为字典，`merge(local_config)` 做递归深合并——**远程优先级更高**，忽略 None 值（`_deep_merge`）。加载路径（`BaseConfig.from_yaml_with_profile`）：本地 yml + 环境变量覆盖 → Nacos 远程覆盖本地 → 占位符二次解析。

**Nacos 控制台配置内容示例**（data_id = `order-service.yml`，group = `DEFAULT_GROUP`）：

```yaml
# Nacos 配置中心存储的 YAML（远程覆盖本地，键级深合并）
app:
  db:
    mysql:
      pool_size: 16            # 覆盖本地连接池大小
      slow_sql_threshold_seconds: 0.3
  mq:
    outbox:
      publish_interval_seconds: 3
```

**应用侧拉取与合并**：

```python
from web_infra.capabilities.config import NacosProperties, NacosConfigLoader

props = NacosProperties(
    server_addresses="127.0.0.1:8848", namespace="public",
    group="DEFAULT_GROUP", data_id="order-service.yml", config_enabled=True,
)
loader = NacosConfigLoader(props)
remote = loader.load_sync()          # 同步拉取并解析（无事件循环限制，见下）
merged = loader.merge(local_config)  # 远程覆盖本地（递归合并，None 值不覆盖）
```

- 远程拉取失败：`get_config` 失败仅告警返回空串，`merge` 结果为本地配置，**不阻断启动**（加载失败打印提示后继续）；
- 拉取结果中 `app.*` 键递归覆盖本地同路径值；远程配置同样支持 `${ENV:default}` 占位符（加载后二次解析）。

**框架装配路径（可选）**：应用侧除手动 `NacosConfigLoader` 外，配置基类也支持 Spring 风格声明式接入——`spring.config.import` 引用 `nacos:<dataId>` 并配 `spring.cloud.nacos.config` 段（源码 `BaseConfig._resolve_nacos_properties`）：

```yaml
# application.yml（配置基类装配路径，非 APP_* 映射）
spring:
  config:
    import:
      - "nacos:order-service.yml"     # 自动构造 NacosProperties 并加载合并
  cloud:
    nacos:
      server-addr: 127.0.0.1:8848
      config:
        namespace: public
        group: DEFAULT_GROUP
```

### 6.3 SKIP_NACOS_CONFIG

`BaseConfig.from_yaml_with_profile` 在合并远程配置前检查 `SKIP_NACOS_CONFIG`，值为 `1/true/yes`（不区分大小写）时跳过 Nacos 配置中心加载（本地配置继续启动）。用于：Nacos 暂不可用的应急启动、本地联调。

```bash
# 应急：跳过配置中心加载
$env:SKIP_NACOS_CONFIG="1"
```

### 6.4 get_config_sync 无事件循环限制

`NacosConfigClient.get_config_sync` 使用**一次性事件循环 + 一次性连接**（`asyncio.new_event_loop` + 用完即关），仅可在**无运行中事件循环的上下文**调用（如应用启动阶段、CLI/脚本）；若处于事件循环内调用会检测到并告警返回空串（`nacos_get_config_sync_in_event_loop`）——异步代码（如 FastAPI 路由）请改用 `get_config()`（复用长连接，线程安全由 SDK 保证）。

```python
# 同步上下文（启动装配/脚本）✓
cfg = loader.load_sync()

# 异步上下文（async 函数）✗ 会告警返回空，应使用：
cfg = await loader.load()   # 复用长连接
```

### 6.5 配置生效与验证

- **生效时机**：环境变量 / `.env` / `application.yml` 变更需**重启生效**（镜像不可变原则：配置与代码同版构建，避免配置漂移）；Nacos 远程配置变更按加载时机生效（配置基类在启动装配时合并，不做运行时热更新——`NacosConfigLoader` 仅提供拉取与合并，未内置监听回调，热更新需业务自行实现）。
- **验证**：启动日志核对关键配置（应用名/环境/连接地址）；`/health/ready` 确认依赖连通（[排障指南](./05-排障指南.md) §2）；`GET /metrics` 核对 service 标签与实例数。

## 7. 配置项审计与变更流程建议

框架侧配置规范（运维落地建议）：

1. **收敛**：业务配置统一放项目根 `application.yml`（敏感值经占位符外置），禁止散落代码硬编码；新增配置项同步 `application.default.yml` 或业务 yml 注释。
2. **评审**：变更生产配置前走 MR 评审，重点核对：环境变量名拼写（映射规则 §3）、默认值兜底是否安全（密码默认空串不可用于生产）、`app.env`/`APP_ENV` 是否显式 prod。
3. **灰度**：Nacos 配置中心远程配置支持运行时生效——先在小流量实例改远程配置验证，再全量推送；本地 yml 变更需发版（镜像不可变，配置与代码同版构建，避免"配置漂移"）。
4. **审计**：敏感配置变更记录（who/when/what），`CONFIG_ENCRYPT_KEY` 轮换周期建议 ≥90 天（与网关鉴权 kid 机制配合，密钥版本轮换不中断服务）；`.env` 不入库，生产注入凭据走秘密管理（K8s Secret / 配置中心密钥）。
5. **回滚预案**：环境变量覆盖的配置回滚=改回旧值重启；Nacos 远程配置回滚=恢复旧配置版本（配置中心自带版本管理）或临时 `SKIP_NACOS_CONFIG=1` 以本地配置启动（注意本地与远程存在差异时行为不一致，需评估）。

**一次典型变更示例**（生产调整 MySQL 连接池）：

1. 本地/测试环境修改 `application.yml`（或 Nacos 远程配置）`app.db.mysql.pool_size: 8 → 16`，MR 评审（默认值兜底、向后兼容）；
2. 走 CI 构建新镜像（配置与代码同版），测试环境验证 `/health/ready` 与连接池指标；
3. 生产按 §5 流程灰度发布（先一个实例，`APP_ENV=prod` 注入）；
4. 验证 `mysql_pool_connection_total` 指标符合预期后全量；变更记录归档（版本/时间/执行人/影响）。
