## 1. 安装

建议在业务项目内创建虚拟环境后安装，避免全局污染：

```bash
python -m venv .venv
.venv\Scripts\activate
```

### 1.1 最小安装（核心，默认依赖）

```bash
pip install flower-web-infrastructure
```

仅安装**核心依赖**（Web/配置/日志/错误码/安全工具类（JWT/密码加密）/监控/内存缓存），
`import web_infra` 与 `create_app()` 开箱即用。**不含** MySQL/Redis/Mongo 数据访问（代码中延迟导入），
以及 MinIO、Nacos、RocketMQ、Alembic、RAG、PDF 等可选组件；数据库与缓存扩展能力需按需安装 extras（见 1.3）。

**最小安装默认启用的能力**（无需 extras、无需额外配置，`create_app()` 开箱即用）——均为**不依赖用户系统、外部服务与业务实现**的基础能力；依赖链上的业务可选能力（用户系统 → 认证 → 鉴权 → 支付）默认全部关闭（见下"默认关闭"表）：

| 能力 | 说明 |
| ---- | ---- |
| Web 应用装配 | `create_app` / 全局异常处理 / 健康检查（`/health/live`、`/health/ready`）/ 指标端点（`/metrics`） |
| 中间件 trace_id | 链路追踪中间件**默认引入**；auth / idempotency / security_headers **默认关闭**（yml 声明式启用） |
| 配置 / 日志 / 错误码 | 本地 YAML / 环境变量 / 字典源；统一日志格式；`Result` / `ErrorCode` 统一响应与异常处理 |
| 安全工具类 | JWT 签发校验（`JWTUtil`）、密码加密（`PasswordEncoder`）等——仅**工具代码**随核心可导入；**认证/鉴权能力**与支付一样依赖用户系统，默认关闭（见 [4.2](#42-能力依赖与装配)） |
| 监控 | Prometheus 指标（`/metrics`）+ HTML 可视化（组件未启用不产生指标） |
| 内存缓存 | `MemoryCacheBackend`（`app.cache.type: memory`） |
| 内存/本地组件 | 内存 MQ、本地对象存储、内存注册表、内存幂等存储、SQLite 会话（标准库 `sqlite3`）——单机开箱即用，无需外部服务 |
| 韧性工具 | 重试 / 熔断 / 限流 / 分布式锁（内存实现） |
| 能力注册表 | `CapabilityRegistry`（能力契约与依赖包含规则，见 [4.2](#42-能力依赖与装配)） |

**默认关闭、需按需启用的能力**：

| 能力 | 启用方式 |
| ---- | ---- |
| 业务可选能力链 | `user`（用户系统，业务实现）/ `authn`（认证）/ `authz`（鉴权）/ `pay`（支付）——`app.capabilities.enabled` 声明（默认 `[]`，启用支付自动带出 鉴权→认证→用户，见 [4.2](#42-能力依赖与装配)）或显式 `from web_infra.payment import ...` |
| 认证/鉴权中间件 | `app.web.middlewares.auth.enabled: true`（JWT 解析注入身份，默认关闭） |
| 多租户 | `app.tenant.enabled: true` |
| AI 模型网关 | `app.ai.enabled: true` |
| MySQL/Redis/Mongo 数据访问 | 安装 `[mysql]` / `[redis]` / `[mongo]` extras + 配置（框架代码延迟导入） |
| Nacos / RocketMQ / MinIO | 安装 `[nacos]` / `[rocketmq]` / `[storage]` extras + 配置 |
| Alembic / RAG / PDF | 安装 `[migrate]` / `[rag]` / `[pdf]` extras |

> `import web_infra` 与 `from web_infra import *` 均兼容最小安装（不触发可选依赖加载）；
> 已安装 mysql/redis/mongo 对应 extras（非最小安装）时，`from web_infra import *` 自动导出**全部能力**
> （含 `Base` / `MySQLConfig` / `RedisConfig` 等，按已安装依赖动态纳入 `__all__`）；最小安装下这些组件
> 需先安装对应 extras 后显式导入（`from web_infra import MySQLConfig`）。

### 1.2 最小单体 / 最小微服务（安装即用）

按架构形态二选一安装，**安装后复制下方 `application.yml` 模板即可启动**（配置主来源为 yml，统一由框架加载）：

```bash
# 最小单体：核心 + MySQL/SQLite + Redis（单库 + 缓存；MQ/存储用内存/本地实现，无需外部 broker）
pip install "flower-web-infrastructure[min-monolith]"

# 最小微服务：核心 + MySQL + Redis + Nacos + RocketMQ + MinIO（需先就绪外部服务）
pip install "flower-web-infrastructure[min-microservice]"
```

**最小单体 `application.yml` 模板**：

```yaml
app:
  name: demo
  env: dev                     # 生产环境改 prod（APP_ENV 环境变量优先）
  logging: { level: INFO, format: text }
  web:
    middlewares:
      trace_id: {}
      auth: { enabled: false, whitelist: ["/health", "/metrics", "/docs"] }   # 按需启用
  cache: { type: redis }       # 或 memory（无需 Redis 时）
  db:
    type: mysql                # mysql / sqlite
    mysql: { host: 127.0.0.1, port: 3306, database: demo, username: ${APP_DB_MYSQL_USERNAME:root}, password: ${APP_DB_MYSQL_PASSWORD:} }
  storage: { type: local, base_dir: ./data }
  mq: { type: memory }
  registry: { type: memory }
```

**最小微服务 `application.yml` 模板**：

```yaml
app:
  name: demo-svc
  env: dev                     # 生产环境改 prod
  logging: { level: INFO, format: json }
  web:
    middlewares:
      trace_id: {}
      auth: { enabled: true, whitelist: ["/health", "/metrics", "/docs"] }
  cache: { type: redis }
  db:
    type: mysql
    mysql: { host: 127.0.0.1, port: 3306, database: demo, username: ${APP_DB_MYSQL_USERNAME:root}, password: ${APP_DB_MYSQL_PASSWORD:} }
  storage: { type: minio }     # 需 MinIO 服务
  mq: { type: rocketmq }       # 需 RocketMQ 服务
  registry:
    type: nacos            # memory / nacos
    nacos:
      server_addresses: localhost:8848   # 支持逗号分隔多地址
      namespace: ""
      group: DEFAULT_GROUP
      # username: ${APP_REGISTRY_NACOS_USERNAME:nacos}   # 默认 Nacos 认证（敏感配置写 .env）
      # password: ${APP_REGISTRY_NACOS_PASSWORD:}
      # access_key: ${APP_REGISTRY_NACOS_ACCESS_KEY:}    # 阿里云 AK/SK 认证（可选）
      # secret_key: ${APP_REGISTRY_NACOS_SECRET_KEY:}
      # grpc_timeout_ms: 5000           # gRPC 请求超时（毫秒）
      # tls_enabled: false              # TLS 配置（可选）
      # tls_ca_file: ""
      # tls_cert_file: ""
      # tls_key_file: ""
```

启动代码（两种形态一致）：

```python
from web_infra import create_app

app = create_app()   # 读取根目录 application.yml，装配全部组件

if __name__ == "__main__":
    import uvicorn
    uvicorn.run(app, host="0.0.0.0", port=8000)
```

### 1.3 按需追加可选能力

```bash
# MySQL/SQLite ORM 数据访问（SQLAlchemy + 异步驱动）
pip install "flower-web-infrastructure[mysql]"

# Redis 缓存/分布式锁/幂等存储
pip install "flower-web-infrastructure[redis]"

# MongoDB 数据访问
pip install "flower-web-infrastructure[mongo]"

# MinIO 对象存储
pip install "flower-web-infrastructure[storage]"

# Alembic 数据库迁移工具（运维/部署用，非运行时依赖）
pip install "flower-web-infrastructure[migrate]"

# 配置中心（Nacos，官方 nacos-sdk-python v2）与消息队列（RocketMQ）—— 按需启用
pip install "flower-web-infrastructure[nacos,rocketmq]"

# RAG 向量检索（faiss + sentence-transformers）
pip install "flower-web-infrastructure[rag]"

# PDF 渲染导出（playwright）
pip install "flower-web-infrastructure[pdf]"

# 能力依赖链（用户系统/认证/鉴权/支付，可选能力：依赖均为核心依赖，extra 仅作能力声明；
# 启用支付默认启用 鉴权→认证→用户，依赖包含规则由 web_infra.capability 维护，见 4.2）
pip install "flower-web-infrastructure[user,authn,authz,pay]"
```

### 1.4 全量安装

```bash
pip install "flower-web-infrastructure[all]"
```

核心 + 全部可选能力（user / authn / authz / pay / nacos / rocketmq / storage / migrate / rag / pdf / mysql / redis / mongo）一次性安装，适用于开发环境或能力不明确的项目。

### 1.5 本地开发安装（editable）

业务项目与框架在同一台机器开发时，用可编辑模式安装（改框架代码即时生效）：

```bash
pip install -e "f:\baseProject\flower-web-infrastructure"
# 带可选能力
pip install -e "f:\baseProject\flower-web-infrastructure[all]"
```

### 1.6 通过 Git 依赖安装

框架有远程仓库时：

```bash
pip install "git+https://github.com/<org>/flower-web-infrastructure.git@v0.1.0"
```

> 依赖传递：核心依赖（fastapi、pydantic、httpx、uvicorn 等）随安装自动解析，业务项目无需手动安装；sqlalchemy / redis / pymongo 等数据库与缓存 SDK 属可选 extras，需按需安装。

## 2. 快速开始

业务项目根目录提供 `application.yml` 覆盖框架默认配置（默认配置已随包内置），然后通过 `create_app` 启动：

```python
from web_infra import create_app, Result, CommonErrorCode

app = create_app({"app.name": "demo"})  # dict 为可选覆盖层（优先级高于 YAML），配置主来源仍是 application.yml

@app.get("/v1/orders/{order_id}")
def get_order(order_id: str):
    if order_id == "0":
        raise CommonErrorCode.COMMON_NOT_FOUND.to_exception()
    return Result.success(data={"orderId": order_id})

if __name__ == "__main__":
    import uvicorn
    uvicorn.run(app, host="0.0.0.0", port=8000)
```

响应统一为 `{ "code": "S0000", "message": "ok", "data": {...} }`；业务异常经全局异常处理器自动转换为统一错误响应。

## 3. 配置说明

- 配置优先级：**环境变量 > 项目根 `application.yml` > 框架默认 `application.default.yml`**。
- YAML 支持 `${ENV}` / `${ENV:default}` 环境变量占位符：敏感配置（如数据库密码）写为 `${APP_DB_MYSQL_PASSWORD:dev_password}`，由环境变量注入、默认值兜底，避免明文随 yml 提交仓库。
- **推荐做法（框架已内置）**：框架默认配置中的敏感项（MySQL/Redis/MongoDB 账号密码、MinIO/Nacos 访问密钥）均已用 `${ENV:default}` 引用环境变量，业务项目只需将敏感值写入项目根 `.env`（如 `APP_DB_MYSQL_PASSWORD=xxx`）即可生效，无需修改 yml。
- 框架启动时自动加载项目根 `.env`（`.env` 已被 `.gitignore` 默认忽略，复制 `.env.example` 填写即可）；已存在的进程/容器环境变量优先、不被 `.env` 覆盖。
- 中间件 / 多租户 / AI 等特殊能力默认关闭，由业务配置显式启用。
- 环境标识：生产环境必须显式指定 `APP_ENV=prod`（未指定时默认 `dev` 并输出 warning，规范 §19.3）。

```yaml
app:
  name: demo
  env: prod                    # 或环境变量 APP_ENV=prod（优先）
  logging:
    level: INFO
    format: text
  web:
    middlewares:
      auth: { enabled: true, whitelist: ["/health", "/metrics", "/docs"] }
      idempotency: { enabled: true, ttl_seconds: 86400 }
  cache: { type: memory }      # memory / redis
  db:
    type: mysql                # mysql / sqlite
    mysql: { host: 127.0.0.1, port: 3306, database: demo, username: ${APP_DB_MYSQL_USERNAME:root}, password: ${APP_DB_MYSQL_PASSWORD:} }
  storage: { type: local }     # local / minio
  mq: { type: memory }         # memory / rocketmq
  registry: { type: memory }   # memory / nacos
```

已装配组件通过 `app.state.<name>` 访问（cache / db / mongo / storage / mq / registry / ai）。

## 4. 常用功能速览

| 能力            | 入口                                               | 说明                                                                                            |
| --------------- | -------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 统一响应 / 异常 | `Result` / `PageResult` / `错误码.to_exception()` | 错误码`E<大类>-<子类>-<3位编号>`，出网自动边界收敛；业务异常统一 `raise 错误码.to_exception(message=...)` |
| 日志            | `get_logger("order.service")`                    | JSON/文本格式 + 敏感信息脱敏 + TraceId 贯穿链路                                                 |
| 请求上下文      | `RequestContext`                                 | TraceId / 用户 / 租户 / 客户端上下文，跨异步自动透传                                            |
| 认证鉴权        | `app.web.middlewares.auth` + `PermissionGuard` | JWT Bearer 校验 + 白名单 + RBAC 权限点 + 静默刷新（EXPIRING）                                   |
| API 幂等        | `idempotency` 中间件                             | 幂等键 + 请求摘要 + 结果缓存，重放比对 409                                                      |
| 缓存            | `CacheBackendInterface`                          | 内存/Redis 实现；空值防穿透、TTL 抖动防雪崩、本地 TTL 钳制                                      |
| 数据库          | `db.session()` / `db.orm_session()`            | 生命周期自动管理（提交/回滚/关闭）；读写分离`read_replica=True`；游标分页 `CursorPageQuery` |
| 消息队列        | `MessagePublisher` / Outbox                      | 分区选择（partition_key）+ 延迟消息 + DLQ + 幂等消费                                            |
| 服务间调用      | `FeignClient`                                     | 注册中心发现 + 负载均衡 + 重试 + 熔断降级；未传 fallback 时默认统一 503 兜底（可传参自定义）    |
| 定时任务        | `TaskScheduler`                                  | 分布式锁防重复 + 执行记录 + 失败退避                                                            |
| 对象存储        | `ObjectStorageInterface`                         | 本地/MinIO；分片上传/断点续传；签名 URL；属主校验                                               |
| AI 网关         | `app.state.ai`                                   | 模型自动注册 + 场景路由 + 主备降级 + 配额 + 权限校验 + 流内错误分片                             |
| 多租户          | `app.tenant.enabled`                             | X-Tenant-Id 注入 + SQL 条件自动注入 + 数据源动态路由                                            |
| 支付能力        | `web_infra.payment`                             | 渠道 SPI + 骨架兜底 + 微信渠道 + 对账/冲正/风控/审计/权限点（见 [4.1 支付能力](#41-支付能力)）  |
| 监控            | `/health/live` `/health/ready` `/metrics`    | 存活/就绪分离探针；Prometheus 指标 + HTML 可视化 + SLO/错误预算                                 |

具体示例见项目 [README 第 7 节](../README.md#7-常用功能示例)。

### 4.1 支付能力

框架支付模块（`web_infra/payment`）按《Web 系统通用架构规范 · 支付扩展 v1.0》实现渠道接入与资金兜底，能力分层如下：

> **可选能力**：支付不随 `web_infra` 顶层导出（`import web_infra` 不加载支付模块、不注册支付错误码），
> 需要支付的系统显式 `from web_infra.payment import ...` 主动引入（示例见下方快速接入）；部分系统无需支付功能，默认零负担。
> 支付依赖鉴权、鉴权依赖认证、认证依赖用户系统（契约能力，业务实现）——启用能力按包含关系自动带上前置，见 [4.2 能力依赖与装配](#42-能力依赖与装配)。

| 能力 | 入口 | 说明 |
| ---- | ---- | ---- |
| 渠道统一抽象 | `PaymentGateway` + `PaymentGatewayRegistry` | 下单/查单/关单/退款/查退款 SPI，按渠道名注册/查询，未注册快速失败 `E4-PAY-001` |
| 渠道骨架层（§3.1/§3.2） | `PaymentChannelTemplate` | Template Method final 骨架：下单幂等（§4.2）→ 渠道调用 → 三态收敛 → 流水落库（§5.2）；关单前查单确认（§5.5）；回调金额/attach/状态机校验（§4.3/§4.5）；能力位运行期拦截 `E4-PAY-008`；必选抽象漏实现无法实例化 |
| 回调验签解密 | `PaymentCallbackVerifier` + `WeChatCallbackVerifier` | 验签失败回 401 渠道重试、时间戳容差防重放、平台证书自动下载；`PaymentCallbackDispatcher` 业务分发 |
| 支付流水/状态机 | `PaymentFlowStore` + `PaymentStateMachine` | 本地事务表 SPI（幂等域/冲正域/状态域）；状态机含 `EXCEPTION` 挂账态、幂等重复对、终态不可逆 |
| 超时自动关单（§5.5） | `close_expired_orders` | 扫描超时订单 → 骨架关单（查单确认）→ CLOSED；查单失败跳过不强行关单 |
| 对账机制（§6） | `reconciliation` 子包 | T+1 对账：账单 vs 本地流水对齐、五类差异分类、查单确认后自动补记/冲正、金额不一致强制人工 P0 告警、审计落库、任务防重 |
| 冲正（§7.5） | `reversal_flow` | 反向冲正流水 + 原流水标记、幂等、冲正事件钩子（下游补偿失败不阻塞） |
| 风控限额（§9） | `risk` 子包（`PaymentRiskGuard`） | 单笔/日/月限额 `E4-PAY-005`、频次 `E4-PAY-006`、可疑拆分 `E4-PAY-007`；Decimal 精确累计 + 原子 |
| 支付审计（§8.3） | `PaymentAuditStore` | 全链路只增不改、失败同样留痕、原始报文仅落审计；骨架 final 入口注入即自动埋点 |
| 权限点（§8.4） | `PaymentPermission` | `AUTH_PERM_` 前缀常量，退款/冲正/对账独立高风险权限点 |
| 渠道账单文件（§6.7） | `BillFileManager` | 完整性校验（失败丢弃重下）、按账期组织、保留期 ≥ 90 天归档 |
| 支付指标（§11） | `monitoring/payment_metrics` | 下单/回调/退款/渠道调用/冲正/关单/查单兜底率 |
| 契约测试（§3.3/§10.3） | `payment/testing` | `PaymentChannelContract` 9 个资金场景契约用例 + `PaymentCallbackSimulator` 回调模拟器 |
| 默认实现 | `InMemoryPaymentGateway` | 骨架化内存渠道（注入 flow_store/order_store 即获全套兜底），单机/测试开箱即用 |
| 微信渠道 | `WeChatPayProvider` | APIv3 四场景下单 + 查单/关单/退款/查退款 + 回调验签；下单不盲目重试（§7.2 红线） |

**快速接入**（内存渠道演示）：

```python
from web_infra.payment import (
    InMemoryPaymentFlowStore, InMemoryPaymentOrderStore,
    InMemoryPaymentGateway, PaymentGatewayRegistry,
)

gateway = InMemoryPaymentGateway(
    flow_store=InMemoryPaymentFlowStore(),   # 支付流水（§5.2）
    order_store=InMemoryPaymentOrderStore(), # 本地支付订单（§4.2）
)
PaymentGatewayRegistry.register("wechat", gateway)  # 生产替换为 WeChatPayProvider 并注入配置
resp = await gateway.prepay(PaymentPrepayRequest(scene=..., out_trade_no=..., total_amount=...))
```

**详细文档**：支付兜底策略见 [订单兜底策略.md](./订单兜底策略.md)、SPI 说明见 [SPI-Extensions.md §15](./SPI-Extensions.md#15-支付模块payment)。

### 4.2 能力依赖与装配

支付的前置是鉴权，鉴权的前置是认证，认证的前置是用户系统（否则无意义）。框架通过能力注册表（`web_infra/capability`，顶层导出）声明
**能力契约（SPI）+ 依赖包含规则 + 装配校验**，具体业务实现（如用户系统 user-service）由业务层提供；启用能力时
按包含关系自动启用前置（启用支付默认启用鉴权→认证→用户，以此类推）。

- **内置依赖图**（`CapabilityRegistry.names()` 可查）：`user`（用户系统，契约能力，业务实现）→ `authn`（认证）→
  `authz`（鉴权）→ `pay`（支付）——认证/鉴权均依赖用户系统（`web_infra.security`），支付依赖鉴权（`web_infra.payment`）；
  另含 `ai / mq / storage / registry / config / db / cache`，见 [SPI-Extensions.md §17](./SPI-Extensions.md#17-能力注册表capability)。
- **运行时启用**：`CapabilityRegistry.enable("pay")` 解析（校验）后按拓扑序自动导入前置与目标能力的框架模块（幂等）；
  `resolve` / `validate` 分别做拓扑解析与装配校验（未知能力/循环依赖报错，缺前置自动补足）。
- **配置驱动装配（推荐）**：`application.yml` 声明 `app.capabilities.enabled`，`create_app` 装配时自动校验并启用：

```yaml
app:
  capabilities:
    enabled: [pay]   # 自动启用 鉴权(authz)→认证(authn)→用户系统(user)（业务实现由业务层提供）
```

> **默认状态**：`app.capabilities.enabled` 默认空（`[]`）——能力注册表中的**业务可选能力链（user / authn / authz / pay）默认全部关闭**，
> 需按需启用（认证/鉴权与支付一样依赖用户系统，见 [1.1](#11-最小安装核心默认依赖) 默认关闭表）。能力注册表中的 `config / db / cache / mq / storage / registry / ai`
> 为框架**内置模块能力**：其框架代码随核心安装即可用（内存/本地实现开箱即用，如内存 MQ、本地存储、SQLite 会话），
> 外部实现（MySQL / Redis / Mongo / Nacos / RocketMQ / MinIO）仍需对应 extras + 配置；在 `enabled` 中声明它们仅用于
> 显式装配校验与依赖展开（默认无需声明）。

- **业务扩展**：业务层按同一机制登记业务能力并声明依赖（如订单能力 `requires=("pay",)`），详见 [SPI-Extensions.md §17.4](./SPI-Extensions.md#174-业务扩展自定义能力)。

## 6. 数据库变更管理

- 结构变更以 **Alembic** 为权威工具（迁移脚本位于框架项目根 `alembic/versions/`），安装 `pip install "flower-web-infrastructure[migrate]"`。
- **数据库 URL 读取（防硬编码）**：`alembic/env.py` 复用框架 `load_env_file` 自动加载项目根 `.env`，解析顺序 进程/容器环境变量 `DATABASE_URL` > `.env` 中的 `DATABASE_URL` > `alembic.ini` 的 `sqlalchemy.url`（留空）；迁移命令单独执行时同样生效，无需在 shell 预先导出环境变量。
- 日常增量脚本 `db/versions/`（`V{版本}-模块-{描述}-ddl/dml.sql`）：DDL 与 DML 同版本成对提供，涉及存量数据语义变更必须提供幂等 DML。
- 基线脚本 `db/init/` 只随大版本重建，禁止回改；已发布变更一律新增版本脚本演进。

## 8. 常见问题

- **`import web_infra` 失败 / ModuleNotFoundError**：确认已安装 `flower-web-infrastructure`（`pip show flower-web-infrastructure`），且虚拟环境激活正确。
- **使用 MySQL/Redis/Mongo/MinIO/RocketMQ/Nacos 报 ModuleNotFoundError**：对应 SDK 属可选能力（延迟导入），需按 [1.3](#13-按需追加可选能力) 安装对应 extras（mysql / redis / mongo / storage / rocketmq / nacos）。
- **启动提示"未显式指定 APP_ENV"**：生产环境设置环境变量 `APP_ENV=prod`（规范 §19.3）。
- **配置不生效**：确认业务项目根目录存在 `application.yml`，且未在代码中硬编码配置（配置统一收敛于 yml）。
