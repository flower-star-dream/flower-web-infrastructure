# 统一响应与错误码

> 框架约定：**所有接口返回统一结构，所有错误走统一编码**。前端对接零歧义，排查问题有据可查。
> 完整错误码清单见 [常量与错误码.md](../常量与错误码.md)。

---

## 1. 统一响应结构（Result）

所有业务接口返回 `Result`，JSON 结构固定为：

```json
{
  "code": "S0000",
  "message": "ok",
  "data": { }
}
```

| 字段 | 说明 |
| ---- | ---- |
| `code` | 业务码。`S0000` 成功；失败为 `E<大类>-<域>-<编号>` |
| `message` | 人类可读描述（失败时为对外展示文案） |
| `data` | 业务数据；失败时恒为 `null` |

### 使用方式

```python
from web_infra import Result, PageResult

@app.get("/orders")
def list_orders():
    return Result.success(data={"orders": [...]})     # 成功

@app.get("/orders/{oid}")
def get_order(oid: str):
    if oid == "0":
        raise CommonErrorCode.COMMON_NOT_FOUND.to_exception()   # 失败
    return Result.success(data={"id": oid})
```

### 分页响应（PageResult）

```python
from web_infra import PageResult

@app.get("/orders/page")
def page_orders(page_no: int = 1, page_size: int = 20):
    items, total = order_repo.page(page_no, page_size)
    return PageResult.success(records=items, total=total)
```

返回结构（`data.list` 为数据项、`data.total` 为总数）：

```json
{
  "code": "S0000",
  "message": "ok",
  "data": {
    "list": [ ... ],
    "total": 100
  }
}
```

## 2. 错误码体系

### 2.1 分段规则

格式：`E<大类>-<域>-<3位编号>`，成功码为 `S0000`。

| 大类 | 语义 | HTTP 状态 | 日志级别 | 可重试 |
| ---- | ---- | --------- | -------- | ------ |
| `S` | 成功 | 200 | INFO | - |
| `E1` | 参数类 | 400 | INFO | ✗ |
| `E2` | 认证类 | 401 | INFO | ✗ |
| `E3` | 基础设施类 | 500 | ERROR | ✔（唯一可重试大类） |
| `E4` | 业务域类 | 422 | WARNING | ✗ |
| `E5` | 系统类 | 500 | ERROR | ✗ |

子类覆盖：`E2-PERM` → 403；`E3-LOCK` → 423。

### 2.2 常用内置错误码（节选）

| 枚举 | code | HTTP | 场景 |
| ---- | ---- | ---- | ---- |
| `CommonErrorCode.SUCCESS` | S0000 | 200 | 成功 |
| `CommonErrorCode.PARAM_INVALID` | E1-PARAM-000 | 400 | 参数非法 |
| `CommonErrorCode.PARAM_REQUIRED` | E1-PARAM-001 | 400 | 缺少必填参数 |
| `CommonErrorCode.RATE_LIMITED` | E1-RATE-000 | 429 | 触发限流/配额 |
| `CommonErrorCode.AUTH_UNAUTHENTICATED` | E2-AUTH-000 | 401 | 未登录 |
| `CommonErrorCode.AUTH_EXPIRED` | E2-AUTH-001 | 401 | 令牌过期 |
| `CommonErrorCode.AUTH_INVALID` | E2-AUTH-002 | 401 | 令牌非法 |
| `CommonErrorCode.PERM_DENIED` | E2-PERM-000 | 403 | 无权限 |
| `CommonErrorCode.COMMON_NOT_FOUND` | E4-COMMON-000 | 404 | 资源不存在 |
| `CommonErrorCode.COMMON_CONFLICT` | E4-COMMON-001 | 409 | 状态冲突（重复操作等） |
| `CommonErrorCode.SYS_INTERNAL` | E5-SYS-001 | 500 | 系统内部错误 |
| `CommonErrorCode.SYS_UNAVAILABLE` | E5-SYS-002 | 503 | 服务暂不可用 |
| `CommonErrorCode.LOCK_FAILED` | E3-LOCK-000 | 423 | 锁获取失败（可重试） |

各能力域错误码：

| 域 | 前缀 | 文档 |
| -- | ---- | ---- |
| AI | E3-THIRD-*（供应商可重试）、E4-AI-*（业务） | [AI 模型网关](./15-AI模型网关.md) |
| 支付 | E3-PAY-*（渠道可重试/验签）、E4-PAY-*（业务） | [支付](./19-支付.md) |
| 搜索 | E3-SRCH-*、E4-SRCH-* | [搜索引擎](./17-搜索引擎.md) |
| 状态机 | E4-STATE-* | [通用状态机](./18-通用状态机.md) |

### 2.3 自定义业务错误码

业务错误码以 `E4-BIZ-*` 或 `E4-<业务域>-*` 命名，注册后即可用：

```python
from web_infra import ErrorCode, ErrorCodeRegistry, CommonErrorCode

ORDER_NOT_PAYABLE = ErrorCode(
    code="E4-ORDER-001",
    message="订单当前状态不可支付",
    http_status=422,
)
ErrorCodeRegistry.register(ORDER_NOT_PAYABLE)

# 使用
raise ORDER_NOT_PAYABLE.to_exception()
```

> 注册后 `ErrorCodeRegistry.get(code)` / `parse(code)` 可用；未注册的错误码按大类自动推导（HTTP 状态/可重试性/日志级别）。

## 3. 抛出与全局处理

### 3.1 统一抛出约定

```python
# 方式一：错误码直接抛（推荐）
raise CommonErrorCode.COMMON_NOT_FOUND.to_exception()
raise CommonErrorCode.PERM_DENIED.to_exception(message="需要订单管理权限", data={"need": "order:write"})

# 方式二：异常子类
from web_infra import BizException, ParamException, PermException, AuthException

raise BizException("订单金额非法")          # 默认 E4-COMMON-001
raise ParamException("分页参数超出范围")     # 默认 E1-PARAM-000
raise PermException("无权访问")             # 默认 E2-PERM-000
raise AuthException("登录已过期")           # 默认 E2-AUTH-000
```

### 3.2 全局异常处理（框架自动注册）

`create_app()` 已注册 4 个处理器，全部输出统一 Result 结构：

| 异常 | 转换结果 |
| ---- | -------- |
| `WebInfraException`（含子类） | 按错误码转码；服务端日志保留完整错误码，出网响应做边界收敛 |
| FastAPI 参数校验失败 | E1-PARAM-000 / 400 |
| Starlette HTTPException | 404 → E4-COMMON-000、405 → E1-HTTP-000，其余 E5-SYS-001 |
| 未捕获 Exception | E5-SYS-000 / 500（记 ERROR + 堆栈） |

## 4. 边界收敛（对外不泄露内部细节）

`converge_error_code(code, message)`：**E3/E5 出网收敛为大类前缀码 + 通用文案**（如 `E5-SYS-002 "服务暂时不可用，请稍后重试"`），E1/E2/E4/S 透传。

- 作用范围：**仅出网响应体**；服务端日志保留完整错误码（内部排障不受影响）；
- 目的：避免把内部实现细节（如「Redis 连接失败」「Nacos 超时」）暴露给调用方。

## 5. 工具函数速查

```python
from web_infra import (

    is_retryable,          # 是否可重试（仅 E3）

```

## 6. 常见问题

**Q：业务层如何拿到完整错误信息？**
A：`BizException` 携带 `error_code` / `http_status` / `message` / `data` 属性；全局处理器按 `error_code.log_level` 记日志。

**Q：校验器（pydantic）报错格式？**
A：FastAPI 参数校验失败统一转 `E1-PARAM-000 / 400`，不会暴露内部异常结构。

**Q：第三方服务调用失败该抛什么？**
A：基础设施类用 E3 系（可重试）；业务不满足用 E4 系；系统兜底用 E5 系。前端判断：`code` 以 `E3`/`E5` 开头通常可提示「请稍后重试」，`E1`/`E4` 为业务错误需按 message 提示。
