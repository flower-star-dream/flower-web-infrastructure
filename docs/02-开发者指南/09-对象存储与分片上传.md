## 1. 是什么

对象存储模块位于 `web_infra.capabilities.storage`，由三部分组成：

1. **统一抽象接口 `ObjectStorageInterface`**（SPI，协议类）：屏蔽 MinIO / 云 OSS / S3 差异，防止技术栈锁定；
2. **两个内置实现**：`LocalObjectStorage`（本地文件系统，单机/测试）与 `MinioObjectStorage`（生产，基于 `minio` SDK）；
3. **分片上传子模块 `storage/upload/`**：`MultipartUploadService` 分片服务 + 任务存储 SPI + 分片存储 SPI。

### 1.1 ObjectStorageInterface 接口

```python
from typing import Callable, Protocol, runtime_checkable

OwnerValidator = Callable[[str, str | None, str | None], None]  # (object_id, owner, current_user)

@runtime_checkable
class ObjectStorageInterface(Protocol):
    async def put(self, bucket: str, key: str, data: bytes, content_type: str | None = None) -> None: ...
    async def get(self, bucket: str, key: str, *, owner: str | None = None,
                  owner_validator: OwnerValidator | None = None) -> bytes | None: ...
    async def delete(self, bucket: str, key: str, *, owner: str | None = None,
                     owner_validator: OwnerValidator | None = None) -> None: ...
    async def exists(self, bucket: str, key: str) -> bool: ...
    async def presign_url(self, bucket: str, key: str, expires: int | None = None) -> str: ...
```

语义要点：

| 方法 | 行为 |
| ---- | ---- |
| `put` | 上传对象；`content_type` 缺省按 `application/octet-stream` 处理 |
| `get` | 下载对象，**对象不存在返回 `None`**（不是抛异常） |
| `delete` | 删除对象（不存在也静默成功） |
| `exists` | 判断对象是否存在 |
| `presign_url` | 生成带过期时间的访问 URL；`expires` 缺省用配置 `presign_expires`（默认 600 秒） |

### 1.2 属主校验（防水平越权，规范 §22.4）

`get` / `delete` 支持两个可插拔参数：

- `owner`：文件属主标识（业务侧决定取值，如 `user_123`）；
- `owner_validator`：属主校验钩子，签名 `(object_id, owner, current_user) -> None`，校验失败**抛权限异常**（如 `PermException`，E2-PERM-*）。

执行流程：两个实现都在下载/删除**前**调用校验钩子，`current_user` 由实现层自动从请求上下文 `RequestContext.get_user_id()` 获取，业务无需传。缺省（不传 `owner_validator`）**不校验**——属主校验是业务可选的加固手段，不是默认强制。

典型防越权场景：文件 key 是 `users/10001/avatar.png`，用户 A（`user_10002`）拿别人的 key 来下载。业务注入一个按 `owner` 比对当前用户的校验器即可拦截：

```python
def check_owner(object_key: str, owner: str | None, current_user: str | None) -> None:
    # owner 在业务里即文件属主用户 ID；current_user 已由实现层从请求上下文注入
    if owner and current_user and owner != current_user:
        raise PermException("无权访问该文件")   # E2-PERM-* 由业务/框架权限异常提供

data = await storage.get(bucket, key, owner="user_10001", owner_validator=check_owner)
```

### 1.3 两种内置实现

| 实现 | 适用场景 | 特性 |
| ---- | -------- | ---- |
| `LocalObjectStorage` | 单体 / 本地开发 / 测试 | 文件落在 `base_dir/{bucket}/{key}`；IO 经 `asyncio.to_thread` 不阻塞事件循环；`presign_url` 返回 HMAC-SHA256 签名 URL |
| `MinioObjectStorage` | 多实例 / 微服务生产 | 私有读写 + SDK 签名 URL（规范 §22.3）；所有 SDK 调用经 `asyncio.to_thread` 异步化；`minio` 包延迟导入（需 `[storage]` extra） |

**本地签名 URL（HMAC）**：本地实现没有真实签名 URL 能力，因此用 `LOCAL_STORAGE_PRESIGN_SECRET`（环境变量注入，默认 `local-presign-secret` 仅供开发）对 `bucket/key:expires` 计算 HMAC-SHA256，URL 形如：

```
./data/{bucket}/{key}?expires=1787051868&signature=<hex>
```

> ⚠️ 本地实现的签名/过期校验需业务按需处理（`get()` 不做强制校验）；**生产环境必须接入真实对象存储**的签名 URL 能力，并遵守私有读写 + 防盗链（规范 §22.3）。

## 2. 何时用

| 场景 | 用哪个 |
| ---- | ------ |
| 单机部署、开发调试、写测试 | `app.storage.type: local`（零外部依赖，开箱即用） |
| 多实例/微服务、文件要跨实例共享、生产环境 | `app.storage.type: minio`（需安装 `[storage]` extra + MinIO 服务） |
| 上传大文件（>50MB）、弱网续传 | `MultipartUploadService` 分片上传（见 §5） |
| 私有文件（头像、证件、账单）不想被随意下载 | `presign_url` 签名 URL + `get/delete` 注入 `owner_validator` |
| 云 OSS / S3 / 其他对象存储 | 实现 `ObjectStorageInterface` 或继承后经 `ObjectStorageRegistry.register` 接入（见 §6） |

## 3. 怎么配

框架装配入口：`create_app()` 按 `app.storage.type` 经 `ObjectStorageRegistry` 按名实例化，结果挂到 `app.state.storage`。未注册的 type 装配期快速失败（`ConfigError`）。

`application.yml`（默认值对齐 `application.default.yml`，仅列差异项即可覆盖）：

```yaml
app:
  storage:
    type: local                # local（默认）/ minio / 自定义注册名
    base_dir: ./data           # 本地实现的数据根目录
    minio:                     # type=minio 时生效
      endpoint: localhost:9000
      access_key: ${APP_STORAGE_MINIO_ACCESS_KEY:}   # 敏感项走环境变量/.env
      secret_key: ${APP_STORAGE_MINIO_SECRET_KEY:}
      secure: false            # HTTPS
      default_bucket: default  # bucket 缺省时回落
      presign_expires: 600     # 签名 URL 有效期（秒，规范 §22.3 建议 ≤ 10min）
```

配置优先级沿用框架约定：环境变量 > 项目根 `application.yml` > `application.default.yml`。

## 4. 代码示例

### 4.1 基础读写（通过 create_app 装配的组件）

```python
from web_infra import create_app

app = create_app()                       # 读取 application.yml，装配 app.state.storage

async def demo():
    storage = app.state.storage          # app.storage.type 决定 local/minio 实现

    await storage.put("my-bucket", "reports/2026-08.csv", b"id,name\n1,alice", content_type="text/csv")
    assert await storage.exists("my-bucket", "reports/2026-08.csv")

    data = await storage.get("my-bucket", "reports/2026-08.csv")   # 不存在返回 None
    url = await storage.presign_url("my-bucket", "reports/2026-08.csv", expires=300)  # 5 分钟有效
    await storage.delete("my-bucket", "reports/2026-08.csv")
```

### 4.2 直接构造（不经 create_app）

```python
from web_infra import LocalObjectStorage, StorageConfig, MinioObjectStorage, MinioStorageConfig

# 本地：默认根目录 ./data
local = LocalObjectStorage(StorageConfig(base_dir="./data"))

# MinIO：bucket 参数缺省回落配置 default_bucket
minio = MinioObjectStorage(MinioStorageConfig(
    endpoint="localhost:9000",
    access_key="AK", secret_key="SK",
    default_bucket="web",
))
```

### 4.3 文件类型校验（FileTypeValidator）

上传前两层校验（规范 §22.2）：

1. **后缀白名单**：默认允许图片（png/jpg/jpeg/gif/webp/bmp/svg/ico）、视频、音频、常见文档与压缩包——**不含可执行/脚本文件**；业务可传自定义白名单扩展；
2. **魔数校验**：按文件头签名识别真实类型（如 PNG 头 `\x89PNG\r\n\x1a\n`、PDF 头 `%PDF`、ZIP 头 `PK\x03\x04`），**防止将 .exe 改名 .png 绕过**。

```python
from web_infra import FileTypeValidator

validator = FileTypeValidator()                       # 默认白名单
validator.validate_extension("头像.png")              # 通过；后缀不在白名单抛 ValueError
validator.validate_magic(b"\x89PNG\r\n\x1a\n...")     # 通过；魔数不匹配抛 ValueError
```

> 注意：魔数表只覆盖部分常见类型（png/jpeg/gif/pdf/zip/rar/7z/gzip/webp/mp4/mp3/wav/ogg），
> txt/md/json 等文本类型无固定魔数，`validate_magic` 对这类内容会误伤——所以分片服务只在**首片**做魔数校验（见 §5），
> 且 `validate_magic` 只做"开头是否命中已知签名"判定，命中任一即通过。

## 5. 分片上传与断点续传

### 5.1 核心参数与状态机

`MultipartUploadService` 关键常量（源码事实）：

| 参数 | 默认值 | 说明 |
| ---- | ------ | ---- |
| `DEFAULT_CHUNK_SIZE` | **5MB**（`5 * 1024 * 1024`） | 大文件自动分片的分片大小 |
| `LARGE_FILE_THRESHOLD` | **50MB**（`50 * 1024 * 1024`） | 超过必须分片（客户端显式不分片时抛 `ValueError`） |
| `max_upload_size` | `None`（不限制） | 上传大小上限（构造传入；`initialize` 超限抛 `ValueError`） |

任务状态机 `UploadStatus`（IntEnum，`get_code()`/`of(code)` 用于入库存 code）：

```
INITIALIZED (0) ──upload_part──> … 全部传完 ──complete──> COMPLETED (1)
      │
      └──cancel / 合并中断──> FAILED (2)
```

### 5.2 全流程（初始化 → 逐片 → 合并校验 → 清理）

```python
import hashlib
from web_infra import (
    MultipartUploadService, InMemoryUploadStore,
    LocalPartStorage, FileTypeValidator,
)

# 组装：任务存储（内存，单实例）+ 分片存储（本地目录）
service = MultipartUploadService(
    store=InMemoryUploadStore(),
    part_storage=LocalPartStorage("./data/upload_tmp"),
    file_type_validator=FileTypeValidator(),   # 缺省内置白名单
    max_upload_size=200 * 1024 * 1024,         # 上传上限 200MB
)

async def upload_big_file(file_name: str, file_size: int, chunks: list[bytes]) -> str:
    # 1. 初始化：校验大小/后缀/分片策略，返回 UploadTask（upload_id 为断点续传定位依据）
    task = await service.initialize(file_name, file_size)   # >50MB 自动按 5MB 分片
    upload_id = task.upload_id

    # 2. 逐片上传（失败重试幂等：同分片重传覆盖；首片自动魔数校验）
    for idx, data in enumerate(chunks, start=1):
        await service.upload_part(upload_id, idx, data)

    # 3. 可选：断点续传场景查询已传分片，只补传缺失部分
    uploaded = await service.list_uploaded_parts(upload_id)   # [1, 2, 3, ...]

    # 4. 合并：分片完整性 + MD5（可选）校验，返回对象 Key（格式 uploads/{upload_id}/{file_name}）
    digest = hashlib.md5(b"".join(chunks)).hexdigest()        # 客户端侧计算的合并文件 MD5
    object_key = await service.complete(upload_id, expected_md5=digest)

    # 5. 失败/取消：清理当前任务分片与记录（仅本任务，不误删其他任务）
    # await service.cancel(upload_id)
    return object_key
```

断点续传客户端侧套路：

```python
uploaded = set(await service.list_uploaded_parts(upload_id))
missing = [n for n in range(1, total_chunks + 1) if n not in uploaded]
for n in missing:
    await service.upload_part(upload_id, n, read_chunk(n))
```

### 5.3 合并校验细节（按源码事实）

`complete(upload_id, expected_md5=None)` 的校验顺序：

1. 任务已 `COMPLETED` → 直接返回既有 `object_key`（幂等）；
2. 分片完整性：`list_uploaded_parts` 必须覆盖 `1..total_chunks`，缺失抛 `ValueError`；
3. **MD5 校验在合并前**基于分片内容计算（`_compute_merged_md5` 按序号读分片累加），不匹配则清理分片并抛 `ValueError`；
4. 合并（本地按序拼接 / MinIO S3 `compose_object` 服务端合并）后校验合并大小 == `file_size`，不一致抛 `ValueError`；
5. 通过后 `store.complete(upload_id, object_key)` 落 `COMPLETED`，并清理分片临时数据。

### 5.4 过期清理

```python
removed = await service.cleanup_stale(ttl_hours=24)   # 清理 24h 前未完成的任务记录与本地分片临时目录
```

`cleanup_stale` 联动两块：任务记录清理（`store.cleanup`）+ 本地分片临时目录清理（`LocalPartStorage.cleanup_expired`，按目录 mtime 判定；MinIO 实现无此能力，自动跳过）。建议配合定时任务周期执行（见 [11-定时任务与异步任务](./11-定时任务与异步任务.md)）。

### 5.5 分片存储两种实现

| 实现 | 存储方式 | 合并方式 |
| ---- | -------- | -------- |
| `LocalPartStorage` | 临时目录 `{base_dir}/{upload_id}/part_{n}` | 本地按序拼接写 `{base_dir}/{upload_id}.merged`，合并后清理 |
| `MinioPartStorage` | 分片作为独立对象 `{upload_id}/part_{n}` | S3 `compose_object` **服务端合并**（不占客户端内存），合并后 stat 取大小，清理分片对象 |

生产大文件用 `MinioPartStorage`（`MinioObjectStorage` 同款配置对象）：

```python
from web_infra import MinioPartStorage, MinioStorageConfig

service = MultipartUploadService(
    store=InMemoryUploadStore(),                       # 多实例需替换为 Redis/MySQL 实现
    part_storage=MinioPartStorage(MinioStorageConfig(endpoint="...", access_key="...", secret_key="...")),
)
```

> **多实例注意**：任务记录存储（`UploadStoreInterface`）默认 `InMemoryUploadStore` 仅单实例有效（@Stateful），
> 多实例部署需扩展 Redis/MySQL 实现；分片存储两个实现均可跨实例访问（本地实现需共享文件系统）。

## 6. 扩展自定义存储后端

`ObjectStorageRegistry` 是类级 SPI 注册表（内置 `local`/`minio`），自定义 OSS/S3 等实现注册后即可被 `create_app` 按 `app.storage.type` 装配：

```python
from web_infra import ObjectStorageRegistry, ObjectStorageInterface
from web_infra.infra.config import Settings

class AliyunOssStorage(ObjectStorageInterface):
    def __init__(self, endpoint: str, access_key: str, secret_key: str): ...
    # …… 实现 put/get/delete/exists/presign_url（SDK 调用放 asyncio.to_thread）

def aliyun_oss_factory(settings: Settings) -> ObjectStorageInterface:
    return AliyunOssStorage(
        endpoint=settings.get("app.storage.aliyun.endpoint"),
        access_key=settings.get("app.storage.aliyun.access_key"),
        secret_key=settings.get("app.storage.aliyun.secret_key"),
    )

ObjectStorageRegistry.register("aliyun", aliyun_oss_factory)   # 模块导入即注册

# application.yml: app.storage.type: aliyun（未注册的 type 装配期抛 ConfigError，快速失败）
```

## 7. 常见坑

1. **`get` 返回 `None` 不代表出错**：对象不存在与读取失败统一返回 `None`（MinIO 实现吞掉 SDK 异常），需要区分"不存在"与"真失败"时用 `exists` 先探测或细化错误码（待确认：MinIO 实现当前对读取异常统一返回 None，生产建议按需求扩展）。
2. **本地签名 URL 不等于安全**：`LOCAL_STORAGE_PRESIGN_SECRET` 默认值是开发占位，生产必须经环境变量注入强随机密钥；且本地实现 `get()` 不校验签名/过期，**生产必须换 MinIO/OSS**。
3. **大文件必须分片**：>50MB 且客户端显式不分片（`chunk_size=0`）时 `initialize` 抛 `ValueError`；不传 `chunk_size` 时小文件单分片、大文件自动按 5MB 分片。
4. **分片号从 1 开始**，越界（`<1` 或 `>total_chunks`）抛 `ValueError`；单分片超过 `chunk_size` 抛 `ValueError`。
5. **首片魔数校验只查首片**：业务若要每片都校验需自行扩展；魔数表未覆盖文本类类型（txt/md/json），对这类文件首片校验可能误伤（魔数表命中任一即通过，若内容头恰好是 PDF 等签名则会放行）。
6. **属主校验缺省关闭**：不传 `owner_validator` 就不校验——需要防水平越权的接口务必注入校验器，并配合认证中间件保证 `current_user` 是真实身份（生产必须启用认证）。
7. **多实例**：`InMemoryUploadStore` 是进程内状态，多实例部署必须换共享存储（Redis/MySQL），否则断点续传跨实例找不到任务。
8. **metrics**：put/get/delete/exists 会写 `StorageMetrics`（低基数标签 `storage`），`/metrics` 可观测。

## 8. 配置项一览

| 配置项 | 默认值 | 说明 |
| ------ | ------ | ---- |
| `app.storage.type` | `local` | local / minio / 自定义注册名（未注册抛 ConfigError） |
| `app.storage.base_dir` | `./data` | 本地实现数据根目录 |
| `app.storage.minio.endpoint` | `localhost:9000` | MinIO 服务地址 |
| `app.storage.minio.access_key` | `${APP_STORAGE_MINIO_ACCESS_KEY:}` | 访问密钥（环境变量注入） |
| `app.storage.minio.secret_key` | `${APP_STORAGE_MINIO_SECRET_KEY:}` | 访问密钥（环境变量注入） |
| `app.storage.minio.secure` | `false` | 是否 HTTPS |
| `app.storage.minio.default_bucket` | `default` | bucket 缺省回落值 |
| `app.storage.minio.presign_expires` | `600` | 签名 URL 有效期（秒，规范 §22.3 建议 ≤ 10min） |
| 环境变量 `LOCAL_STORAGE_PRESIGN_SECRET` | `local-presign-secret` | 本地签名 URL 的 HMAC 密钥（生产必须注入强随机值） |

模型侧对应：`StorageConfig`（base_dir / presign_expires / max_upload_size）、`MinioStorageConfig`（endpoint / access_key / secret_key / secure / default_bucket / presign_expires）。
