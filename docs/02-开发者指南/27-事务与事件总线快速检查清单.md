# 事务与事件总线 使用快速检查清单

> 面向开发者的**使用前/使用中核对表**，用于自查 `@transactional`（声明式事务）、`publish_after_commit`（事务事件）与事件总线（`EventBus` / `@event_listener`）的使用是否正确。配套详读：[24-声明式横切与AOP.md](./24-声明式横切与AOP.md)、[25-事件总线.md](./25-事件总线.md)、[06-数据库.md](./06-数据库.md)。

## 一、`@transactional` 声明式事务

### ✅ 用法对不对

- [ ] 装饰器用对了吗？三种写法等价，任选其一：
  - `@transactional`（裸写，默认 `REQUIRED`）
  - `@transactional(propagation=Propagation.REQUIRED, isolation_level=None)`
  - `@transactional(Propagation.REQUIRES_NEW)`（位置传传播级别）
- [ ] **只装饰 `async` 函数**（`@cacheable`/`@cache_evict` 只支持 async，`@transactional` 对同步函数仅做组件存在性校验、不真正开事务）。
- [ ] 传播级别选对了吗？
  - `REQUIRED`（默认）：复用外层事务；内层异常会标记外层 `rollback-only`。
  - `REQUIRES_NEW`：新建独立事务（挂起外层），互不影响（如审计独立落库）。
  - `NESTED`：外层内开 SAVEPOINT，内层异常仅回滚到保存点。
- [ ] 方法内用 `current_session()` 取会话了吗？**装饰器不会注入 `session` 参数**：
  ```python
  @transactional
  async def create_order(order: dict) -> int:
      s = current_session()     # 必须用 current_session() 取当前事务会话
      ...
  ```

### ✅ 事务边界对不对

- [ ] 方法体所有数据库操作都走 `current_session()`（会用同一事务）。
- [ ] **不要在事务方法内 `await db.session()` 再开一层**（除非刻意 `REQUIRES_NEW` —— 那会挂起当前事务并占用额外连接）。
- [ ] 上层已开事务时，内层 `@transactional`（默认 `REQUIRED`）是**复用**外层，不是新事务；异常会标记外层 `rollback-only`，即使外层 `catch` 住，最外层提交时也会强制回滚。
- [ ] SQLite 场景：`isolation_level` 会被静默忽略（`_open_session` 探测签名），不要依赖 SQLite 的隔离级别。

### ✅ 风险点

- [ ] 连接池压力：`REQUIRES_NEW` 每层占一条连接，**避免事务嵌套过深**，建议限制嵌套深度。
- [ ] 长事务：事务耗时会触发长事务监控（默认 >5s 告警 + `db_long_transaction_total` 指标），临界区避免远程调用/慢查询。
- [ ] 取不到 db 组件：若未 `create_app()` / 未 `bind_components({'db': ...})`，运行时会抛 `RuntimeError`。

## 二、`@cacheable` / `@cache_evict` 声明式缓存（与事务配合）

- [ ] **仅支持 async 函数**（装饰同步函数直接抛 `RuntimeError`）。
- [ ] 缓存装饰器是**普通装饰器**，不参与 AOP order——靠书写顺序决定与事务切面的嵌套，**`@transactional` 必须写在最上方**。
  ```python
  @transactional          # 最外层（先进入事务）
  @cacheable("order:{0}")
  async def get_order(oid): ...
  ```
- [ ] 缓存变更**不绑定事务提交时机**：读/删缓存在方法执行时生效。若要求"事务提交后再失效缓存"，需事务外调用 `cache.delete(key)`。

## 三、事件总线 `EventBus` / `@event_listener`

### ✅ 装配

- [ ] **`app.event.enabled: true` 了吗？**默认 `false`，未开启时 `app.state.event` 不存在（取用会 `AttributeError`）。
  ```yaml
  app:
    event:
      enabled: true        # 默认 false
      fail_fast: false     # true=监听器异常阻断其余；false=记日志继续
  ```
- [ ] 或测试里直接构造 `EventBus(fail_fast=False)`。

### ✅ 定义事件

- [ ] 事件继承 `ApplicationEvent`，需有稳定 `event_name`：
  ```python
  class OrderCreatedEvent(ApplicationEvent):
      event_name = "order.created"     # 显式声明；缺省由类名推导（OrderCreatedEvent -> order_created_event）
  ```
- [ ] `trace_id` 会自动绑定请求上下文（`RequestContext.get_trace_id()`），无需手动传。

### ✅ 定义监听器

- [ ] 用 `@event_listener`，`event` 传**事件名**（`"order.created"`）或**事件类型**（`OrderCreatedEvent`，自动推导 event_name + 父类匹配）。
- [ ] `async_mode` 与 handler 类型匹配了吗？
  - handler 是 `async` 函数 → `async_mode=True`
  - handler 是同步函数 → `async_mode=False`（默认；若返回 awaitable 会内部 await）
- [ ] `order` 决定同事件多监听器执行顺序（升序）。

### ✅ 发布

- [ ] 普通事件：`await bus.publish(event)` —— **立即**分发。
- [ ] 事务事件：`await bus.publish_after_commit(event)` —— **必须在事务内调用**（`@transactional` / `db.session()` 中），提交成功后才触发，**回滚不触发**。
  ```python
  @transactional
  async def create_order(order: dict) -> int:
      order_id = ...
      await app.state.event.publish_after_commit(OrderCreatedEvent(payload={"order_id": order_id}))
      return order_id
  ```
- [ ] 想在事务提交后触发监听器，监听器应保持 `async_mode=False`（同步）——**SQLite 场景尤其重要**：异步监听器的 after_commit 回调会被 `trigger_after_commit_sync` 跳过并告警。

### ✅ 数据源 / 边界

- [ ] `publish_after_commit` 在 MySQL / SQLite / 基类 `_finalize_commit` 均已接入（提交成功后触发）。
- [ ] 进程内事件**不会跨服务**：需要跨服务 / 持久化 / 广播到多实例 → 改用 MQ（+Outbox）。

## 四、常见踩坑速查

| 症状 | 原因 | 处理 |
| ---- | ---- | ---- |
| `app.state.event` 不存在 | `app.event.enabled` 未开启（默认 false） | 配置 `enabled: true` 或直接构造 `EventBus` |
| `publish_after_commit` 事件没触发 | 在事务外调用，或无提交入口；SQLite 下监听器为 async 被跳过 | 在 `@transactional` 内调用；SQLite 用同步监听器 |
| 事务没回滚 | 内层 `REQUIRED` 复用外层，异常被外层 `catch` 未重新抛出 | 注意 `rollback-only` 语义，或改用 `REQUIRES_NEW` |
| 缓存装饰了同步函数 | `@cacheable`/`@cache_evict` 仅支持 async | 改用 async 函数 |
| 缓存与事务时序错位 | 缓存读写在方法内完成，不随提交时机 | 需要"提交后失效"则事务外 `cache.delete` |
| `@transactional` 方法内取不到 session | 未用 `current_session()` | 方法体内用 `current_session()` 取会话 |
| 事件总线误跨服务 | 进程内事件不会广播到其他实例 | 跨服务改走 MQ（Outbox 保证可靠投递） |
