## 1. 是什么

支付模块（`web_infra.capabilities.payment`）按《Web 系统通用架构规范 · 支付扩展》实现渠道接入与资金兜底，核心是**一套 SPI + 一个骨架 + 一个生产渠道**：

- **SPI**：`PaymentGateway`（渠道统一抽象）、`PaymentCallbackVerifier`（回调验签解密）、`PaymentCallbackHandler`（业务回调处理器）——业务代码只依赖接口，渠道差异内部屏蔽；
- **骨架**：`PaymentChannelTemplate`（Template Method）固化资金流程——幂等检查 → 渠道调用 → 三态收敛 → 流水落库，渠道实现方只填充 `_do_*` 与 `_parse_callback`；
- **生产渠道**：微信 APIv3（`provider/wechat`）——四场景下单、查单/关单/退款、回调验签解密、平台证书自动下载。

> **可选能力**：支付不随 `web_infra` 顶层导出，需显式 `from web_infra.capabilities.payment import ...` 引入；`app.capabilities.enabled: [pay]` 声明时自动带出前置能力链 鉴权→认证→用户（详见 [使用说明.md §4.2](../使用说明.md#42-能力依赖与装配)）。

## 2. 快速接入（内存渠道演示）

不配置任何微信参数即可跑通下单/查单/退款/回调入账全链路：

```python
from decimal import Decimal
from web_infra.capabilities.payment import (
    InMemoryPaymentFlowStore, InMemoryPaymentOrderStore,
    InMemoryPaymentGateway, PaymentGatewayRegistry,
    PaymentPrepayRequest, PaymentScene,
)

# 注入存储（生产替换为 MySQL 本地事务表实现，见 §8）
gateway = InMemoryPaymentGateway(
    flow_store=InMemoryPaymentFlowStore(),
    order_store=InMemoryPaymentOrderStore(),
)
PaymentGatewayRegistry.register("wechat", gateway)   # 生产替换为 WeChatPayProvider

resp = await gateway.prepay(PaymentPrepayRequest(
    scene=PaymentScene.NATIVE,
    out_trade_no="O202608180001",
    description="测试商品",
    total_amount=Decimal("10.00"),
))
# resp.code_url  → 二维码内容（NATIVE 场景）
```

## 3. SPI 三件套

### 3.1 PaymentGateway：渠道统一抽象

```python
class PaymentGateway(Protocol):   # 无默认实现，业务只依赖本接口
    async def prepay(self, request: PaymentPrepayRequest) -> PaymentPrepayResponse: ...
    async def query_order(self, out_trade_no: str) -> PaymentOrder | None: ...
    async def close_order(self, out_trade_no: str) -> None: ...
    async def refund(self, request: PaymentRefundRequest) -> PaymentRefundResponse: ...
    async def query_refund(self, out_refund_no: str) -> PaymentRefundResponse | None: ...
```

- 请求/响应模型：`PaymentPrepayRequest`（scene/out_trade_no/description/total_amount/notify_url/openid/client_ip/time_expire/attach）、`PaymentPrepayResponse`（scene/prepay_id/pay_params/code_url/h5_url）、`PaymentRefundRequest`（out_trade_no/out_refund_no/refund_amount/total_amount/reason/refund_notify_url）、`PaymentRefundResponse`（out_refund_no/refund_id/status/refund_amount）、`PaymentOrder`（out_trade_no/transaction_id/status/total_amount/payer_total/paid_at）；
- 金额统一 `Decimal` 元；`out_trade_no`（商户订单号）与 `out_refund_no`（商户退款单号）是**渠道侧幂等键**；
- 查单/查退款「不存在」返回 `None`（对齐 FeignClient 404→None 语义）。

### 3.2 PaymentCallbackVerifier：回调验签解密

```python
class PaymentCallbackVerifier(Protocol):
    async def parse(self, headers, body) -> PaymentCallback | None: ...
```

渠道侧实现把回调 headers+body 验签解密为统一回调结构 `PaymentCallback`（event_type/out_trade_no/transaction_id/amount/refund_status/mch_refund_no/attach/raw）。**验签/解密/解析失败统一返回 `None`**，回调入口映射 401（渠道自动重试）。内置实现：`WeChatCallbackVerifier`（微信）与 `InMemoryPaymentCallbackVerifier`（测试，构造注入回调直接返回）。

### 3.3 PaymentCallbackHandler：业务处理器

```python
class PaymentCallbackHandler(ABC):
    @abstractmethod
    async def handle(self, callback: PaymentCallback) -> None: ...
```

业务实现支付成功/退款结果的处理（发货、积分、记账等），**回调幂等由业务保证**（回调事件带 `event_type + out_trade_no`，可复用框架幂等组件；订单状态幂等可借助 `PaymentStateMachine.is_idempotent_repeat` 判定）。

### 3.4 PaymentGatewayRegistry：渠道注册表与能力位校验

按渠道名注册/查询 `PaymentGateway`，未注册渠道 `get` 抛 `E4-PAY-001`：

```python
from web_infra.capabilities.payment import PaymentGatewayRegistry

PaymentGatewayRegistry.register("wechat", provider)   # 同名覆盖
PaymentGatewayRegistry.get("wechat")                  # 未注册抛 E4-PAY-001
PaymentGatewayRegistry.registered_names()             # ["wechat"]
```

**能力位启动校验**（注册时执行）：渠道实现声明 `capabilities` 时，缺必选能力 `query_order/close_order/parse_callback` 拒绝注册（`ValueError`）；声明 `refund` 未配套 `query_refund` 告警降级；未声明 `capabilities` 的渠道告警放行（兼容过渡）。

### 3.5 PaymentCallbackDispatcher：回调分发器

```python
from web_infra.capabilities.payment import PaymentCallbackDispatcher

dispatcher = PaymentCallbackDispatcher()
dispatcher.register(OrderCallbackHandler())          # 注册业务处理器（可多个）

await dispatcher.dispatch(callback)                  # 顺序分发全部处理器
```

未注册任何处理器时静默兜底（日志告警），保证回调入口不抛错。

## 4. 渠道骨架 PaymentChannelTemplate

骨架是渠道接入的**推荐起点**（内存渠道与微信渠道都继承它）：四个 final 入口固化资金流程，渠道实现方只填充 `_do_*`（必选抽象漏实现无法实例化）与 `_parse_callback`。

### 4.1 final 入口固化资金流程

| final 入口 | 固化流程 |
| ---- | ---- |
| `prepay` | 下单幂等检查（已 SUCCESS/USERPAYING/EXCEPTION 拒绝，`E4-PAY-003`）→ 渠道下单 → 成功后写本地支付订单（注入 order_store 时） |
| `refund` | 退款能力位校验（`E4-PAY-008`）→ 退款幂等与超额校验（同 out_refund_no 拒绝重复；已退+本次 ≤ 实付，超限拒绝）→ 渠道退款 → 退款申请流水（PENDING 待入账） |
| `close_order` | 本地幂等（已 CLOSED 直接返回；已 SUCCESS 抛冲突）→ **查单确认未支付**（查单失败禁止强行关单，防已支付被关闭）→ 渠道关单 → 关单流水 |
| `handle_callback` | 渠道层 `_parse_callback` 验签解密（失败抛 `E3-PAY-001` 映射 401）→ 通用层校验（金额 `E4-PAY-002`/attach/状态机 `E4-PAY-003`）→ 本地事务入账（订单状态 + 支付流水） |

```python
from decimal import Decimal
from typing import Mapping
from web_infra.capabilities.payment import (
    PaymentChannelTemplate, PaymentCallback, PaymentPrepayRequest,
    PaymentPrepayResponse, PaymentOrder, PaymentRefundRequest, PaymentRefundResponse,
)

class MyChannel(PaymentChannelTemplate):
    # 能力位声明（§3.4）：必选 query_order/close_order/parse_callback；可选 refund/query_refund
    capabilities = frozenset({"query_order", "close_order", "refund", "query_refund", "parse_callback"})

    # ---- 必选抽象：漏实现无法实例化 ----
    async def _do_prepay(self, request: PaymentPrepayRequest) -> PaymentPrepayResponse: ...
    async def _do_query_order(self, out_trade_no: str) -> PaymentOrder | None: ...
    async def _do_close_order(self, out_trade_no: str) -> None: ...
    async def _parse_callback(self, headers: Mapping[str, str], body: str) -> PaymentCallback | None: ...

    # ---- 可选能力：声明 refund 的渠道须覆写（默认抛 E4-PAY-008）----
    async def _do_refund(self, request: PaymentRefundRequest) -> PaymentRefundResponse: ...
    async def _do_query_refund(self, out_refund_no: str) -> PaymentRefundResponse | None: ...
```

回调入口的另一种形态：渠道无回调签名体系时（如内存渠道），业务回调入口先 `await channel.validate_callback(callback)` 完成通用校验（金额/attach/状态机），再交 `PaymentCallbackDispatcher` 分发——`validate_callback` 是 `handle_callback` 的校验半程复用入口。

### 4.2 三态收敛与流水落库

渠道调用结果严格区分三态（规范 §7.4）：`SUCCESS` / `FAILED` / `UNKNOWN`，未知态只允许**查证与对账兜底**，禁止凭猜测动账。骨架用 `PaymentFlowContext` 统一收敛写流水：

```python
from web_infra.capabilities.payment.payment_channel_template import PaymentFlowContext

# 骨架内部：prepay 结果未知（网络/超时）抛渠道错误，由业务先查单确认再决策（禁止盲目重试）
await self._persist_flow(PaymentFlowContext(
    out_trade_no=order_no, amount=amount,
    event_type=PaymentFlowEvent.PAY.value, status="SUCCESS",
    channel=self.__class__.__name__, transaction_id=tx_id, raw={...},
))
```

- `status` 三态 → 账务状态：SUCCESS→`BOOKED`（已入账），FAILED/UNKNOWN→`PENDING`（待入账）；
- 关单流水 `status_override=PaymentFlowStatus.CLOSED`；退款申请流水 `status_override=PaymentFlowStatus.PENDING`；
- 唯一索引 `(out_trade_no + event_type)` 兜底幂等（重复 append 返回首次记录）。

### 4.3 能力位声明与依赖注入

```python
# 未声明 capabilities 时 _supports 放行并告警（建议声明，规范 §3.4）
channel = MyChannel(
    flow_store=my_flow_store,      # PaymentFlowStoreInterface：不注入跳过流水落库（降级纯渠道调用）
    order_store=my_order_store,    # PaymentOrderStoreInterface：不注入跳过本地幂等/金额校验（降级）
    audit_store=my_audit_store,    # PaymentAuditStoreInterface：不注入跳过审计埋点
)
```

**未注入时降级为纯渠道调用**（兼容 SPI 直用场景）；注入后兜底全量生效（下单幂等/关单查单确认/回调校验/流水落库/审计埋点）。生产接入建议三者都注入（审计可后续补）。

## 5. 微信 APIv3 渠道

### 5.1 配置项

`app.payment` 配置段（默认 `type: memory`），微信参数全在 `app.payment.wechat`（敏感项经 `${APP_PAYMENT_*}` 环境变量注入，见 [application.default.yml](../../src/web_infra/infra/config/application.default.yml)）：

```yaml
app:
  payment:
    type: wechat            # memory | wechat
    wechat:
      appid: ${APP_PAYMENT_WECHAT_APPID:}              # 微信小程序/公众号/App 应用 ID
      mchid: ${APP_PAYMENT_WECHAT_MCHID:}              # 微信支付商户号
      mch_serial_no: ${APP_PAYMENT_WECHAT_MCH_SERIAL_NO:}  # 商户 API 证书序列号（请求签名用）
      api_v3_key: ${APP_PAYMENT_WECHAT_API_V3_KEY:}    # APIv3 密钥（回调报文 AES-256-GCM 解密）
      private_key: ${APP_PAYMENT_WECHAT_PRIVATE_KEY:}  # 商户 API 私钥 PEM 内容（与 private_key_path 二选一）
      private_key_path: ${APP_PAYMENT_WECHAT_PRIVATE_KEY_PATH:}
      notify_url: ${APP_PAYMENT_WECHAT_NOTIFY_URL:}    # 支付成功回调地址
      refund_notify_url: ${APP_PAYMENT_WECHAT_REFUND_NOTIFY_URL:}  # 退款结果回调地址
      verify_mode: platform_cert    # 回调验签凭据模式：platform_cert | public_key
      platform_cert_dir: ./cert     # 平台证书 PEM 目录（文件名=<证书序列号>.pem）
      cert_auto_download: false     # 平台证书自动下载（验签遇未知序列号自动调 /v3/certificates 获取并缓存）
      public_key_id: ${APP_PAYMENT_WECHAT_PUBLIC_KEY_ID:}   # 微信支付公钥 ID（public_key 模式）
      public_key: ${APP_PAYMENT_WECHAT_PUBLIC_KEY:}         # 微信支付公钥 PEM 内容（public_key 模式）
      connect_timeout: 5            # 连接超时（秒）
      read_timeout: 30              # 读超时（秒）
```

`WechatPayConfig` 模型另有重试默认值（yml 未显式列出，可覆盖）：`retries=2`（网络/5xx/429 重试，0 关闭）、`retry_delay_base=0.5`、`retry_delay_max=4.0`。

### 5.2 签名与验签 WeChatSigner

`provider/wechat/wechat_signer.py`：SHA256withRSA 工具类（密钥 PEM 按内容缓存，轮换自动换缓存）。

```python
from web_infra.capabilities.payment.provider.wechat.wechat_signer import WeChatSigner

# 请求签名：签名串 method\nurl\nts\nnonce\nbody\n，返回 Authorization 头
sign = WeChatSigner.request_signature("POST", "/v3/pay/transactions/native", body, private_key_pem)
header = WeChatSigner.authorization_header(mchid, serial_no, sign["timestamp"], sign["nonce"], sign["signature"])
# WECHATPAY2-SHA256-RSA2048 mchid="...",nonce_str="...",signature="...",timestamp="...",serial_no="..."

# 应答/回调验签：签名串 timestamp\nnonce\nbody\n
WeChatSigner.verify_response(timestamp, nonce, body, signature, platform_public_key_pem)  # True/False

# 调起支付二次签名（JSAPI：appId\nts\nnonce\npackage\nRSA；App：appId\nts\nnonce\nprepay_id=xxx）
WeChatSigner.jsapi_pay_sign(appid, ts, nonce, prepay_id, private_key_pem)
WeChatSigner.app_pay_sign(appid, ts, nonce, prepay_id, private_key_pem)
```

### 5.3 HTTP 客户端 WeChatPayClient

`provider/wechat/wechat_pay_client.py`：底层 httpx，自动附加签名头、应答验签、错误映射与失败重试兜底。

- **自动签名**：请求体 JSON 序列化 + 签名头（商户私钥）；**应答验签**：缺签名头跳过，验签失败抛 `E3-PAY-000`；
- **重试边界**：可重试故障 = 网络异常（httpx.HTTPError）/ 微信 5xx / 429，指数退避 + 抖动（`min(base * 2^attempt * jitter, max)`）默认重试 2 次；4xx 业务错误与验签失败**不重试**；重试耗尽抛 `E3-PAY-000`（data 带 `http_status` 与 `retryable` 标记）；
- **下单禁止盲目重试**：下单是资金操作，调用方传 `retryable=False`（微信 provider 内部已传），失败由业务先查单确认再决策（规范 §7.2 红线）；
- **404 → None**（`not_found_ok=True`）、**204 → {}**；
- **平台证书自动下载**：`cert_auto_download` 开启且应答验签遇未知序列号时自动调用 `/v3/certificates` 获取并缓存（`asyncio.Lock` 防并发重复下载）。

### 5.4 渠道实现 WeChatPayProvider

`provider/wechat/wechat_pay_provider.py`：`PaymentChannelTemplate + PaymentGateway` 实现，四场景下单：

```python
from decimal import Decimal
from web_infra.capabilities.payment import (
    WechatPayConfig, PaymentPrepayRequest, PaymentScene, PaymentGatewayRegistry,
)
from web_infra.capabilities.payment.provider.wechat.wechat_pay_provider import WeChatPayProvider
from web_infra.infra.config.settings import Settings

config = WechatPayConfig.model_validate(Settings.instance().get("app.payment.wechat") or {})
provider = WeChatPayProvider(
    config,
    flow_store=my_flow_store,     # 骨架依赖注入（§4.3）
    order_store=my_order_store,
)
PaymentGatewayRegistry.register("wechat", provider)

resp = await provider.prepay(PaymentPrepayRequest(
    scene=PaymentScene.JSAPI,          # JSAPI（小程序/公众号，openid 必填）/ NATIVE / H5（client_ip 必填）/ APP
    out_trade_no="O202608180001",
    description="示例订单",
    total_amount=Decimal("10.00"),     # 元，内部转分
    openid="oABC123...",
))
# JSAPI/APP：resp.prepay_id + resp.pay_params（已做二次签名，可直接前端调起）
# NATIVE：resp.code_url；H5：resp.h5_url
```

- 场景校验：不支持的场景抛 `E4-PAY-004`；JSAPI 缺 openid、H5 缺 client_ip 抛 `E4-PAY-004`；
- 查单 `_do_query_order`（微信 404 转 None）、关单 `_do_close_order`（骨架已前置查单确认）、退款 `_do_refund`、查退款 `_do_query_refund`；
- 回调 `_parse_callback` 复用 `WeChatCallbackVerifier`（DCL 懒加载，并发首次回调只构造一次）；
- `time_expire` 格式化为微信 ISO8601；`_to_fen` / `_to_yuan` 完成金额换算。

### 5.5 回调验签解密 WeChatCallbackVerifier

`provider/wechat/wechat_callback_verifier.py` 实现 `PaymentCallbackVerifier`，任一环节失败统一返回 `None`（回调入口映射 401，微信自动重试）：

- **签名头完整性**：`wechatpay-timestamp/nonce/signature/serial` 缺一拒绝；
- **时间戳容差 300s**（`PaymentConstant.CALLBACK_SIGN_EXPIRE_SECONDS`）防重放；
- **验签**：`platform_cert` 模式按 `serial` 从 `platform_cert_dir` 加载平台证书公钥（未知序列号且开启自动下载时先下载）；`public_key` 模式用静态公钥；
- **解密**：AES-256-GCM 解密 `resource`（APIv3 密钥），明文 JSON 映射为 `PaymentCallback`（金额分→元）。

### 5.6 平台证书存储 WeChatCertificateStore

`provider/wechat/wechat_certificate_store.py`：下载接口返回的加密证书（AES-256-GCM）解密 → X509 提取公钥转 SPKI PEM → 原子落盘 `<serial_no>.pem`（先写临时文件再 `os.replace`，防并发读到半截文件）→ 下载成功后清理失效旧证书。`cert_auto_download=false` 时需要手动放置证书文件（文件名 = 证书序列号）。

### 5.7 金额 Decimal 元 ↔ 分换算

微信支付金额单位为分，框架统一 Decimal 元，边界自动换算（`PaymentConstant.BIZ_PAY_AMOUNT_SCALE = 100`）：

```python
from decimal import Decimal
from web_infra.capabilities.payment import PaymentConstant

fen = int(Decimal("10.00") * Decimal(PaymentConstant.BIZ_PAY_AMOUNT_SCALE))   # 1000
yuan = Decimal(1000) / Decimal(PaymentConstant.BIZ_PAY_AMOUNT_SCALE)           # Decimal('10.00')
```

## 6. 支付域模型

### 6.1 枚举：场景/状态/事件

```python
from web_infra.capabilities.payment import PaymentScene, PaymentStatus, PaymentEvent, RefundStatus

PaymentScene.JSAPI / NATIVE / H5 / APP          # 支付场景（对齐微信 APIv3）

PaymentStatus.SUCCESS / REFUND / NOTPAY / CLOSED / REVOKED / PAYERROR / USERPAYING / EXCEPTION
# EXCEPTION = 异常挂账态（非终态）：结果未知超窗口后强制挂账，由对账收敛

PaymentEvent.PAY_SUCCESS / PAY_FAILED / PAY_TIMEOUT / CLOSE / CONFIRM_FAILED / CONFIRM_EXCEED / \
    RECONCILE_SUCCESS / RECONCILE_FAILED / REFUND_SUCCESS / REFUND_PARTIAL

RefundStatus.SUCCESS / CLOSED / PROCESSING / ABNORMAL
```

### 6.2 PaymentStateMachine 合法流转表

业务与骨架共用同一权威定义（禁止各模块自定义）。`target(current, event)` 求目标状态（幂等重复返回原状态，非法抛 `E4-PAY-003`）：

| 当前状态 | 事件 → 目标状态 |
| ---- | ---- |
| NOTPAY | PAY_SUCCESS→SUCCESS；PAY_FAILED→PAYERROR；PAY_TIMEOUT→CLOSED；CLOSE→CLOSED |
| USERPAYING | PAY_SUCCESS→SUCCESS；PAY_FAILED→PAYERROR；CONFIRM_FAILED→CLOSED；CONFIRM_EXCEED→EXCEPTION |
| EXCEPTION | RECONCILE_SUCCESS→SUCCESS；RECONCILE_FAILED→CLOSED |
| SUCCESS | REFUND_SUCCESS→REFUND；REFUND_PARTIAL→SUCCESS |

- **幂等重复对**（重复回调返回首次结果，非冲突）：`(SUCCESS, PAY_SUCCESS)`、`(SUCCESS, REFUND_PARTIAL)`、`(REFUND, REFUND_SUCCESS)`、`(CLOSED, CLOSE)`；
- **终态不可回退**：SUCCESS / CLOSED / REVOKED / REFUND；EXCEPTION 非终态，仅由对账收敛（RECONCILE_*）。

```python
from web_infra.capabilities.payment import PaymentStateMachine, PaymentStatus, PaymentEvent

new_status = PaymentStateMachine.target(PaymentStatus.NOTPAY, PaymentEvent.PAY_SUCCESS)  # SUCCESS
PaymentStateMachine.is_idempotent_repeat(PaymentStatus.SUCCESS, PaymentEvent.PAY_SUCCESS)  # True
PaymentStateMachine.is_terminal(PaymentStatus.SUCCESS)   # True
```

### 6.3 支付流水 PaymentFlowRecord

本地资金变更明细（对账/审计的本地权威依据），`PaymentFlowStatus`（本地账务状态）与订单状态分离：

```python
from web_infra.capabilities.payment import PaymentFlowStatus, PaymentFlowEvent

PaymentFlowStatus.BOOKED / PENDING / REVERSED / CLOSED     # 已入账/待入账/已冲正/已关闭
PaymentFlowEvent.PAY / REFUND / CLOSE / REVERSAL           # 幂等域：唯一索引 = 订单号 + 事件类型

PaymentFlowRecord(
    out_trade_no="O202608180001", event_type=PaymentFlowEvent.PAY,
    amount=Decimal("10.00"), status=PaymentFlowStatus.BOOKED,
    channel="wechat", transaction_id="WX-...", raw={...},
)
```

存储经 `PaymentFlowStoreInterface` SPI（append 幂等 / find_by_order_and_event / find_by_flow_id / find_reversal / sum_refunded），默认 `InMemoryPaymentFlowStore`，生产用 MySQL 本地事务表（append 支持传 session 与业务同事务提交）。

## 7. 辅助能力

### 7.1 超时自动关单 close_expired_orders

`payment_close_task.py`：扫描超时未支付订单 → 骨架 `close_order`（内部先查单确认未支付）→ 本地状态置 CLOSED + 关单流水。**查单失败/渠道异常跳过该订单并记 WARN**（禁止在渠道状态不明时强行关单，防已支付被关闭），跳过单下轮重试。经框架 `TaskScheduler` 注册定时任务：

```python
from datetime import datetime, timedelta, timezone
from web_infra.capabilities.payment.payment_close_task import close_expired_orders

closed = await close_expired_orders(
    order_store=my_order_store,
    channel=provider,                    # 渠道骨架实现
    expire_before=datetime.now(timezone.utc).replace(tzinfo=None) - timedelta(minutes=15),
    limit=100,
)
```

### 7.2 冲正 reversal_flow

`payment_reversal.py`：对「不应发生或状态未知」的本地记账做反向调整——**新增反向冲正流水（不可删除原流水）+ 标记原流水已冲正**：

```python
from web_infra.capabilities.payment import reversal_flow

reversal = await reversal_flow(
    flow_store=my_flow_store,
    original_flow=original_flow,         # 须已入账 BOOKED 的本地流水
    channel="wechat", reason="对账差异:AMOUNT_MISMATCH",
    event_callback=notify_downstream,    # 下游业务补偿投递（失败不阻塞冲正本身，仅告警）
)
```

- **红线**：禁止冲正冲正流水（`is_reversal=True` 抛 `ValueError`）；原流水已冲正抛 `ValueError`（幂等）；
- 幂等：以「原流水号 + REVERSAL」唯一索引兜底，重复执行返回首次冲正流水；
- 触发条件约束：只适用支付后阶段，必须基于渠道权威状态（主动查单/对账结论），禁止凭猜测冲正。

### 7.3 支付审计 PaymentAuditStore

`payment_audit_store.py`：全链路只增不改，失败同样留痕，原始报文仅落审计（不落业务日志）。骨架 final 入口注入 `audit_store` 后自动埋点（prepay/callback/refund/close_order），审计失败仅记日志不阻断业务主链路。`PaymentAuditStoreInterface.append(record, session)` + `InMemoryPaymentAuditStore` 默认实现，生产用 MySQL 审计表（保留 ≥ 90 天）。

### 7.4 对账 ReconciliationService

`reconciliation/` 子包：T+1 对账——渠道账单（`BillRecord` 统一明细）vs 本地流水按「订单号 + 事件类型 + 金额」对齐 → 差异分类 → 自动处理 → 审计落库。

**五类差异**（`DifferenceType`）：

| 差异类型 | 含义 | 风险等级 | 自动处理 |
| ---- | ---- | ---- | ---- |
| LOCAL_ONLY | 本地有、渠道无（短款） | MEDIUM | 查单确认未支付后冲正 |
| CHANNEL_ONLY | 渠道有、本地无（长款） | HIGH | 查单确认已支付后补记 |
| AMOUNT_MISMATCH | 金额不一致 | CRITICAL | **禁止自动动账**：冻结挂账 + P0 告警 + 人工 |
| STATUS_MISMATCH | 状态不一致 | HIGH | **禁止自动动账**：P0 告警 + 人工核查 |
| REFUND_MISMATCH | 退款差异 | HIGH | 查退款确认后补记（资金流出优先） |

**红线（§6.4）**：未确认不处理资金——任何自动补记/冲正必须基于主动查单的渠道权威状态，禁止凭账单单方判断直接动账；金额/状态不一致强制人工。

```python
from web_infra.capabilities.payment import (
    ReconciliationService, InMemoryReconciliationAuditStore,
    run_reconciliation, BillFileManager,
)

service = ReconciliationService(
    flow_store=my_flow_store,
    audit_store=InMemoryReconciliationAuditStore(),
    query_order=provider.query_order,      # 主动查单回调（渠道权威状态）；None 时不自动处理
    query_refund=provider.query_refund,
    auto_handle=True,
)

result = await run_reconciliation(
    service,
    channel="wechat",
    biz_date="2026-08-17",                 # T-1 账期
    bill_provider=load_bill_records,       # 账单下载 + 解析为 BillRecord 列表
    flow_provider=load_local_flows,        # 本地流水按账期查询
)
# result.matched_count / difference_count / auto_booked / auto_reversed / manual_count / audit_id
```

- 防重：任务唯一标识 `pay:job:reconcile:{channel}:{biz_date}`，同渠道 + 账期已审计 → 跳过（重试幂等）；
- 账单文件：`BillFileManager`（完整性校验失败丢弃重下、按账期组织 `base/{channel}/{biz_date}/`、保留期 ≥ 90 天清理）；
- 对账审计：`ReconciliationAuditStoreInterface` 只增不改，差异清单 + 处理动作留痕（§6.6）；
- 权限点：对账/差异处理 `AUTH_PERM_PAY_RECONCILE`。

### 7.5 风控 PaymentRiskGuard

`risk/` 子包：下单前逐项校验——单笔限额 / 日累计 / 月累计（超限 `E4-PAY-005`）、下单频次（超限 `E4-PAY-006`）、可疑拆分（大额拆分多笔接近单笔限额，命中 `E4-PAY-007`）：

```python
from decimal import Decimal
from web_infra.capabilities.payment import (
    PaymentRiskGuard, LimitRule, PaymentLimitConfig, InMemoryLimitCounterStore,
)

guard = PaymentRiskGuard(counter_store=InMemoryLimitCounterStore())   # 生产用 Redis（跨实例原子）

rule = LimitRule(
    per_transaction=Decimal("5000"),      # 单笔限额（元，None 不限制）
    daily_limit=Decimal("20000"),         # 日累计限额
    monthly_limit=Decimal("100000"),      # 月累计限额
    frequency_window_seconds=60,          # 下单频次窗口（0 = 不限）
    max_attempts=5,                       # 窗口内最大下单次数
    suspicious_split_count=3,             # 可疑拆分：窗口内 ≥90% 单笔限额的笔数阈值
)
PaymentLimitConfig({"wechat": rule})      # 渠道名 → 规则容器，配置中心推送即时生效

await guard.check_prepay(user_id=1001, channel="wechat", amount=Decimal("100.00"), rule=rule)
```

限额累计 Decimal 精确 + 原子更新（禁止浮点/非原子，防并发超限）；拦截必须留痕（风控命中落审计可申诉，由业务接入）。

## 8. 接入流程：从配置到业务回调处理器

1. **配置**：`application.yml` 声明 `app.payment.type: wechat` 与微信参数（敏感项写 `.env`，见 §5.1）；如需能力链校验可声明 `app.capabilities.enabled: [pay]`；
2. **实现存储 SPI**（生产必需，框架提供内存默认实现仅供单机/测试）：
   - `PaymentOrderStoreInterface`：本地支付订单存取（业务订单表适配）；
   - `PaymentFlowStoreInterface`：支付流水本地事务表（`(out_trade_no + event_type)` 唯一索引）；
   - `PaymentAuditStoreInterface`（可选）：审计表（只增不改）；
3. **构造并注册渠道**：

```python
from web_infra.capabilities.payment import (
    WechatPayConfig, PaymentGatewayRegistry, PaymentCallbackDispatcher,
)
from web_infra.capabilities.payment.provider.wechat.wechat_pay_provider import WeChatPayProvider
from web_infra.infra.config.settings import Settings

config = WechatPayConfig.model_validate(Settings.instance().get("app.payment.wechat") or {})
provider = WeChatPayProvider(config, flow_store=my_flow_store, order_store=my_order_store,
                             audit_store=my_audit_store)
PaymentGatewayRegistry.register("wechat", provider)
```

4. **业务回调处理器**：实现 `PaymentCallbackHandler.handle(callback)`（幂等由业务保证），注册到 `PaymentCallbackDispatcher`；
5. **回调 HTTP 入口**（FastAPI 路由，返回 401 让渠道重试）：

```python
from fastapi import Request, Response
from web_infra.capabilities.payment import PaymentCallbackDispatcher

async def wechat_notify(request: Request) -> Response:
    body = (await request.body()).decode("utf-8")
    headers = {k.lower(): v for k, v in request.headers.items()}
    callback = await provider._parse_callback(headers, body)   # 渠道层验签解密（失败返回 None）
    if callback is None:
        return Response(status_code=401)                        # 微信自动重试
    await provider.validate_callback(callback)                  # 通用校验（金额/attach/状态机）
    await dispatcher.dispatch(callback)                         # 业务分发
    return Response(status_code=200)
```

6. **定时任务**：`close_expired_orders`（超时关单，经 TaskScheduler 注册）、`run_reconciliation`（T+1 对账）、风控 `check_prepay` 挂在下单入口前置校验。

## 9. 常见坑

- **回调验签失败返回 401**：验签失败必须回 401（微信自动重试），回 200 会导致渠道不再重试、掉单；业务校验失败（金额/状态冲突）才回 4xx 非 401。
- **下单失败直接重试**：下单是资金操作，`WeChatPayClient` 对 prepay 传了 `retryable=False`，失败应**先查单确认**再决策（防重复下单/重复扣款，规范 §7.2 红线）。
- **未注入 order_store/flow_store 时兜底失效**：回调金额校验、下单幂等、流水落库全部降级跳过（仅日志告警），生产必须注入。
- **金额用 float 计算**：金额必须 Decimal（元）；元↔分换算用 `PaymentConstant.BIZ_PAY_AMOUNT_SCALE`，禁止浮点换算（精度丢失）。
- **关单前不查单**：骨架已固化「查单确认未支付才关单」，但定时关单任务/人工关单务必走骨架 `close_order`，查单失败跳过不强行关单。
- **对账自动动账**：`ReconciliationService` 的自动补记/冲正必须注入 `query_order`/`query_refund`（渠道权威状态）；金额/状态不一致强制人工，不要绕过 `MANUAL_ONLY_TYPES`。
- **回调幂等**：`PaymentStateMachine` 的幂等重复对保证订单状态不冲突，但**业务侧**（发货/积分）幂等需自己保证（建议复用框架幂等组件或消息表）。
- **回调入口未注册处理器**：`PaymentCallbackDispatcher` 无处理器时静默忽略并告警——排查回调「收到但无效果」先查是否注册了处理器。
