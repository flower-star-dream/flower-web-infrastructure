# 测试切片（轻量测试上下文 / 组件替身 / 上下文缓存 / 自动回滚）

> 对标 Spring Boot Test 切片（`@SpringBootTest` / `@DataJpaTest` / `@WebMvcTest`）与 `@MockBean`：**只装配指定能力子集，不起全应用**（不触网、开销低），用替身对象替换外部依赖，让单测聚焦被测逻辑。入口统一从 `from web_infra.testing import ...`（或顶层 `from web_infra import ...`）。

## 1. 是什么

`web_infra.testing`（源码见 `src/web_infra/testing/`）提供：

| 组件 | 职责 |
| ---- | ---- |
| `TestContext` | 轻量测试上下文：按 components 子集装配出的组件集合（`components` 字典 + 按名取组件的 `__getattr__`） |
| `web_test_context` | 构建 `TestContext`（只装配指定组件子集，绑定 AOP 组件访问器） |
| `bind_test_components` | 把测试组件绑定到 AOP 访问器（供 mock_component 替换） |
| `mock_component` | 组件替身注入（对标 `@MockBean`） |
| `get_context` | 测试上下文缓存（按配置指纹复用，降低启动开销） |
| `clear_cache` | 清空测试上下文缓存（测试隔离用） |
| `auto_rollback` | 测试自动回滚（当前为最小实现） |

**为何用**：被测代码经 AOP 组件访问器（`get_component("cache")` / `"db"` 等）取组件（见 [AOP 文档](./24-声明式横切与AOP.md) §7）。测试切片只需装配被测逻辑依赖的组件子集（如只装 `cache`），并用替身替换外部依赖，即可脱离真实 DB/Redis/MQ 运行。

## 2. web_test_context：构建轻量测试上下文

```python
from web_infra.testing import web_test_context

# 只装配 cache 组件（默认）
ctx = web_test_context()

# 指定装配 cache + mq 两个组件 + 应用配置覆盖
ctx = web_test_context(settings={"app.cache.max_size": 500}, components=("cache", "mq"))
```

**真实接口签名**：

```python
def web_test_context(
    settings: dict[str, Any] | None = None,
    *,
    components: tuple[str, ...] = ("cache",),
) -> TestContext: ...
```

要点（源码事实）：

- `settings`：应用配置覆盖字典，与框架默认源（`Settings.default_source()`）合并为 `Settings`。
- `components`：装配的组件名集合，默认 `("cache",)`。**当前仅支持无外部依赖的组件子集**：`cache` / `mq` / `storage` / `registry`（其它组件名抛 `ValueError`）。
- 装配后自动调用 `bind_components(components_dict)`，把组件绑定到 AOP 组件访问器——被测代码即可经 `get_component(...)` 取到这些测试组件。

## 3. TestContext：上下文对象

```python
from web_infra.testing import TestContext

@dataclass
class TestContext:
    __test__ = False                 # 声明非 pytest 测试类（类名以 Test 开头，避免被 pytest 误收集）
    components: dict[str, Any]       # 已装配组件字典，如 {"cache": MemoryCacheBackend}

    def __getattr__(self, name: str) -> Any: ...
```

要点：

- `components`：按子集构建的组件字典。
- `__getattr__`：按名取组件（`app.state.<name>` 语义）；组件不存在抛 `AttributeError`。
- 注意设置 `__test__ = False`：避免 `TestContext` 这个类名（以 `Test` 开头）被 pytest 误收集为测试。

## 4. mock_component：组件替身注入

```python
from web_infra.testing import mock_component

# 装饰一个"返回替身"的工厂函数：装饰即把该组件替换为替身产物
@mock_component("cache")
def fake_cache():
    return MemoryCacheBackend(max_size=10)   # 或用自定义替身/桩
```

**真实接口签名**：

```python
def mock_component(component_name: str) -> Callable[[Callable[..., R]], Callable[..., R]]: ...
```

要点（源码事实，对标 `@MockBean`）：

- 装饰一个**返回替身**的工厂函数；被装饰函数执行时调用工厂并调用 `_install(fake)` 替换组件。
- **装饰时即装配替身**（对标 Spring `@MockBean` 在测试前注册）：装饰这行代码执行时就会调 `_install(factory())`（需要工厂无参可调用），后续 `get_component(component_name)` 即返回替身。
- 实现基于 `all_components()` 取当前全量组件副本 → 替换单个组件 → `bind_components()` 回绑全量；**未替换组件保持原值**（不污染容器原对象）。
- 替代后若需恢复，可重新 `bind_test_components(components)` 或 `clear_cache()` + 重新构建。

## 5. get_context：测试上下文缓存

```python
from web_infra.testing import get_context, clear_cache

# 按 (settings, components) 指纹取/建上下文：缓存命中直接复用
ctx = get_context(settings={"app.cache.max_size": 500}, components=("cache",))

clear_cache()    # 测试隔离用：清空缓存
```

**真实接口签名**：

```python
def get_context(settings: dict[str, Any], components: tuple[str, ...]): ...
def clear_cache() -> None: ...
```

要点（源码事实，对标 Spring 测试上下文缓存）：

- 缓存键 = `(tuple(sorted(settings.items())), components)`；未命中才构建 `web_test_context(settings, components=components)` 并写入缓存。
- **仅缓存无副作用组件子集**（cache/mq/storage/registry）。重复构建同 spec 直接复用，降低测试启动开销。
- `clear_cache()` 用于测试隔离（如多个测试文件之间避免组件状态串扰）。

## 6. auto_rollback：测试自动回滚

```python
from web_infra.testing import auto_rollback

@auto_rollback
async def test_xxx():
    ...
```

**真实接口签名**：

```python
def auto_rollback(fn: Callable[..., R]) -> Callable[..., R]: ...
```

**当前为最小非破坏性实现**（源码事实，注意与实际能力边界）：装饰器在函数执行外包一层包装，任何情况下不真正提交（由调用方控制）——完整回滚需与框架事务边界（`db.session` NESTED / `open_transaction` + rollback）协作，后续增强。

> 对你而言：在当前最小实现下，`auto_rollback` 只保证「装饰可调用、不污染」；若测试需要真正的事务回滚语义，请结合 `db.session()`/事务边界自行控制，或在框架后续增强后再依赖。**不要假设它会自动回滚已提交的数据。**

## 7. 最小可运行示例

```python
# test_order_service.py
import pytest
from web_infra.testing import web_test_context, mock_component, get_context, auto_rollback
from web_infra.capabilities.cache import MemoryCacheBackend, CacheConfig


def test_cache_slice_only():
    ctx = web_test_context(components=("cache",))
    cache = ctx.cache                       # 按名取 cache 组件（MemoryCacheBackend）
    assert cache is not None


@mock_component("cache")
def fake_cache_factory():
    # 装饰即替换：此后 get_component("cache") 返回替身
    return MemoryCacheBackend(CacheConfig(max_size=10))


def test_with_mock_cache():
    # 写业务测试：被测方法经 get_component("cache") 拿到替身
    ...
```

复用缓存的推荐写法（pytest fixture 风格）：

```python
import pytest
from web_infra.testing import get_context, clear_cache


@pytest.fixture()
def ctx():
    clear_cache()                                    # 测试隔离
    return get_context(settings={}, components=("cache",))


def test_using_cached_context(ctx):
    assert ctx.cache is not None
```

## 8. 常见坑

1. **组件子集有限**：`web_test_context` 目前只支持 `cache` / `mq` / `storage` / `registry`，其它组件名抛 `ValueError`。要 mock `db`/`redis` 等，先用 `web_test_context` 装支持项，再用 `mock_component` 替换你需要的组件。
2. **mock_component 装饰工厂需无参可调用**：装饰时就会 `_install(factory())`，工厂若需参数应改为无参或预先绑定；替身在装饰时即生效（不必等到被装饰函数调用）。
3. **替身替换污染全局**：`mock_component` 通过 AOP 组件访问器（全局 ContextVar）替换，跨测试会残留——建议在测试隔离处 `clear_cache()` / `bind_test_components(...)` 重置，避免影响其他用例。
4. **TestContext 类名被 pytest 收集**：已设置 `__test__ = False` 规避；自定义类若以 `Test` 开头请同样标记。
5. **不要依赖 auto_rollback 真正回滚**：当前最小实现不自动回滚已提交数据，需真实回滚请结合框架事务边界。
6. **未绑定组件访问器即调用**：被测代码经 `get_component` 取组件，务必先 `web_test_context(...)` / `bind_test_components(...)` 完成绑定，否则取到 `None`（或抛错）。
