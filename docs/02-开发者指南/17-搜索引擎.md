## 1. 是什么

`web_infra.capabilities.search` 是框架的全文检索能力层（搜索引擎接入计划 v0.2.0 §3）：

- **统一 SPI**：`SearchEngineInterface`（`@runtime_checkable` Protocol）定义索引生命周期（创建/删除，幂等）、单条/批量写入、删除、关键词检索（分页/高亮）；
- **默认实现** `InMemorySearchEngine`：简化 BM25 打分 + 倒排索引，单机/测试零依赖；
- **生产实现** `ElasticsearchSearchEngine`：基于官方 `elasticsearch-dsl`（AsyncSearch / AsyncIndex），支持业务自定义 mapping/settings（含 IK 中文分词入口）、`multi_match` 全字段检索、高亮；
- **注册表** `SearchEngineRegistry`：按 `type` 名装配，内置 `memory` / `elasticsearch` 条目，自定义实现 `register` 即可接入（无需改框架代码）；
- 与向量检索互补：全文检索（关键词/分词）见本文，向量 kNN 检索走 [16-RAG检索与向量库.md](./16-RAG检索与向量库.md)（`ElasticsearchVectorStore`，索引后缀 `_vector`）。

## 2. 何时用

- 商品/文章/日志等**结构化或半结构化文档**的关键词全文检索（按相关性排序、分页、高亮）；
- 期望业务代码只依赖统一接口，默认内存可跑、生产无缝切 ES；
- 多租户系统需要**按租户隔离索引**（真实索引名带租户前缀）；
- 注意：全文检索不是向量语义检索——需要「语义相似」召回请用 RAG 向量库（[16-RAG检索与向量库.md](./16-RAG检索与向量库.md)），两者可共存。

### 2.1 实现选型

| 维度 | InMemorySearchEngine | ElasticsearchSearchEngine |
| ---- | -------------------- | ------------------------- |
| 外部依赖 | 无 | ES 集群（`[es]` extra） |
| 部署形态 | 单实例/单进程（`@Stateful`，多实例不共享） | 任意实例数 |
| 分词 | 英文按单词、中文按单字（简单分词） | 可配 IK 等分析器（`mappings` 透传） |
| 打分 | 简化 BM25（K1=1.2、B=0.75） | ES 原生 BM25 |
| 容量 | `max_documents_per_tenant` 上限淘汰最旧 | 无内置上限（由 ES 集群承载） |
| 适用场景 | 测试 / 演示 / 小规模单机 | 生产 / 大规模 / 多实例 |
| 接入方式 | `app.search.type: memory`（默认） | `app.search.type: elasticsearch` |

## 3. 启用与配置（app.search.*）

默认关闭（`enabled: false`），需业务显式开启：

```yaml
app:
  search:
    enabled: true
    type: elasticsearch     # memory（默认，零依赖）/ elasticsearch（生产推荐，需 [es] extra）/ custom（自研，SPI 接入）
    index_prefix: web       # 真实索引名 {index_prefix}_{tenant}_{index}，多租户前缀隔离（按部署环境可覆盖）
    elasticsearch:
      hosts: ["http://localhost:9200"]   # 列表或逗号分隔字符串，经 APP_SEARCH_ELASTICSEARCH_HOSTS 覆盖
      username: ${APP_SEARCH_ELASTICSEARCH_USERNAME:}
      password: ${APP_SEARCH_ELASTICSEARCH_PASSWORD:}
      verify_certs: true     # TLS 证书校验（生产默认开启；测试环境可显式关闭）
      connect_timeout: 5
      read_timeout: 30
```

搜索引擎**不挂 `app.state`**，业务代码经注册表直接实例化使用（与 `create_app` 解耦）：

```python
from web_infra import SearchEngineRegistry, Settings

engine = SearchEngineRegistry.create("elasticsearch", Settings())   # 按 app.search.type 实例化
```

## 4. SearchEngineInterface

```python
class SearchEngineInterface(Protocol):
    async def create_index(self, tenant_id, index_name, *, mappings=None, settings=None) -> None
    async def delete_index(self, tenant_id, index_name) -> None
    async def index_document(self, tenant_id, index_name, doc_id, document, *, refresh=False) -> None
    async def bulk_index(self, tenant_id, index_name, documents, *, refresh=False) -> None
    async def delete_document(self, tenant_id, index_name, doc_id, *, refresh=False) -> None
    async def search(self, tenant_id, query: SearchQuery) -> list[SearchHit]
```

语义约定：

- **索引生命周期幂等**：`create_index` 已存在不报错；`delete_index` / `delete_document` 不存在静默（ES 实现 `NotFoundError`/`404` 吞掉）；
- **`index_document`**：doc_id 幂等（同名覆盖，全量替换）；`refresh=True` 立即可查（默认 false 近实时）；
- **`bulk_index`**：`documents` 每项**必须含 `id` 键**（作为文档标识，不写入内容），缺 `id` 的项跳过并告警、不中断整批；
- **`tenant_id` 可选**：显式传则按租户隔离；缺省读请求上下文（`TenantGuard.current_tenant()`）；再无回落 `no-tenant` 占位（单租户系统所有数据收敛同一命名空间）。

## 5. SearchQuery 与 SearchHit

```python
SearchQuery(
    keyword="苹果",        # 查询关键词（必填，长度 ≥1）
    index_name="default",  # 业务索引名（在租户命名空间内解析，默认 "default"）
    offset=0,              # 分页偏移（对应 ES from，≥0）
    size=10,               # 返回条数（对应 ES size，1~100，默认 10）
    highlight=False,       # 是否返回高亮片段
)

SearchHit(
    id="p1",               # 文档唯一标识
    score=3.2,             # 相关性得分（越大越相关）
    source={"title": "苹果手机"},   # 文档内容（写入时的原始字段）
    highlight={"title": ["<em>苹果</em>手机"]},  # 高亮片段（字段名 → 片段列表；未开启时为空字典）
)
```

高亮标签统一为 `<em>` / `</em>`（`SearchConstant.HIGHLIGHT_PRE_TAG/POST_TAG`，内存与 ES 实现一致，业务不感知实现差异）。

### 5.1 SearchConstant 常量速查

| 常量 | 值 | 说明 |
| ---- | -- | ---- |
| `DEFAULT_INDEX_PREFIX` | `"web"` | 索引前缀默认值（`app.search.index_prefix` 缺省） |
| `DEFAULT_INDEX_NAME` | `"default"` | 默认业务索引名（`SearchQuery.index_name` 缺省） |
| `VECTOR_INDEX_NAME` | `"vector"` | 向量索引业务名（RAG 向量库命名空间后缀，见 [16-RAG检索与向量库.md](./16-RAG检索与向量库.md)） |
| `DEFAULT_PAGE_SIZE` / `MAX_PAGE_SIZE` | `10` / `100` | 分页默认条数 / 上限（`SearchQuery.size` 约束 1~100） |
| `HIGHLIGHT_PRE_TAG` / `HIGHLIGHT_POST_TAG` | `<em>` / `</em>` | 高亮标签（两实现统一） |
| `BM25_K1` / `BM25_B` | `1.2` / `0.75` | 简化 BM25 参数（与 Lucene/ES 默认一致） |
| `ERROR_DOMAIN` | `"SRCH"` | 错误码域前缀（E3-SRCH / E4-SRCH） |

## 6. InMemorySearchEngine（默认实现）

`@Stateful` 进程内实现（单实例/单进程，多实例需换 ES）：

- **分词**：`tokenize(text)` 英文按单词（小写）、中文按单字、数字整体（`"Hello 世界 123"` → `["hello", "世", "界", "123"]`）；构建倒排索引（term → {doc_id: term_frequency}）；
- **简化 BM25 打分**：`K1 = 1.2`、`B = 0.75`（与 Lucene/ES 默认一致，`SearchConstant`），IDF + 长度归一化 TF 求和；得分降序 → 分页切片 → 可选高亮；
- **租户命名空间**：内部按（解析后租户, 索引名）划分，禁止跨租户命中；
- **容量上限**：`max_documents_per_tenant`（构造参数，默认 None 不限制）超限按写入顺序淘汰最旧文档（防内存无限增长）；
- **mappings/settings 忽略**：内存实现无物理索引，`create_index` 仅校验命名空间参数后幂等空操作。

## 7. ElasticsearchSearchEngine（生产实现）

基于 `elasticsearch-dsl` ORM（AsyncSearch / AsyncIndex）+ 底层 client 写入，连接参数来自 `app.search.elasticsearch`：

- **创建索引**：`indices.create`（body 完全自定义），`settings` 默认 `{"number_of_shards": 1, "number_of_replicas": 0}`（业务传入的 settings 覆盖合并）；`mappings` 原样透传——**IK 等中文分词分析器配置入口**；已存在（`resource_already_exists_exception`）幂等忽略，其他错误转 `E3-SRCH-001`；
- **写入/删除**：client `index` / `bulk` / `delete`（`refresh` 参数透传；`NotFoundError` 静默）；异常转 `E3-SRCH-000`；
- **检索**：
  - `Q("multi_match", query=keyword, fields=["*"])`——**全字段**匹配；
  - 分页：`s[offset : offset + size]` 切片语法映射 ES from/size；
  - 高亮：`s.highlight("*", require_field_match=False, pre_tags=["<em>"], post_tags=["</em>"])`——`require_field_match=False` 保证**非匹配字段也能返回高亮**；
  - **索引不存在（NotFoundError）检索降级返回空列表**（不阻断主流程，与 Retriever 异常降级语义一致）；其他异常转 `E3-SRCH-000`；
- **`aclose()`**：释放底层连接（应用停机/测试收尾调用）；
- 支持注入 `client`（AsyncElasticsearch 实例，测试 Mock 用）。

### 7.1 生产实践：IK 中文分词 + 高亮完整配置

中文场景强烈建议在 `create_index` 时显式声明分析器（ES 默认 standard 分析器对中文效果差）：

```python
await engine.create_index(
    "t1", "products",
    mappings={
        "properties": {
            # ik_max_word 索引粒度最细（召回全）；search_analyzer 用 ik_smart 查询粒度更准
            "title": {"type": "text", "analyzer": "ik_max_word", "search_analyzer": "ik_smart"},
            "description": {"type": "text", "analyzer": "ik_max_word", "search_analyzer": "ik_smart"},
            "price": {"type": "float"},
            "category": {"type": "keyword"},       # 精确匹配字段用 keyword
        }
    },
    settings={"number_of_shards": 1, "number_of_replicas": 0},
)
```

> 前置条件：ES 集群需安装 IK 分词插件（`bin/elasticsearch-plugin install analysis-ik`）；
> `multi_match(fields=["*"])` 对 text 字段生效，keyword 字段精确匹配不参与分词。高亮无需专门字段配置——`highlight("*")` 自动作用于全部检索字段。

## 8. SearchEngineRegistry 工厂注册

```python
SearchEngineRegistry.register("memory", lambda settings: InMemorySearchEngine())          # 内置
SearchEngineRegistry.register("elasticsearch", _elasticsearch_search_factory)            # 内置（读取 app.search 配置）
engine = SearchEngineRegistry.create("elasticsearch", Settings())   # 未注册抛 KeyError（装配期转 ConfigError）
```

- 工厂签名 `SearchEngineFactory = Callable[[Settings], SearchEngineInterface]`；
- 内置条目模块导入即注册（幂等）；`register` 同名覆盖；`unregister` / `registered_names` 配套；
- **自定义搜索引擎接入**：`register("my_search", factory)` 后 `app.search.type: my_search` 即装配，无需改框架代码；
- `elasticsearch` 条目**仅在工厂被调用（实例化）时**才加载 es extra 依赖——未安装 `[es]` 时 `memory` 装配不受影响。

## 9. 索引命名与租户隔离

- 真实索引名：`{index_prefix}_{tenant_id}_{index_name}`（全文，如 `web_t1_products`）与 `{index_prefix}_{tenant_id}_vector`（向量库）；
- `tenant_id` / `index_name` **禁止含下划线 `_`**（命名空间分隔符保留），违例抛 ValueError；
- 租户解析优先级：显式传参 > `TenantGuard.current_tenant()`（请求上下文）> `no-tenant` 占位（单租户收敛同一命名空间）。

## 10. 错误码

| 错误码 | 说明 | HTTP | 可重试 | 触发场景 |
| ------ | ---- | ---- | ------ | -------- |
| E3-SRCH-000 | 搜索引擎调用失败 | 502 | ✅ | 检索/写入异常（ES 不可用、网络抖动） |
| E3-SRCH-001 | 索引操作失败 | 502 | ✅ | 创建/删除索引失败 |
| E4-SRCH-001 | 搜索引擎未配置/未注册 | 422 | ❌ | `SearchEngineRegistry` 未注册的 type |
| E4-SRCH-002 | 检索参数非法 | 422 | ❌ | SearchQuery 校验失败（keyword 空、size 超界等） |
| E4-SRCH-003 | 索引不存在 | 404 | ❌ | 索引不存在（检索侧已降级空列表，此码保留给显式场景） |

错误码权威清单见 [常量与错误码.md](../常量与错误码.md)；E3 可重试（配合重试中间件/韧性组件，见 [14-韧性设计.md](./14-韧性设计.md)）。

## 11. es extra 依赖

```bash
pip install "flower-web-infrastructure[es]"
```

`ElasticsearchSearchEngine` 依赖 es extra（`elasticsearch-dsl>=8.0`，自动携带 `elasticsearch-py`）；**延迟导入**——未安装时导入模块不报错，构造实例才抛安装提示。`InMemorySearchEngine` 无任何外部依赖。

## 12. 代码示例

```python
import asyncio

from web_infra import Settings, SearchEngineRegistry
from web_infra.capabilities.search import SearchQuery

async def main() -> None:
    # 按配置实例化（app.search.type 决定 memory / elasticsearch）
    engine = SearchEngineRegistry.create("elasticsearch", Settings())

    # 1) 建索引：业务自定义 mapping（IK 中文分词入口，生产启用）
    await engine.create_index(
        "t1", "products",
        mappings={
            "properties": {
                "title": {"type": "text", "analyzer": "ik_max_word"},
                "price": {"type": "float"},
            }
        },
    )

    # 2) 写入（单条 + 批量；doc_id 幂等覆盖）
    await engine.index_document("t1", "products", "p1", {"title": "苹果手机", "price": 5999.0})
    await engine.bulk_index(
        "t1", "products",
        [
            {"id": "p2", "title": "华为平板", "price": 2999.0},
            {"title": "缺 id 会被跳过"},                 # 缺 id 的项跳过并告警
        ],
    )

    # 3) 检索：关键词 + 分页 + 高亮
    hits = await engine.search(
        "t1",
        SearchQuery(keyword="苹果", index_name="products", offset=0, size=10, highlight=True),
    )
    for hit in hits:
        print(hit.id, round(hit.score, 4), hit.source, hit.highlight)
        # p1 3.x {'title': '苹果手机', 'price': 5999.0} {'title': ['<em>苹果</em>手机']}

    # 4) 删除（幂等）
    await engine.delete_document("t1", "products", "p1")
    await engine.delete_index("t1", "products")          # 幂等，可重复调用

    # 单租户系统：可不传租户，缺省读请求上下文、再无回落 no-tenant 占位
    hits = await engine.search(None, SearchQuery(keyword="苹果", index_name="products"))

asyncio.run(main())
```

> 说明：检索索引不存在时降级返回空列表（不抛错），写入前可不先建索引——`index_document` 依赖 ES 动态 mapping 直接写入；但生产建议先 `create_index` 声明字段类型与分析器。

### 12.1 与向量检索（RAG）互补使用

全文检索与向量检索索引天然共存（命名空间后缀不同，互不干扰）：

```python
# 全文索引：{index_prefix}_{tenant}_{index_name}，如 web_t1_products
await engine.create_index("t1", "products", mappings={...})

# 向量索引：{index_prefix}_{tenant}_vector，如 web_t1_vector（ElasticsearchVectorStore 内部维护）
from web_infra.capabilities.ai.retrieval import ElasticsearchVectorStore
vec_store = ElasticsearchVectorStore(hosts=["http://localhost:9200"], dims=768, index_prefix="web")
vec_store.add("t1", ["c1"], [[0.1] * 768])
```

典型组合：**关键词检索（本文）兜底精确词命中 + 向量检索（RAG）补充语义召回**，两者结果可按业务规则融合（如关键词结果优先、向量结果补充），或分别作为不同接口暴露。

## 13. 常见坑

- **中文检索效果差**：默认（动态 mapping）ES 用 standard 分析器，中文按整体/单字匹配效果有限；生产务必在 `create_index` 的 `mappings` 里声明 `"analyzer": "ik_max_word"` 并安装 IK 分词插件；
- **`bulk_index` 丢数据**：每项必须带 `id` 键且不写入内容，缺 id 的项被静默跳过（仅告警）——检查批量数据是否都带了 id；
- **`type: elasticsearch` 装配报 KeyError/ImportError**：先确认已 `pip install "flower-web-infrastructure[es]"`（延迟导入：构造时才报错）；未注册的 type 抛 KeyError（装配期转 ConfigError）提示内置 memory/elasticsearch；
- **租户/索引名含下划线报 ValueError**：真实索引名用 `_` 拼接，`tenant_id` 与 `index_name` 本身禁止含 `_`（命名空间分隔符保留）；
- **写入后搜不到**：默认 `refresh=False` 近实时语义，写入后立即检索可能不命中；需要立即可查时 `refresh=True`；
- **内存实现在多实例下不共享**：`InMemorySearchEngine` 是进程内状态，多实例部署必须切 ES；
- **全文 ≠ 语义**：关键词检索按分词匹配，同义词/改写检索不到；语义召回请用向量库（[16-RAG检索与向量库.md](./16-RAG检索与向量库.md)）。
