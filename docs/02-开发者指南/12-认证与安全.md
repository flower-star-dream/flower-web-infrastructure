## 1. 能力总览

| 能力 | 入口 | 说明 |
| ---- | ---- | ---- |
| JWT 签发/校验/登出 | `JWTUtil` + `TokenVerifyStatus` | 静默刷新（EXPIRING 阈值 300s）、refresh token 单独密钥段、同设备凭证复用、kid 密钥版本 |
| 签名密钥 SPI | `JwtKeyProvider` | 默认 `EnvJwtKeyProvider`（`JWT_SECRET_KEY` 环境变量必填 + HS256） |
| Token 状态存储 SPI | `JwtTokenStore` | 内存（单实例）/ Redis（分布式，框架启用 Redis 时默认） |
| 密码加密 | `PasswordEncoder` | bcrypt，UTF-8 前 72 字节截断 |
| 图形验证码 | `CaptchaService` + `CaptchaStoreInterface` | 去混淆字符池、一次性消费、TTL 300s |
| 登录防爆破 | `LoginFailLockService` | 账号 + IP 双维度，默认 5/10 次，Redis 异常静默降级 |
| RBAC 接口权限 | `PermissionGuard.require` | 声明式依赖注入，admin 通配，权限点走 `AUTH_PERM_` 常量 |
| 水平越权防护 | `DataPermissionGuard.check` | 按 owner_id 三重校验，失败抛 E2-PERM-000 |
| PII 检测脱敏 | `PrivacyGuard` | 手机/身份证/银行卡/邮箱/中文姓名/地址 |
| OAuth2 | `OAuth2ClientRegistry` + `OAuth2TokenService` | client_credentials 最小实现，默认 15 分钟 TTL |
| 三方登录 | `SocialLoginService` + `SocialPlatformRegistry` | 生成授权 URL / 登录 / 绑定 / 解绑，E2-AUTH-005~008 |
| 统一鉴权中间件 | `app.web.middlewares.auth` | Bearer 解析 + 白名单 + 注入请求上下文，业务禁止自行解析凭证 |

> 安全相关常量（`AUTH_` 前缀）唯一权威来源为 `web_infra.infra.constants.auth_constant.AuthConstant`（规范 §6.9），错误码大类 E2 见 [常量与错误码.md](../常量与错误码.md)。

## 2. JWT 体系

### 2.1 组件构成

JWT 体系由 4 个角色协作（`web_infra.capabilities.security`）：

1. **JWTUtil**（核心门面，全部为类方法/类属性）：
   - `configure(token_store, key_provider)`：启动期一次性注入自定义 SPI（进程内全局，优先级最高）；
   - `set_redis(redis)` / `set_redis_config(config)`：注入 Redis（Application 装配时自动调用，启用 Redis 后 Token 状态默认走 Redis）；
   - `generate_token(user_id, username, extra_claims, expires_in, client_id, device_id)`：签发 access token 并写入状态存储（同设备凭证复用）；
   - `verify_token(token) -> (payload, TokenVerifyStatus)`：校验（含静默刷新信号）；
   - `create_refresh_token(user_id, username, extra_claims, expires_days)`：签发 refresh token（单独密钥段 + `token_type="refresh"`，不写状态存储）；
   - `verify_refresh_token(token)`：校验 refresh token（`token_type` 必须为 refresh，防与 access 混用）；
   - `parse_token` / `get_user_id`：便捷解析；
   - `invalidate_token(token)`：使 token 失效（登出，走状态存储 revoke）；
   - `get_current_device_jti` / `get_current_device_jti_async`：查询同设备当前有效 jti（Redis 场景必须用 async 版）。
2. **TokenVerifyStatus** 枚举：`VALID / EXPIRED / INVALID / REVOKED / EXPIRING`。`EXPIRING` 表示凭证尚未过期但剩余有效期低于阈值（300s），由统一入口拦截识别后放行并触发静默续期，而不是拒绝请求。
3. **JwtKeyProvider**（SPI，`Protocol`）：`access_secret()` / `refresh_secret()` / `algorithm()`。默认 `EnvJwtKeyProvider`：
   - access 密钥 = 环境变量 `JWT_SECRET_KEY`（缺失抛 RuntimeError，禁止落盘）；
   - refresh 密钥 = 主密钥 + `":refresh"` 后缀派生（规范 §6.1 单独密钥段，与 access 双向防混用）；
   - 算法固定 `HS256`（`AuthConstant.AUTH_JWT_ALGORITHM`）。
4. **JwtTokenStore**（SPI，`Protocol`）：`save` / `exists` / `revoke` / `current_jti`。默认实现：`InMemoryJwtTokenStore`（单实例，RLock + 惰性清理过期条目）；`RedisJwtTokenStore`（分布式，Key 经 `CacheKeyBuilder` 生成：`web:auth:v1:token:{user_id}:{jti}`、`web:auth:v1:user_tokens:{user_id}`、`web:auth:v1:device_token:{user_id}:{client_id}:{device_id}`）。

**同设备凭证复用**（规范 §6.2）：`save` 按 `(user_id, client_id, device_id)` 复合键维护最新 jti，同设备新签发会替换旧 jti（旧凭证立即失效，最多 1 个有效凭证）。

### 2.2 配置与装配

JWT 相关配置项不在 `application.yml` 中（统一从环境变量读取，规范 §15.2）：

| 配置项 | 来源 | 默认 | 说明 |
| ------ | ---- | ---- | ---- |
| `JWT_SECRET_KEY` | 环境变量/.env | **必填**（缺失启动即 RuntimeError） | access token 签名密钥；支持 `enc:` 前缀加密值（ConfigCipher 自动解密） |
| `JWT_EXPIRE_MINUTES` | 环境变量/.env | `120` | access token 有效期（分钟），经 `SecureConfigLoader.get_jwt_expire_minutes()` 读取 |
| `AUTH_TOKEN_REFRESH_TTL_DAYS` | 常量 | `7` | refresh token 默认有效期（天），`create_refresh_token(expires_days=...)` 可覆盖 |
| `REFRESH_THRESHOLD_SECONDS` | 常量 | `300` | 静默刷新阈值：剩余有效期低于该值返回 `EXPIRING` |
| `JWT_KID` | 常量 | `"v1"` | 密钥版本标识（S15-3：密钥 ≥90 天轮换，kid 标识版本，新旧并行 ≥24h） |

状态存储的自动回落规则（无需手动配置）：`configure` 注入的自定义 store > `set_redis` 显式注入 > 框架 Redis 默认（`set_redis_config` 注入且应用启用了 Redis）> `InMemoryJwtTokenStore`。**多实例部署必须使用 Redis 状态存储**（内存实现进程内状态无法共享，同设备凭证复用与登出撤销会失效）。

### 2.3 代码示例

签发、校验（含静默刷新）、登出：

```python
import asyncio
import os

os.environ["JWT_SECRET_KEY"] = "dev-only-secret-please-rotate"  # 生产经环境变量注入，禁止写代码

from web_infra.capabilities.security.jwt_util import JWTUtil
from web_infra.capabilities.security.token_verify_status_enum import TokenVerifyStatus


async def demo():
    # 1. 签发 access token（expires_in 缺省走 JWT_EXPIRE_MINUTES=120）
    token = await JWTUtil.generate_token(
        user_id="u1001",
        username="alice",
        client_id="web",          # 同设备凭证复用维度（不传按 user_id 聚合）
        device_id="device-1",
    )

    # 2. 校验：返回 (payload, 状态)；剩余有效期 < 300s 时为 EXPIRING（静默刷新信号）
    payload, status = await JWTUtil.verify_token(token)
    if status in (TokenVerifyStatus.VALID, TokenVerifyStatus.EXPIRING):
        print("有效，user_id =", payload["sub"])
    elif status == TokenVerifyStatus.EXPIRED:
        print("过期")
    elif status == TokenVerifyStatus.REVOKED:
        print("已登出")
    else:
        print("非法/被混用")

    # 3. 静默刷新：EXPIRING 时用 refresh token 续期
    refresh = await JWTUtil.create_refresh_token("u1001", "alice")  # 默认 7 天
    r_payload, r_status = await JWTUtil.verify_refresh_token(refresh)
    if r_status == TokenVerifyStatus.VALID:
        new_token = await JWTUtil.generate_token("u1001", "alice",
                                                 client_id="web", device_id="device-1")

    # 4. 登出：吊销 access token（同设备旧 jti 被替换后同样失效）
    await JWTUtil.invalidate_token(new_token)


asyncio.run(demo())
```

自定义 SPI（例如切换到 RS256 或 KMS 托管密钥）：

```python
from web_infra.capabilities.security.jwt_key_provider_interface import JwtKeyProvider
from web_infra.capabilities.security.jwt_util import JWTUtil


class RsaKeyProvider:
    """RS256 密钥提供器示例：密钥来自业务密钥管理服务"""

    def access_secret(self) -> str:
        return read_public_key_for_signing()      # 业务自行实现

    def refresh_secret(self) -> str:
        return read_refresh_signing_key()          # refresh 独立密钥段

    def algorithm(self) -> str:
        return "RS256"


JWTUtil.configure(key_provider=RsaKeyProvider())  # 启动期调用一次
```

接入 Redis 状态存储（多实例部署）：

```python
from web_infra.capabilities.db.redis_config import RedisConfig
from web_infra.capabilities.security.jwt_util import JWTUtil

JWTUtil.set_redis_config(RedisConfig(host="127.0.0.1", port=6379, db=0))
# 框架 Application 装配时若启用了 Redis（app.cache.type=redis），会自动注入，无需业务手动调用
```

### 2.4 常见坑

- **未注入 `JWT_SECRET_KEY`**：任何签发/校验调用都会抛 `RuntimeError`（`SecureConfigLoader` 强制环境变量），这是刻意的 fail-fast，不要硬编码密钥进代码或 yml。
- **refresh token 混用**：refresh token 不能当 access token 用（`verify_token` 看到 `token_type=refresh` 直接判 INVALID），反之 `verify_refresh_token` 要求 `token_type == "refresh"`，双向防混用由单独密钥段 + 用途字段双重保证。
- **Redis 状态下勿用同步桥接**：`get_current_device_jti`（同步版）在跨事件循环场景会抛错，Redis 状态存储场景请改用 `get_current_device_jti_async`。
- **多实例必须 Redis 状态存储**：否则登出撤销、同设备凭证复用都只在单进程内生效。
- **`EXPIRING` 不等于拒绝**：凭证即将过期应放行并触发静默刷新（统一入口 AuthMiddleware 与 `OAuth2TokenService.verify_token` 均按 VALID 语义处理 EXPIRING），不要把 EXPIRING 当 EXPIRED 处理。

## 3. 密码 / 验证码 / 防爆破

### 3.1 PasswordEncoder

bcrypt 加密（类似 Spring Security 的 BCryptPasswordEncoder）。bcrypt 仅使用输入的前 72 字节，`PasswordEncoder` 统一截断为 UTF-8 前 72 字节（`AUTH_PASSWORD_BCRYPT_MAX_BYTES=72`）。

```python
from web_infra.capabilities.security.password_encoder import PasswordEncoder

hashed = PasswordEncoder.encode("my-secret-password")   # $2b$12$...（每次随机盐）
assert PasswordEncoder.verify("my-secret-password", hashed) is True
assert PasswordEncoder.verify("wrong", hashed) is False
```

> 注意：72 字节截断意味着超长密码的不同部分可能同哈希，属 bcrypt 固有限制；业务侧如需要，可在调用前自行做摘要扩展，框架按规范实现不再叠加。

### 3.2 CaptchaService

图形验证码生成与校验（规范 §25 应用层安全）。要点：

- 生成：`generate(ttl_seconds=300, length=4, char_pool=_DEFAULT_CHAR_POOL)` 返回 `(captcha_id, code)`；默认字符池为去混淆字符 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`（去除 0/O/1/l/I 等易混淆字符）；
- 校验：`verify(captcha_id, code)` **一次性消费**（`take` 取走即删除，未命中/过期返回 None），大小写不敏感；
- 存储 SPI：`CaptchaStoreInterface`（`save` / `take`），默认 `InMemoryCaptchaStore`（单实例），多实例部署换 `RedisCaptchaStore`（基于 Redis GETDEL 原子取走，Key `web:common:v1:captcha:{captcha_id}`）；
- 图片绘制不属于框架职责：调用方基于返回的 `code` 自行渲染图片（SVG/图片流），`captcha_id` 下发前端回传。

```python
from web_infra.capabilities.security.captcha_service import CaptchaService
from web_infra.capabilities.security.redis_captcha_store import RedisCaptchaStore

captcha = CaptchaService(RedisCaptchaStore(redis_client))  # 单实例可省略参数用内存实现

captcha_id, code = await captcha.generate()          # 4 位去混淆字符，TTL 300s
# 业务：把 captcha_id 随图片一起下发，前端回传 captcha_id + 用户输入
ok = await captcha.verify(captcha_id, input_code)    # 一次性消费，大小写不敏感
```

### 3.3 LoginFailLockService

登录失败计数与账号/IP 双维度锁定（规范 §6.2 凭证安全、§25.1）：

| 参数 | 默认 | 说明 |
| ---- | ---- | ---- |
| `max_user_fail_times` | `5` | 账号维度锁定阈值 |
| `max_ip_fail_times` | `10` | IP 维度锁定阈值 |
| `lock_ttl_seconds` | `1800` | 锁定持续时间（30 分钟） |
| `fail_count_ttl_seconds` | `1800` | 失败计数保留时长 |

机制：Redis `INCR` 原子自增 + 首次失败设 TTL；计数达到阈值写入锁定 Key（TTL 即锁定时长）。**Redis 不可用时静默降级为不计数、不锁定**（保证登录可用性，日志输出 `login_fail_lock_degraded`）。Key 模板：`web:auth:v1:login_fail_count:{username}` / `web:auth:v1:login_lock:{username}` / `web:auth:v1:login_fail_count_ip:{ip}` / `web:auth:v1:login_lock_ip:{ip}`。

```python
from web_infra.capabilities.security.login_fail_lock import LoginFailLockService

lock = LoginFailLockService(redis_client)   # 默认 5 次/账号、10 次/IP

async def do_login(username: str, ip: str, password: str) -> None:
    if await lock.is_locked(username, ip):
        raise CommonErrorCode.RATE_LIMITED.to_exception(message="尝试次数过多，请稍后再试")
    if not verify_password(username, password):
        await lock.record_failure(username, ip)
        raise CommonErrorCode.AUTH_UNAUTHENTICATED.to_exception(message="用户名或密码错误")
    await lock.clear(username, ip)          # 登录成功：清除计数与锁定
```

> `is_locked` 返回 True 仅表示账号或 IP 至少一个被锁；Redis 异常时返回 False（降级放行）。

## 4. 权限

### 4.1 PermissionGuard（RBAC 声明式）

接口级权限控制（规范 §6.6 声明式 + §25.3）：权限来源为 `AuthMiddleware` 注入请求上下文的 `scope`（空格分隔的权限点列表），**admin 通配**（`AUTH_SCOPE_ADMIN="admin"` 仅超级管理员），校验失败统一抛 E2-PERM-000（403）。权限点必须走 `AuthConstant.AUTH_PERM_*` 常量（禁止裸字符串）。

```python
from fastapi import Depends
from web_infra.infra.constants import AuthConstant
from web_infra.capabilities.security.permission_guard import PermissionGuard

# 内置权限点示例：AUTH_PERM_ORDER_READ="ORDER_READ" / AUTH_PERM_ORDER_WRITE="ORDER_WRITE"
@app.post("/v1/orders", dependencies=[Depends(PermissionGuard.require(AuthConstant.AUTH_PERM_ORDER_WRITE))])
async def create_order():
    ...

@app.get("/v1/orders/{order_id}", dependencies=[Depends(PermissionGuard.require(AuthConstant.AUTH_PERM_ORDER_READ))])
async def get_order(order_id: str):
    ...

# require(*permissions)：要求全部权限点；缺任一个即 403 并提示缺失项
# 传非空字符串以外的值（如空串）会在构建依赖时抛 ValueError
```

> 权限点命名遵循 `AUTH_PERM_<模块>_<动作>` 常量前缀；业务新增权限点请在 `AuthConstant` 中扩展常量，不要散落字符串。

### 4.2 DataPermissionGuard（水平越权）

数据属主一致性校验（规范 §25.2）：业务在查询/修改资源前调用，任一条件不满足即拒绝（抛 `PermException`，E2-PERM-000/403）：

- `owner_id` 为空（数据属主缺失）→ 拒绝；
- `owner_id != required_owner_id`（数据属主与请求声明的属主不一致）→ 拒绝；
- `required_owner_id != current_user_id`（请求属主非当前登录用户，越权访问他人数据）→ 拒绝。

```python
from web_infra.infra.context import RequestContext
from web_infra.capabilities.security.data_permission import DataPermissionGuard

async def get_order_detail(order_id: str):
    order = await get_order_by_id(order_id)
    DataPermissionGuard.check(
        owner_id=order.owner_id,              # 数据记录实际属主
        required_owner_id=order.owner_id,     # 请求声明属主（如查询参数 ownerId）
        current_user_id=RequestContext.get_user_id(),  # 当前登录用户
    )
    return order

# 便捷判断（不抛错）：
if DataPermissionGuard.is_owner(order.owner_id, RequestContext.get_user_id()):
    ...
```

## 5. 隐私保护 PrivacyGuard

基于正则的 PII 检测与脱敏（规范 §17.3 敏感信息脱敏、§15.3 数据安全分级）。返回 `PiiResult`（`has_pii` / `matches`（`PiiMatch`：category/start/end/text/masked）/ `masked_text`），`mask()` 快捷返回脱敏后文本。

| 类别 | 识别示例 | 脱敏规则 |
| ---- | ---- | ---- |
| `mobile` | 13800138000 | `138****8000`（11 位）；非 11 位取 `前2****后2` |
| `id_card` | 18 位身份证（末位 x/X） | `前6********后4` |
| `bank_card` | 16~19 位数字 | `****后4` |
| `email` | 邮箱 | `首字母***末字母@域名` |
| `chinese_name` | 由"姓名/联系人/我叫…"等关键词引导的 2~4 个汉字 | `首字**` |
| `address` | 省市区+道路+门牌结构 | 长地址 `前4****后2`；短地址 `前2**后2` |

```python
from web_infra.capabilities.security.privacy_guard import PrivacyGuard

guard = PrivacyGuard()
result = guard.detect("联系人：张三，手机 13800138000，邮箱 zhangsan@example.com")
print(result.masked_text)
# 联系人：张**，手机 138****8000，邮箱 z***n@example.com
print(result.has_pii)          # True
print([m.category for m in result.matches])  # ['chinese_name', 'mobile', 'email']

# 日志/接口输出脱敏场景直接用 mask：
safe_text = guard.mask(user_note)
```

> 中文姓名识别依赖"姓名/联系人/我叫/我是/患者/家属/医生"等触发词（支持 `:：` 分隔），无法覆盖所有语境；对高敏字段（如身份证）建议业务在存储层直接脱敏，而不只依赖正则兜底。

## 6. OAuth2

最小化 client_credentials 实现（规范 §6.1/§6.2/§6.4/§6.7）：客户端凭证校验后签发自包含 access token（复用 JWTUtil），载荷含 `userId/scope/exp`；授权码模式端点预留（`OAuth2Client` 携带 `redirect_uris`）。

```python
from web_infra.capabilities.security.oauth2 import (
    InMemoryOAuth2ClientRegistry, OAuth2Client, OAuth2TokenService,
)

# 1. 注册客户端（client_secret 服务端保存，禁止明文入库；多实例可扩展数据库实现）
registry = InMemoryOAuth2ClientRegistry()
registry.register(OAuth2Client(
    client_id="web",
    client_secret="client-secret-xxx",
    scopes=("read", "write"),       # 客户端可用权限范围（§6.6 Scope）
))

# 2. 令牌服务：默认 access token 有效期 15 分钟
svc = OAuth2TokenService(registry)   # access_token_ttl_minutes=15

# 3. client_credentials 签发
resp = await svc.issue_client_token("web", "client-secret-xxx", scopes=["read"])
# {'access_token': 'eyJ...', 'token_type': 'Bearer', 'expires_in': 900}

# 4. 资源服务器统一入口校验（配合 AuthMiddleware 注入 token_verifier）
payload = await svc.verify_token(resp["access_token"])
# 过期抛 E2-AUTH-001；非法/被撤销抛 E2-AUTH-002；EXPIRING 与 VALID 一致放行

# 5. 撤销（登出/客户端吊销）
await svc.invalidate_token(resp["access_token"])
```

接入统一鉴权中间件（让 OAuth2 凭证走同一入口）：

```python
from web_infra.capabilities.security.oauth2 import OAuth2TokenService
from web_infra.infra.web.auth_middleware import AuthMiddleware

app.add_middleware(
    AuthMiddleware,
    token_verifier=oauth2_svc.verify_token,   # 校验器签名 (token) -> payload
    whitelist=("/health", "/docs"),
)
```

> 规范 §6.4：资源服务器校验在统一入口完成，业务禁止自行解析凭证（不要 `jwt.decode` 手撸）。

## 7. 社交登录

### 7.1 SocialLoginService 编排

三方登录统一编排（规范 §6.8 认证域）：`generate_authorize_url`（生成授权跳转 URL，state 由业务生成防 CSRF）→ `login`（换 token → 拉 userinfo → 查绑定）→ `bind` / `unbind`（已登录用户绑定/解绑）。登录成功复用 `JWTUtil` 签发框架自有 JWT（`extra_claims={"login_type": "social"}`），后续鉴权走 AuthMiddleware。

```python
from web_infra.capabilities.security.social import (
    SocialPlatformRegistry, InMemorySocialBindingStore,
    SocialLoginService, DemoSocialPlatform,
)

# 1. 注册平台 + 构建服务（多实例部署把 InMemorySocialBindingStore 换成 Redis/DB 实现）
registry = SocialPlatformRegistry()
registry.register(DemoSocialPlatform())          # provider="demo" 模拟平台（不触网）
service = SocialLoginService(registry, InMemorySocialBindingStore())

# 2. 生成授权 URL（state 业务自行保存，session/缓存）
url = await service.generate_authorize_url("demo", "https://api.example.com/cb", state)

# 3. 回调登录
result = await service.login("demo", code, redirect_uri)
if result.bound:
    return {"access_token": result.access_token, "user_id": result.user_id}
# 未绑定：require_bound=False（默认）返回 bound=False 待绑定信号
return {"need_bind": True, "user_info": result.user_info}

# 4. 绑定（已登录用户）：同一三方账号仅能绑定一个本地用户
await service.bind("demo", code, redirect_uri, user_id="u1001")

# 5. 解绑：非属主解绑抛 PERM_DENIED
await service.unbind("demo", result.user_info.openid, user_id="u1001")
```

错误码语义（登录/绑定链路）：

| 错误码 | 场景 |
| ---- | ---- |
| `E2-AUTH-005`（422） | 三方平台未注册/未配置（`SocialPlatformRegistry` 中取不到 provider） |
| `E2-AUTH-006`（422） | 三方授权码无效或换取凭证失败（平台侧 exchange_token/fetch_userinfo 报错） |
| `E2-AUTH-007`（422） | `login(require_bound=True)` 且三方账号未绑定本地用户 |
| `E2-AUTH-008`（409） | `bind` 时三方账号已被其他用户绑定（同用户重复绑定幂等返回既有绑定） |

### 7.2 微信登录接入

完整实操（实现 `provider="wechat_open"` 的 `WechatSocialPlatform` 适配器 + 三接口 `build_authorize_url`/`exchange_token`/`fetch_userinfo` + 注册装配 + Controller 编排）见 [接入微信登录.md](../接入微信登录.md)。要点提醒：

- 微信 `sns/userinfo` 要求 `openid` 与 `access_token` 匹配，二者由 `exchange_token` 返回并随 `SocialAccessToken` 透传给 `fetch_userinfo`；
- 多实例部署必须将 `InMemorySocialBindingStore` 替换为业务实现的 Redis/DB 版 `SocialBindingStore`（绑定关系跨实例共享），同一三方账号仅能绑定一个本地用户。

## 8. 认证中间件与能力链

### 8.1 启用认证中间件

统一入口鉴权（规范 §6.4：认证校验在统一入口完成，业务模块不直接对接认证中心），配置驱动启用：

```yaml
app:
  web:
    middlewares:
      auth:
        enabled: true          # 默认 false（不引入），需业务显式开启
        whitelist: ["/health", "/health/live", "/health/ready", "/metrics", "/capacity", "/docs", "/redoc", "/openapi.json"]
```

行为（`AuthMiddleware`）：

- 白名单路径（精确或前缀匹配）与 OPTIONS 预检直接放行；
- 其余请求解析 `Authorization: Bearer <token>`，缺 token 返回 401（E2-AUTH-000）；
- 校验失败返回 401（E2-AUTH-001 过期 / E2-AUTH-002 非法或已撤销），不进入业务模块；
- 校验成功（含 EXPIRING 静默刷新信号，同 VALID 放行）注入请求上下文：`user_id`（sub）/ `scope` / `client_id`，业务经 `RequestContext` 取身份，禁止自行解析凭证；
- 中间件顺序约束（Starlette 后声明者在外层先执行）：`trace_id` 必须最后声明（最先执行生成 TraceId），`auth` 次之（随后以 token payload 注入身份，不被外层覆盖），`idempotency` 最内层最后执行（此时身份已就绪）。

### 8.2 JWT 体系与认证能力链

- **能力链**（`CapabilityRegistry`，见 [核心概念](./02-核心概念.md)）：`user`（用户系统，契约能力，业务实现）→ `authn`（认证）→ `authz`（鉴权）→ `pay`（支付）。认证/鉴权能力位于 `web_infra.capabilities.security`，均依赖用户系统；启用支付默认自动带出 鉴权→认证→用户。`app.capabilities.enabled` 默认 `[]`（业务可选能力默认关闭）。
- **工具与能力的边界**：JWT 签发校验（`JWTUtil`）、密码加密（`PasswordEncoder`）等属于**安全工具类**，随核心安装即可导入使用；认证/鉴权**能力**（AuthMiddleware 装配、PermissionGuard 鉴权）依赖用户系统业务实现，默认关闭，由 yml 显式启用。
- **推荐链路**：`AuthMiddleware`（认证，注入 user_id/scope/client_id 到 RequestContext）→ `PermissionGuard.require`（鉴权，按 scope 校验权限点）→ `DataPermissionGuard.check`（数据权限，按 owner_id 防水平越权）→ `PrivacyGuard`（输出脱敏）。

## 9. 错误码速查

| 错误码 | HTTP | 含义 | 抛出点 |
| ---- | ---- | ---- | ---- |
| `E2-AUTH-000` | 401 | 未认证（缺凭证/客户端认证失败） | AuthMiddleware、OAuth2TokenService |
| `E2-AUTH-001` | 401 | 凭证已过期 | AuthMiddleware、OAuth2TokenService |
| `E2-AUTH-002` | 401 | 凭证非法/签名错误/已撤销 | AuthMiddleware、OAuth2TokenService |
| `E2-AUTH-003` | 401 | 凭证即将过期（静默刷新信号，业务不应直接抛） | 常量定义（框架内部按 EXPIRING 放行） |
| `E2-AUTH-004` | 401 | 单点登录被踢 | 常量定义（配合同设备凭证复用语义） |
| `E2-AUTH-005` | 422 | 三方登录平台未注册/未配置 | SocialLoginService |
| `E2-AUTH-006` | 422 | 三方授权码无效或换取凭证失败 | 平台适配器 |
| `E2-AUTH-007` | 422 | 三方账号未绑定本地用户 | SocialLoginService.login(require_bound=True) |
| `E2-AUTH-008` | 409 | 三方账号已被其他用户绑定 | SocialLoginService.bind |
| `E2-PERM-000` | 403 | 无权限 | PermissionGuard / DataPermissionGuard / TenantGuard |

> 全部错误码与常量以 [常量与错误码.md](../常量与错误码.md) 为唯一权威清单；本文仅为安全域子集速查。
