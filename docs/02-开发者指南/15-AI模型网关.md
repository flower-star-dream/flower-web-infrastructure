## 1. 是什么

`web_infra.capabilities.ai` 是框架的「大模型接入层」，按《AI 规范 §2/§17.4》实现：

- **统一出入参**：`ChatRequest` / `ChatResponse` / `ChatStreamChunk` / `EmbeddingRequest` / `EmbeddingResponse` / `Usage`，屏蔽厂商差异，业务只依赖统一结构（规范 §2.2）；
- **供应商 SPI**：`ModelProviderInterface` 抽象 + `ModelProviderRegistry` 注册表 + `ModelProviderFactory` 构建器；未注册的协议一律回落 OpenAI 兼容格式（默认协议，规范 §17.4）；
- **模型配置**：`ModelConfig` 标准化视图（`env:VAR` 安全引用 API Key，规范 AI-7）+ 三种配置来源（yml / 数据库 / 自定义 SPI）+ `ModelConfigManager` 缓存热刷新 + `ModelAutoRegistrar` 自动注册；
- **统一模型网关** `ModelGateway`：场景路由 → 权限校验 → 配额 → 内容审核 → 缓存 → 主备降级 → 指数退避重试 → 并发守卫 → 计费指标，一个入口收敛全部横切关注点；
- **周边组件**：Prompt 模板管理（`prompt/`）、结果缓存（`ai_cache.py`）、内容安全（`rule_based_content_guard.py`）、配额（`quota/`）、计费（`usage_accounting.py`）、上下文窗口截断重试（`context_truncator.py` 等）。

能力开关与完整配置项见 [03-配置参考.md](./03-配置参考.md#7-ai-与大模型appai)，错误码权威清单见 [常量与错误码.md](../常量与错误码.md)。

## 2. 何时用

- 业务需要调用大模型（对话 / 流式对话 / Embedding），希望**不绑定具体厂商 SDK**，后期可换供应商或加备用模型；
- 需要统一的「场景 → 模型」路由与主备降级、调用次数/Token/成本配额、输入输出内容审核、结果缓存、用量计费；
- 只需要**单供应商直连**（无网关横切需求）时，也可绕过网关直接用 `ModelProviderRegistry.get("model_code")` 调用；
- 单机/测试场景无需外部服务即可运行（内存实现开箱即用），生产接入真实模型端点。

## 3. 启用与配置（app.ai.*）

默认关闭，`app.ai.enabled: true` 显式启用。模型清单随 `app.ai.models` 声明（`store.type: yml` 时生效）：

```yaml
app:
  ai:
    enabled: true
    # 模型配置来源：yml（默认）/ db（ai_model_config 表）/ 自定义（ModelConfigStoreRegistry 注册后按名装配）
    store:
      type: yml
    # 模型清单：字段与 ModelConfig 对齐；provider 缺省回落 openai_compatible
    models:
      - model_code: deepseek-chat          # 模型逻辑名（业务代码只引用它）
        model_name: DeepSeek Chat
        provider: openai_compatible
        api_base: https://api.deepseek.com/v1
        api_key: env:LLM_API_KEY           # env: 前缀引用环境变量，禁止明文落盘（AI 规范 AI-7）
        model_id: deepseek-chat            # 厂商侧真实模型 ID（缺省用 model_code）
        max_tokens: 4096
        temperature: 0.0
        top_p: 0.0
        timeout: 120
        is_deterministic: false
        input_price_per_1k: 0.001          # 输入 Token 单价（元/1K），计费用
        output_price_per_1k: 0.002         # 输出 Token 单价（元/1K）
      - model_code: glm-4
        model_name: 智谱 GLM-4
        provider: openai_compatible
        api_base: https://open.bigmodel.cn/api/paas/v4
        api_key: env:ZHIPU_API_KEY
    model_gateway:
      default_scene: chat                  # 无匹配场景时回退；空则抛 E4-AI-001
      routes:
        chat:                              # 场景 -> 主备模型（主失败按顺序降级）
          primary: deepseek-chat
          backups: [glm-4]
    connection_pool:                       # 流式/非流式分池（规范 §5.1，流式池上限须小于非流式池）
      stream_max_connections: 16
      stream_max_keepalive_connections: 16
      sync_max_connections: 64
      sync_max_keepalive_connections: 32
      connect_timeout_seconds: 1.0
      stream_read_timeout_seconds: 30.0
      sync_read_timeout_seconds: 60.0
    quota:                                 # 模型网关级配额（按租户维度，0 表示不限制）
      max_calls: 0
      max_tokens: 0
      max_cost: 0.0
      window_seconds: 3600
```

装配后经 `app.state.ai` 获取网关实例（`create_app` 自动注入连接池与配额；缓存/审核/计费/权限为可选注入，见 §7.4）：

```python
from web_infra import create_app

app = create_app()
gateway = app.state.ai          # ModelGateway 实例（app.ai.enabled=false 时为 None）
```

## 4. 统一出入参

| 结构 | 关键字段 | 说明 |
| ---- | -------- | ---- |
| `ChatRequest` | `model`（模型逻辑名，必填）、`messages`（`list[ChatMessage]`）、`temperature`/`max_tokens`、`stream`、`model_version`（参与缓存 Key）、`idempotency_key`、`ttft_timeout_seconds`/`total_timeout_seconds` | 业务只引用**逻辑名**，不接触厂商 ID |
| `ChatMessage` | `role`（`ChatRole`：system/user/assistant/tool）、`content` | 统一消息 |
| `ChatResponse` | `id`、`model`、`message`、`finish_reason`（`FinishReason`）、`usage` | 非流式响应 |
| `ChatStreamChunk` | `delta`、`finish_reason`、`usage`（流结束时）、`error`（AI-5 流内错误分片错误码） | 流式分片 |
| `EmbeddingRequest` | `model`、`input`（`str \| list[str]`） | 向量化请求 |
| `EmbeddingResponse` | `model`、`embeddings`（`list[list[float]]`）、`usage` | 向量化响应 |
| `Usage` | `prompt_tokens` / `completion_tokens` / `total_tokens` | Token 用量 |
| `FinishReason` | `STOP` / `LENGTH` / `CONTENT_FILTER` / `TOOL_CALLS` / `ERROR` | 结束原因；`get_code()`/`of(code)` 入库存 code |

## 5. 供应商 SPI

### 5.1 ModelProviderInterface

供应商统一抽象（规范 §2.1），业务代码只依赖该接口：

```python
from web_infra.capabilities.ai import ModelProviderInterface

class MyProvider(ModelProviderInterface):
    name: str = "my-llm"                       # 供应商逻辑名（注册表路由键）

    async def chat(self, request: ChatRequest) -> ChatResponse: ...
    def stream_chat(self, request: ChatRequest): ...          # 默认不支持，async generator 覆写
    async def embedding(self, request: EmbeddingRequest) -> EmbeddingResponse: ...  # 默认不支持
```

### 5.2 默认协议：OpenAICompatibleProvider

任何 OpenAI 兼容端点（DeepSeek / 智谱 / 通义 / 私有化部署等）**零代码接入**：`provider: openai_compatible`（或缺省）即按 `api_base/api_key/model_id` 调用 `{api_base}/chat/completions` 与 `{api_base}/embeddings`，支持非流式 / SSE 流式（TTFT 首包超时 + 全量生成超时，规范 §4.1）。一个实例绑定一个 `ModelConfig`，`provider.name = model_code`。

### 5.3 注册：ModelProviderRegistry 与 ModelProviderFactory

- `ModelProviderRegistry`（类级注册表）：`register(provider)` / `get(name)`（未注册快速失败 E4-AI-001）/ `contains` / `names`；
- `ModelProviderFactory`（协议构建器）：`create(config)` 按 `config.provider` 找已注册工厂，未注册回落 `OpenAICompatibleProvider`。

自定义供应商三步接入（yml 里 `provider` 写自定义名即可自动装配）：

```python
from web_infra.capabilities.ai import (
    ModelProviderFactory, ModelConfig, ModelProviderInterface,
)

def build(config: ModelConfig) -> ModelProviderInterface:
    return MyProvider(config)          # 按 ModelConfig 构建供应商实例

ModelProviderFactory.register_factory("my_llm", build)
```

```yaml
# application.yml
app:
  ai:
    models:
      - model_code: my-model
        provider: my_llm               # 已注册的自定义协议
        api_base: http://internal-llm:8000/v1
        api_key: env:INTERNAL_LLM_API_KEY
```

## 6. 模型配置管理

### 6.1 ModelConfig 与 env:VAR 安全引用

`ModelConfig` 为不可变 dataclass，字段：`id / model_name / model_code / provider / api_base / api_key / model_id / max_tokens(4096) / temperature(0.0) / top_p(0.0) / timeout(120) / is_deterministic(False) / stop / input_price_per_1k / output_price_per_1k`。

**API Key 安全（规范 AI-7）**：`api_key` 字段禁止明文落盘。以 `env:ENV_VAR_NAME` 前缀书写（如 `env:LLM_API_KEY`），`resolved_api_key` 属性运行时从环境变量解析；环境变量缺失时原样返回（便于排查），不抛异常。真实密钥放项目根 `.env`（如 `LLM_API_KEY=sk-xxx`），密钥按 ≥90 天周期轮换。

### 6.2 配置来源：ModelConfigStoreInterface 三种来源

```python
@runtime_checkable
class ModelConfigStoreInterface(Protocol):
    async def load(self, model_code: str | None = None) -> ModelConfig | None: ...
    async def load_all(self) -> list[ModelConfig]: ...
```

| 来源 | store.type | 说明 |
| ---- | ---------- | ---- |
| yml（默认） | `yml` | `app.ai.models` 清单，`DictModelConfigStore` 内存实现，启动即注册；内置注册表条目 |
| 数据库 | `db` | `SqlAlchemyModelConfigStore` 读写 `ai_model_config` 表（字段与 `db/init/ddl/002-ai-model-config-init-ddl.sql` 对齐）；数据源跟随 `app.db.type`（mysql 复用数据库组件会话工厂，sqlite 走独立 aiosqlite 引擎）；启动生命周期内经 `register_from_store` 自动注册；`upsert` 幂等写入支持页面化配置；`api_key` 列仅存 `env:VAR` 引用 |
| 自定义 | 任意名 | 配置中心 / Redis 等，经 `ModelConfigStoreRegistry.register(name, factory)` 注册无参工厂后按 `store.type` 装配；未注册的 type 启动期快速失败（ConfigError） |

### 6.3 ModelConfigManager：缓存 + 热刷新

`get_config(model_code)` 优先读缓存（Key `web:common:v1:model_config:{model_code}`，TTL 300s），未命中经 store 加载并回填缓存；`refresh(model_code)` 强制删缓存后重载（模型配置变更后调用即热生效）。业务代码禁止硬编码模型密钥。

### 6.4 ModelAutoRegistrar：自动注册与远程模型拉取

- `register_configs(configs)`：配置清单 → 供应商实例 → SPI 注册表，同 `model_code` 覆盖注册（配置刷新语义）；
- `register_from_store(store)`：从配置来源 SPI 全量加载并同步注册（页面化配置同步）；
- `fetch_remote_models(provider_url, api_key, http_client)`：调用 OpenAI 兼容 `GET {base_url}/models` 动态拉取模型 ID 列表（AI-10 页面化配置能力）；**仅在显式调用时发生网络请求**，失败（网络/非 2xx/结构异常）返回空列表并告警，不阻断手动登记。

## 7. 统一模型网关 ModelGateway

### 7.1 调用时序（chat）

`gateway.chat(request, scene=..., tenant_id=..., user_id=...)` 的完整链路：

```
场景路由 ModelRouter.route(scene)            # 未命中场景回退 default_scene，均未命中抛 E4-AI-001
  → 权限校验 ModelAccessPolicy.require_access # 默认 AllowAll 放行；注入 RBAC 策略后无权限抛 E2-PERM-*
  → 配额检查 QuotaManager.check_and_consume  # 租户维度必查（缺省 no-tenant）；user/scene 维度有值才查
  → 输入内容审核 ContentGuard.check_input     # BLOCK 抛 E4-AI-002（未注入审核器则跳过）
  → AI 缓存命中 _try_cache_hit               # 仅注入 AICache 且非流式确定性场景；命中直接返回（cache_hit 埋点）
  → 幂等键兜底 _ensure_idempotency_key       # 未携带时生成 uuid 并透传，重试复用同一键（规范 §4.2）
  → 主备降级循环（primary + backups 依次尝试）
      每候选模型：
        → 备用模型权限复检（主模型已在入口校验）
        → 连接池客户端注入 _attach_pool_clients（流式/非流式分池，仅首次注入，asyncio.Lock 防竞态）
        → 重试循环（max_retries=2 次）
            → 并发守卫 ConcurrencyGuard.acquire  # 执行槽 + 有界排队，超时抛 E1-RATE-000
            → provider.chat(effective_request)
            → retryable（E3-THIRD-*）指数退避 base*2^attempt（1s、2s）后重试
            → 内容审核拒绝（E4-AI-002）直接抛出，不重试不降级
        → 输出内容审核 check_output            # BLOCK 抛 E4-AI-002
        → 计费与指标打点（_record_success：成功/降级 outcome、耗时、Token、成本）
        → Token 配额累计 consume_usage         # 仅累计不增加调用次数，超限由下次入口拦截
        → 主模型成功才写缓存（降级响应不落缓存）
  → 全部候选失败 → 抛 E3-THIRD-001（模型供应商服务不可用）
```

### 7.2 流式语义（stream_chat）

- **TTFT 计时**：首个分片产出时埋点 `record_ai_ttft`；供应商侧施加 TTFT 首包超时与全量生成超时（请求字段缺省回退模型配置 `timeout`，超时抛 E3-THIRD-002）；
- **未产出分片前**：retryable 异常指数退避重试，仍失败降级到备用模型（与 chat 一致）；
- **已产出分片后（AI-5）**：异常不再整体重试/降级，而是产出**统一流内错误分片** `ChatStreamChunk(error=<错误码>, finish_reason=ERROR)` 终止；调用方消费到 `error` 分片即知中断原因（`WebInfraException` 用其错误码，其他异常统一 E4-AI-004）；
- **输出审核**：每个分片返回前累计检查，BLOCK 立即中断抛 E4-AI-002；
- 流结束时（`finish_reason` 与 `usage` 同时非空）打点耗时/Token/成本并累计 Token 配额。

### 7.3 embed

`gateway.embed(request, ...)`：走场景路由（无降级链）、入口权限校验与配额检查，取主模型直接调用。

### 7.4 可选注入组件

`create_app` 装配网关时只注入连接池与配额；以下组件**可选**，业务按需自行组装（构造 `ModelGateway` 传参）：

| 组件 | 参数 | 说明 |
| ---- | ---- | ---- |
| 内容审核 | `content_guard` | `ContentGuardInterface`，默认不启用 |
| 模型权限 | `access_policy` | `ModelAccessPolicy`，默认 `AllowAllModelAccessPolicy` 放行 |
| AI 缓存 | `ai_cache` | `AICache`，注入后非流式确定性 chat 缓存优先 |
| 计费 | `usage_accounting` | `UsageAccounting`，打点成本与用量聚合 |
| 连接池 | `pool_manager` | `ConnectionPoolManager`（create_app 已注入） |
| 配额 | `quota_manager` | `QuotaManager`（create_app 已注入，quota 全 0 时为 None） |
| 并发 | `default_concurrency` | 单供应商并发上限，默认 8（`ConcurrencyGuard` 按模型懒创建） |

### 7.5 调用示例

```python
from web_infra.capabilities.ai import (
    ChatRequest, ChatMessage, ChatRole, AICache,
    RuleBasedContentGuard, ModelGateway,
)
from web_infra.capabilities.ai.model_gateway import ModelRouter, RouteEntry

router = ModelRouter(
    {"chat": RouteEntry(primary="deepseek-chat", backups=("glm-4",))},
    default_scene="chat",
)
gateway = ModelGateway(
    router,
    content_guard=RuleBasedContentGuard(),   # 可选：输入/输出内容审核
    ai_cache=AICache(),                      # 可选：结果缓存（生产注入 RedisCacheBackend）
)

# 非流式对话
resp = await gateway.chat(
    ChatRequest(
        model="deepseek-chat",
        messages=[ChatMessage(role=ChatRole.USER, content="你好，请介绍框架")],
        model_version="2026-08-01",          # 参与缓存 Key，版本变更缓存自然失效
    ),
    scene="chat",
    tenant_id="t1",
    user_id="u1",
)
print(resp.message.content, resp.usage.total_tokens, resp.finish_reason)

# 流式对话
async for chunk in gateway.stream_chat(
    ChatRequest(model="deepseek-chat", messages=[ChatMessage(role=ChatRole.USER, content="写一首诗")], stream=True),
    scene="chat",
):
    if chunk.error:                          # AI-5 流内错误分片
        print("流中断，错误码:", chunk.error)
        break
    print(chunk.delta, end="")
```

## 8. Prompt 管理

| 组件 | 说明 |
| ---- | ---- |
| `PromptTemplate` | `key`（唯一键）+ `version`（默认 `1.0.0`）+ `content`（`{var}` 占位符）；`fingerprint = "key:version"`，模板版本变更应同步失效 AI 缓存（作为缓存 Key 组成要素） |
| `PromptTemplateStoreInterface` | 模板存取 SPI（`load(key, version)` / `save`）；默认 `InMemoryPromptTemplateStore`，多实例部署替换为数据库实现 |
| `PromptTemplateFiller` | 占位符填充：`extract_variables` 提取 `{var}`（不匹配 `{{ jinja }}` 或 `{obj.prop}`）；`fill` 先**哨兵保护变量值中嵌套的 `{xxx}`**（防二次替换误伤），再替换、还原、检测未替换占位符（`raise_on_unfilled` 时抛 ValueError） |
| `PromptAssembler` | 注入防护（规范 §7.2）：系统提示与用户输入按消息角色隔离（用户输入不可覆盖系统提示）；系统提示模板经参数化填充禁止裸拼接；`validate_tools` 工具调用白名单校验，白名单外抛 E1-PARAM-000 |

```python
from web_infra.capabilities.ai import PromptTemplate, PromptTemplateFiller, PromptAssembler

filler = PromptTemplateFiller()
# 变量值中嵌套 {xxx} 不会被二次替换
text = filler.fill("报告：{topic}（参考 {ref}）", {"topic": "AI 规范 {AI-1}", "ref": "§2"})
assert "{AI-1}" in text                       # 哨兵保护生效，未被误替换

assembler = PromptAssembler()
messages = assembler.assemble_with_template(
    template="你是{role}，请用{lang}回答",
    variables={"role": "领域专家", "lang": "中文"},
    user_input="用户原始输入",                  # 置于 USER 消息，与系统提示隔离
)
```

## 9. AI 缓存

`AICache` 复用 `CacheBackendInterface`（默认 `MemoryCacheBackend`，多实例注入 `RedisCacheBackend`）。**Key 构建**（规范 §8，禁用 MD5）：

```text
material = JSON(prompt, model_code, model_version, tenant_id, user_id, params)   # sort_keys + 紧凑序列化
digest   = SHA-256(material)[:32]
key      = {key_prefix}{tenant_id}:{digest}      # 前缀默认 web:ai:v1:cache:
```

- `model_version` 参与 Key——模型版本变更缓存自然失效；
- `tenant_id` 进明文前缀实现租户隔离，`user_id` 参与哈希防跨用户语义串扰（不进明文，避免 Key 过长）；
- 网关侧仅在**主模型成功**后写缓存（降级响应不落缓存），命中/未命中分别埋点 `cache_hit` / `cache_miss`。

## 10. 内容安全

| 组件 | 说明 |
| ---- | ---- |
| `ContentGuardInterface` | SPI：`check_input`（进模型前）/ `check_output`（返回用户前）；可整体替换为第三方审核服务 |
| `GuardAction` | `BLOCK` / `WARN` / `PASS`（枚举 `get_code`/`of`） |
| `GuardResult` | `action` + `rules`（命中规则名）+ `message`；`blocked` / `passed` 便捷属性 |
| `RuleBasedContentGuard` | 默认实现，关键词正则：输入命中阻断规则即 BLOCK；输出按 危险（阻断）/ 敏感（警告）分级。内置规则可用参数合并覆盖，也可 `block_rules`/`warn_rules` 自定义 |

**内置规则**：阻断——`violence`（枪支|弹药|爆炸物|砍人|杀人方法）、`dangerous`（制造.*毒品|自杀方法|自残）；警告——`sensitive`（政治敏感|色情|赌博网站）、`medical_self_medication`（自行服药|停用药物|代替医生）。

网关接入后，输入/输出命中 BLOCK 抛 **E4-AI-002**（输出内容未通过安全审核），不重试不降级。

## 11. 配额

`QuotaManager`（默认内存 `InMemoryQuotaStore`，多实例注入 Redis 实现 `QuotaStoreInterface`）按**三维度**限流（规范 §5.3）：`tenant` / `user` / `scene`。

- `check_and_consume(scope, scope_value, tokens=0, cost=0.0)`：**先累计再校验**（窗口内边缘超额计入本次，防绕过边界）；调用次数 / Token 超限抛 `E1-RATE-000`，成本超限抛 `E4-AI-005`；
- `consume_usage(...)`：仅累计 Token/成本（**不重复计调用次数**），调用成功后按实际用量调用；本次调用已完成、超限不抛错仅告警，由下一次入口 `check_and_consume` 基于累计值拦截；
- `QuotaConfig`：`max_calls` / `max_tokens` / `max_cost`（0 不限）+ `window_seconds`（默认 3600）。

网关入口统一 `_check_quota`（租户必查，user/scene 有值才查），成功后 `_consume_usage` 按实际用量累计——chat / stream_chat / embed 三入口一致（AI-2）。

## 12. 计费与用量

`UsageAccounting` 成本计算：`cost = prompt_tokens/1000*input_price + completion_tokens/1000*output_price`（四舍五入 6 位），默认出口为结构化日志 + 内存聚合；配置 `UsageRecordStoreInterface` 后异步持久化（无事件循环时降级日志提示）。

- `record(usage, model_code, provider=..., tenant_id=..., scene=..., input_price_per_1k=..., output_price_per_1k=...)`：返回 `UsageRecord`（含 `timestamp/model_code/provider/tenant_id/scene/各 Token 数/cost`）；
- `record_from_config(usage, config, tenant_id=..., scene=...)`：单价取自 `ModelConfig.input_price_per_1k / output_price_per_1k`，与模型配置联动；
- `aggregate(group_by=("model_code",))`：按 model_code / provider / tenant_id / scene 单一维度查询聚合。

网关侧 `_record_cost` 透传 `provider / tenant_id / scene` 聚合维度（AI-3），成本 > 0 时埋点 `record_ai_cost`（网关不持有单价时成本为 0，由业务侧按模型配置核算）。

## 13. 上下文窗口处理

- `ContextTruncator`：基于 `TokenCounter` 精确计数，`truncate(text, budget_tokens)` 按预算保留前缀——先按比例粗裁再递减校准；
- `ContextWindowErrorParser.parse(error)`：解析供应商"上下文超长"错误（OpenAI 风格 `maximum context length is X tokens` / `you requested X tokens` / 通用 `context length exceeded`），返回所需 Token 预算（>0 具体值 / 0 表示需截断但未知具体量 / `None` 表示非超长错误）；
- `ContextWindowRetryPolicy`：`run(call, context_factory, model_code)` 循环 `max_attempts`（默认 2）次：每次用预算重建上下文（首次 `None`）→ 调用 → 捕获超长错误解析预算 → 有明确超出量按该量截断、否则按原预算 50% 裁剪（`_DEFAULT_BUDGET_RATIO=0.5`）→ 重试；耗尽或非超长错误抛原异常。

## 15. 常见坑

- **`app.state.ai` 为 None**：`app.ai.enabled` 未开。开之后仍需确认 `app.ai.models` 或 `store.type=db` 已提供至少一个模型，否则调用时抛 E4-AI-001；
- **场景路由抛 E4-AI-001**：`routes` 未配置该 `scene` 且 `default_scene` 为空。路由键是 `scene`（业务调用传的 `scene=`），不是模型名；
- **API Key 无效/落盘**：`api_key` 写 `env:LLM_API_KEY`，值放 `.env`；`resolved_api_key` 解析不到时**原样返回** `env:` 前缀串（不抛异常），表现是供应商 401——先查环境变量是否注入；
- **流式中途异常**：AI-5 语义是产出 `error` 分片（不是抛异常），调用方循环里必须检查 `chunk.error`；只有**未产出分片前**的失败才抛异常；
- **缓存命中旧内容**：改了 Prompt 模板后应递增 `model_version` 或调用 `ModelConfigManager.refresh`——`model_version` 参与缓存 Key；
- **内存配额/缓存/连接池是进程内状态**（`@Stateful`）：多实例部署必须换 Redis 共享实现（`QuotaStoreInterface` / `RedisCacheBackend`），否则各实例配额独立计数、缓存不共享；
- **`create_app` 未自动注入内容审核/缓存/计费/权限策略**：这些是可选横切组件，需要时自行组装 `ModelGateway`（见 §7.4）。
