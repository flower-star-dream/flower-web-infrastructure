# 通用状态机

> 面向业务的状态机能力：状态/事件枚举基类 + 路由抽象 + 引擎 SPI 与默认实现 + 注册表，引擎只做「流转合法性校验 + 事件分发」，不触碰持久层（持久化由路由处理器自行完成）。

## 1. 是什么

状态机能力（`web_infra.capabilities.state_machine`）解决业务代码中**状态流转校验散落各处**的问题：业务侧只需要声明「状态 × 事件 → 目标状态」的合法流转表与「事件 → 处理器」两张表，引擎统一负责：

- **流转合法性校验**：当前状态 + 事件组合不在合法流转表中即抛 `E4-STATE-000`；
- **事件分发**：按事件找到注册的处理器并执行，返回目标状态。

**设计定位（重要）**：引擎**不触碰持久层**——状态翻转计算发生在处理器内，处理器自行负责把新状态持久化（写库/更新缓存）。这样引擎保持无状态、可测试、与任何持久化方案解耦。若你还需要「持久化由引擎接管」的强状态机，本能力不适合，可基于第三方库（如 transitions）自行实现。

模块结构：

| 文件 | 职责 |
| ---- | ---- |
| `base_state.py` | `BaseState` 状态枚举基类 |
| `base_event.py` | `BaseEvent` 事件枚举基类 |
| `base_status.py` | 开箱即用的启停状态机（`BaseStatus` / `StartStopEvent` / `BaseStatusRouter`） |
| `state_route_params.py` | 路由参数容器 `StateRouteParams` |
| `state_router.py` | 路由抽象基类 `StateRouter`（两张声明表 + `route` 统一分发） |
| `state_machine_engine.py` | 引擎 SPI（Protocol：`fire` / `fire_async`） |
| `state_machine.py` | 默认引擎实现 `StateMachine` |
| `state_machine_registry.py` | 注册表 `StateMachineRegistry`（三种注册方式 + 引擎实例缓存） |
| `state_machine_error.py` | 错误码 `E4-STATE-*`（模块导入时自动登记到 `ErrorCodeRegistry`） |

## 2. 核心组件

### 2.1 状态/事件枚举基类 BaseState / BaseEvent

业务侧按「成员 = (业务码, 中文名)」声明枚举，继承基类即获得三个方法：

- `get_code()`：返回入库业务码（规范要求**入库存 code，禁存枚举名**）；
- `description`：返回中文名（引擎报错信息、日志可读标签用）；
- `of(code)`：按业务码反查成员，未知码抛 `E4-STATE-004`（UNKNOWN_STATE）。

```python
from web_infra.capabilities.state_machine import BaseState, BaseEvent

class OrderStatus(BaseState):
    CREATED = (0, "已创建")
    PAID = (1, "已支付")
    CANCELLED = (2, "已取消")

class OrderEvent(BaseEvent):
    PAY = (1, "支付")
    CANCEL = (2, "取消")

OrderStatus.PAID.get_code()        # 1
OrderStatus.PAID.description       # "已支付"
OrderStatus.of(1)                  # <OrderStatus.PAID>
OrderStatus.of(99)                 # 抛 E4-STATE-004（未知的状态码/事件码）
```

注意：`BaseState` / `BaseEvent` 是**推荐便捷基类，非强制**——引擎不要求状态/事件必须继承它们（`StateRouter` 的泛型 S/E 是任意 hashable 值，支持扩展或动态状态值），但继承后报错信息更可读（引擎优先取 `description` 作标签）。

### 2.2 路由参数容器 StateRouteParams

处理器需要上下文（实体、操作人、事务会话等）时，通过参数容器传递，支持任意数量/任意类型：

```python
from web_infra.capabilities.state_machine import StateRouteParams

params = StateRouteParams.create() \
    .add_param("entity", order) \
    .add_param("operator", "admin")          # add_param 返回自身，支持链式

params.get_param("entity")                   # order
params.get_param("not_exist")                # None
params.get_param("not_exist", default=1)     # 1
params.contains("operator")                  # True
params.size()                                # 2
```

### 2.3 路由抽象 StateRouter

业务侧继承 `StateRouter[S, E, D]`（S=状态类型，E=事件类型，D=数据实体类型），实现两张声明表，`route` 为统一分发入口：

```python
from typing import Callable
from web_infra.capabilities.state_machine import StateRouter, StateRouteParams

class OrderRouter(StateRouter[OrderStatus, OrderEvent, Order]):
    # 表 1：合法流转表（状态 × 事件 → 目标状态），引擎仅用于流转合法性校验
    def get_state_event_target_config(self) -> dict[OrderStatus, dict[OrderEvent, OrderStatus]]:
        return {
            OrderStatus.CREATED: {
                OrderEvent.PAY: OrderStatus.PAID,
                OrderEvent.CANCEL: OrderStatus.CANCELLED,
            },
            OrderStatus.PAID: {OrderEvent.CANCEL: OrderStatus.CANCELLED},
        }

    # 表 2：事件 → 业务处理器（签名 handler(current_state, params) -> 目标状态）
    def get_event_dispatcher(self) -> dict[OrderEvent, Callable[[OrderStatus, StateRouteParams], OrderStatus]]:
        return {
            OrderEvent.PAY: self._pay,
            OrderEvent.CANCEL: self._cancel,
        }

    def _pay(self, current_state: OrderStatus, params: StateRouteParams) -> OrderStatus:
        order = params.get_param("entity")
        order.status = OrderStatus.PAID          # 状态翻转（持久化由处理器自行完成）
        # ... 写数据库、发消息等业务动作
        return OrderStatus.PAID
```

要点：

- **处理器签名统一**为 `handler(current_state, params)`，返回目标状态；同一事件可按当前状态分叉（处理器内部判断）；
- **持久化由处理器自行完成**（引擎不触碰持久层）；
- `route(event, current_state, params)` 统一分发：事件未注册处理器抛 `E4-STATE-003`（EVENT_ROUTER_ERROR）；
- 处理器可以是普通函数或 **async 函数**（async 处理器需走 `fire_async` 触发）。

### 2.4 默认引擎 StateMachine

默认引擎实现 `StateMachineEngine` SPI，**只做流转合法性校验 + 事件分发**，校验顺序：

```
状态非空（E4-STATE-001）→ 参数非空（E4-STATE-002）→ 组合表合法性（E4-STATE-000）→ 事件分发（route）→ 目标状态非空（E4-STATE-001）
```

```python
from web_infra.capabilities.state_machine import StateMachine, StateRouteParams

machine = StateMachine(OrderRouter())

# 同步触发（处理器为普通函数）
target = machine.fire(
    OrderStatus.CREATED, OrderEvent.PAY,
    StateRouteParams.create().add_param("entity", order),
)
assert target == OrderStatus.PAID

# 非法流转：PAID 状态收到 PAY 事件（合法表未声明该组合）→ E4-STATE-000
machine.fire(OrderStatus.PAID, OrderEvent.PAY,
             StateRouteParams.create().add_param("entity", order))  # 抛 ILLEGAL_STATE_TRANSITION

# 异步触发（处理器为 async 函数时使用；同步处理器也可走 fire_async）
target = await machine.fire_async(OrderStatus.CREATED, OrderEvent.PAY,
                                  StateRouteParams.create().add_param("entity", order))
```

注意：`fire` 遇到 async 处理器会抛 `TypeError` 提示改用 `fire_async`（同时关闭协程避免 ResourceWarning）；`fire_async` 对同步/异步处理器均兼容。`current_state` / `params` 传 `None` 分别抛 `E4-STATE-001` / `E4-STATE-002`。

### 2.5 注册表 StateMachineRegistry

注册表按 **(状态类, 事件类, 数据类)** 三元组注册与获取引擎，引擎实例进程内缓存复用，提供**三种注册方式**：

```python
from web_infra.capabilities.state_machine import StateMachineRegistry
```

**方式一：`@register` 类装饰器**（路由类需无参构造，`get` 时惰性实例化并做静态校验）：

```python
@StateMachineRegistry.register
class OrderRouter(StateRouter[OrderStatus, OrderEvent, Order]):
    ...  # 同上
```

**方式二：`register_instance` 实例注册**（路由需要构造注入时使用，立即执行静态校验）：

```python
router = OrderRouter(dep_service)              # 构造注入
StateMachineRegistry.register_instance(router)
```

**方式三：`register_engine_factory` 自定义引擎 SPI**（基于第三方状态机库实现 `StateMachineEngine` 协议后替换默认引擎，须在 `get` 之前调用）：

```python
from web_infra.capabilities.state_machine import StateMachineEngine

class MyEngine(StateMachineEngine):
    def fire(self, current_state, event, params=None): ...
    async def fire_async(self, current_state, event, params=None): ...

StateMachineRegistry.register_engine_factory(
    OrderStatus, OrderEvent, Order, lambda: MyEngine(),
)
```

获取引擎（未注册抛 `KeyError`；同 key 缓存复用；`get` 内部做双重检查锁定，并发首次 `get` 只构建一次）：

```python
engine = StateMachineRegistry.get(OrderStatus, OrderEvent, Order)
target = await engine.fire_async(OrderStatus.CREATED, OrderEvent.PAY, params)
```

**构建期静态校验（P0）**：`get` / `register_instance` 时校验「合法流转表声明的事件均已在 dispatcher 注册处理器」，只声明无处理器的事件直接抛 `ValueError`（启动即暴露配置错误，而不是运行到才炸）。

**key 推导**：路由类须直接继承 `StateRouter[S, E, D]` 泛型基类（3 个泛型参数），否则 `TypeError`。

## 3. 何时用

| 场景 | 建议 |
| ---- | ---- |
| 订单/审批/工单等**有明确状态集与事件集**的业务流转 | 使用本能力：声明两张表 + 处理器，引擎统一校验与分发 |
| 仅需要「启用/禁用」互转 | 直接用开箱即用的启停状态机（见 §4），无需自定义路由 |
| 已基于 transitions 等第三方库的存量系统 | 实现 `StateMachineEngine` 协议经 `register_engine_factory` 接入，业务代码无感 |
| 状态集小、流转简单（2~3 个状态） | 可不引入状态机，if/elif 即可；状态机价值在于流转规则复杂/散落多处时收敛为一处 |

## 4. 开箱即用：基础启停状态机

无需任何自定义，直接使用启停互转：实体 `status` 字段在 `ENABLE` 与 `DISABLE` 之间翻转，`params` 需携带 `key="entity"` 的实体（须有 `status` 字段，值为 `BaseStatus`）。

```python
from web_infra.capabilities.state_machine import (
    BaseStatus, StartStopEvent, BaseStatusRouter,
    StateRouteParams, StateMachineRegistry,
)

# 业务实体（演示用；status 字段值为 BaseStatus）
class Config:
    def __init__(self):
        self.status = BaseStatus.DISABLE

entity = Config()
params = StateRouteParams.create().add_param("entity", entity)

# 注册并获取引擎（key = (BaseStatus, StartStopEvent, 数据类)）
@StateMachineRegistry.register
class ConfigStatusRouter(BaseStatusRouter[Config]):
    pass

engine = StateMachineRegistry.get(BaseStatus, StartStopEvent, Config)
target = engine.fire(BaseStatus.DISABLE, StartStopEvent.START_OR_STOP, params)
# target == BaseStatus.ENABLE，且 entity.status 已翻转为 ENABLE（处理器内完成翻转与持久化）

# params 缺 entity → E4-STATE-002
engine.fire(BaseStatus.ENABLE, StartStopEvent.START_OR_STOP, StateRouteParams.create())
```

## 5. 错误码表

状态机错误码域为 `E4-STATE`（HTTP 422，业务域 WARNING，模块导入时自动登记到 `ErrorCodeRegistry`）：

| 错误码 | 常量名 | 含义 | 触发场景 |
| ------ | ------ | ---- | ---- |
| E4-STATE-000 | `ILLEGAL_STATE_TRANSITION` | 非法的状态流转 | 当前状态 + 事件组合不在合法流转表 |
| E4-STATE-001 | `EMPTY_STATE` | 状态不能为空 | `fire` 传 `current_state=None`，或处理器返回 `None` |
| E4-STATE-002 | `EMPTY_PARAMETER` | 状态路由参数不能为空 | `fire` 传 `params=None`，或处理器要求但 params 缺参数（如启停路由缺 entity） |
| E4-STATE-003 | `EVENT_ROUTER_ERROR` | 事件未注册路由处理器 | `route` 分发时事件不在 dispatcher 中 |
| E4-STATE-004 | `UNKNOWN_STATE` | 未知的状态码/事件码 | `BaseState.of` / `BaseEvent.of` 反查不到 |

用法与框架错误码一致：`raise StateMachineErrorCode.ILLEGAL_STATE_TRANSITION.to_exception(message="...")`。

## 6. 完整业务示例：订单状态机

以订单为例演示完整接入：状态翻转 + 持久化（处理器自行完成）+ 通过注册表获取引擎。

```python
from typing import Callable
from web_infra.capabilities.state_machine import (
    BaseState, BaseEvent, StateRouter, StateRouteParams,
    StateMachineRegistry, StateMachine,
)

# 1. 状态与事件（继承基类，code 入库）
class OrderStatus(BaseState):
    CREATED = (0, "已创建")
    PAID = (1, "已支付")
    SHIPPED = (2, "已发货")
    COMPLETED = (3, "已完成")
    CANCELLED = (4, "已取消")

class OrderEvent(BaseEvent):
    PAY = (1, "支付")
    SHIP = (2, "发货")
    COMPLETE = (3, "完成")
    CANCEL = (4, "取消")

# 2. 业务实体（演示；生产对应订单表模型）
class Order:
    def __init__(self, out_trade_no: str):
        self.out_trade_no = out_trade_no
        self.status = OrderStatus.CREATED

# 3. 路由：两张声明表 + 处理器（持久化由处理器自行完成）
@StateMachineRegistry.register
class OrderRouter(StateRouter[OrderStatus, OrderEvent, Order]):
    def get_state_event_target_config(self) -> dict[OrderStatus, dict[OrderEvent, OrderStatus]]:
        return {
            OrderStatus.CREATED: {
                OrderEvent.PAY: OrderStatus.PAID,
                OrderEvent.CANCEL: OrderStatus.CANCELLED,
            },
            OrderStatus.PAID: {
                OrderEvent.SHIP: OrderStatus.SHIPPED,
                OrderEvent.CANCEL: OrderStatus.CANCELLED,   # 未发货可取消（退款）
            },
            OrderStatus.SHIPPED: {OrderEvent.COMPLETE: OrderStatus.COMPLETED},
        }

    def get_event_dispatcher(self) -> dict[OrderEvent, Callable[[OrderStatus, StateRouteParams], OrderStatus]]:
        return {
            OrderEvent.PAY: self._pay,
            OrderEvent.SHIP: self._ship,
            OrderEvent.COMPLETE: self._complete,
            OrderEvent.CANCEL: self._cancel,
        }

    def _pay(self, current: OrderStatus, params: StateRouteParams) -> OrderStatus:
        order = params.get_param("entity")
        order.status = OrderStatus.PAID
        self._persist(order)                     # 处理器内持久化（示例：写库）
        return OrderStatus.PAID

    def _ship(self, current: OrderStatus, params: StateRouteParams) -> OrderStatus:
        order = params.get_param("entity")
        order.status = OrderStatus.SHIPPED
        self._persist(order)
        return OrderStatus.SHIPPED

    def _complete(self, current: OrderStatus, params: StateRouteParams) -> OrderStatus:
        order = params.get_param("entity")
        order.status = OrderStatus.COMPLETED
        self._persist(order)
        return OrderStatus.COMPLETED

    def _cancel(self, current: OrderStatus, params: StateRouteParams) -> OrderStatus:
        order = params.get_param("entity")
        order.status = OrderStatus.CANCELLED
        self._persist(order)
        return OrderStatus.CANCELLED

    def _persist(self, order: Order) -> None:
        # 业务实现：UPDATE orders SET status = <order.status.get_code()> WHERE out_trade_no = ...
        pass

# 4. 业务侧使用：获取引擎并触发流转
async def pay_order(order: Order) -> None:
    engine = StateMachineRegistry.get(OrderStatus, OrderEvent, Order)
    params = StateRouteParams.create().add_param("entity", order)
    target = await engine.fire_async(order.status, OrderEvent.PAY, params)
    assert target == OrderStatus.PAID

order = Order("O202608180001")
await pay_order(order)

# 非法流转：COMPLETED（终态）收到 CANCEL → E4-STATE-000
try:
    await StateMachineRegistry.get(OrderStatus, OrderEvent, Order).fire_async(
        OrderStatus.COMPLETED, OrderEvent.CANCEL,
        StateRouteParams.create().add_param("entity", order),
    )
except Exception as exc:
    assert exc.code == "E4-STATE-000"   # 终态不可回退由合法流转表保证
```

不经过注册表也可以直接构造引擎：`StateMachine(OrderRouter())`（路由无注入依赖时等价）。

## 7. 常见坑

- **`fire` 抛 TypeError "同步 fire 不能处理 async 处理器"**：处理器是 async 函数，改用 `fire_async`（对同步/异步处理器都兼容）。
- **状态/事件忘了 `get_code()`，直接存枚举名**：规范要求入库存 code（`get_code()`），反查用 `of(code)`；存枚举名会导致跨语言/跨版本不兼容。
- **`get` 报 KeyError "未注册的状态机"**：未注册或 key 不匹配。key 是 (状态类, 事件类, 数据类) 三元组，注意**数据类必须与注册时一致**（如 `Order` 与 `OrderEntity` 是不同 key）。
- **构建期 `ValueError: 组合表声明的事件未在 dispatcher 注册处理器`**：合法流转表里声明了事件但 `get_event_dispatcher` 没注册对应处理器（或反之）。两张表要一一对应。
- **`TypeError: 未声明 StateRouter[状态, 事件, 数据] 泛型`**：路由类必须直接继承 `StateRouter[S, E, D]` 且恰好 3 个泛型参数。
- **依赖注入的路由用 `@register` 装饰器**：装饰器注册的是类，`get` 时无参实例化——需要构造注入时改用 `register_instance`（立即静态校验）。
- **引擎不持久化**：别忘了在处理器里写库。引擎返回目标状态但不会替你更新数据库，这是设计使然（见 §1）。
