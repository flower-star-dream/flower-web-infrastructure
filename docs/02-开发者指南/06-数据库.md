## 1. 是什么

`web_infra.capabilities.db` 是框架的数据访问层（源码见 `src/web_infra/capabilities/db/`），围绕规范 §10（数据访问）与 §14.1（连接池）提供：

| 组件 | 职责 |
| ---- | ---- |
| `DatabaseSessionInterface` | 通用会话契约：`execute` / `query_one` / `query_all` / `commit` / `rollback` / `close`，SQL 用命名参数，屏蔽 MySQL / PostgreSQL / SQLite 驱动差异 |
| `DatabaseFactoryInterface` | 通用工厂契约：`create_session` / `session` / `close` / `health_check`（SPI 扩展点） |
| `MySQLDatabase`（默认） | SQLAlchemy 2.x + aiomysql 的异步实现：通用会话 + ORM 会话 + 读写分离 + 长事务监控 |
| `SqliteSessionFactory` / `SqliteSession` | sqlite3 同步参考实现（轻量 / 测试场景）；连接参数走 `DatabaseConfig`（`url` / `max_pool_size` / `min_idle` / `connect_timeout` / `socket_timeout` / `leak_detection_threshold`） |
| `MongoDatabase` | Beanie + PyMongo 的文档数据库默认实现（另见 [SPI-Extensions.md §4.4-4.6](../SPI-Extensions.md#44-mongosessioninterface--mongodb-通用会话接口)） |
| `RedisConfig` | Redis 本质为数据库，故其异步连接管理归入 db 模块（缓存后端复用，见 [07-缓存](./07-缓存.md)） |
| `DatabaseRegistry` | 按 `app.db.type` 装配数据库工厂的注册表（内置 `mysql` / `sqlite`） |

**何时用**：业务读写 MySQL / SQLite / MongoDB；系统需要多数据源、租户独立库、读写分离；需要把 PostgreSQL 等新数据库接入 `create_app`。

> 安装：MySQL/SQLite 需 `pip install "flower-web-infrastructure[mysql]"`，MongoDB 需 `[mongo]`，Redis 需 `[redis]`（均为延迟导入，最小安装下 `import web_infra` 不受影响，见 [使用说明.md §1.3](../使用说明.md#13-按需追加可选能力)）。

## 2. 快速开始

最小单体模板（`application.yml`）：

```yaml
app:
  db:
    type: mysql                # mysql（默认）/ sqlite / 自定义（见 §12）
    mysql:
      host: 127.0.0.1
      port: 3306
      database: demo
      username: ${APP_DB_MYSQL_USERNAME:root}
      password: ${APP_DB_MYSQL_PASSWORD:}
```

框架装配后经 `app.state.db` 访问。业务代码只写业务逻辑，不碰 `try/finally`：

```python
from web_infra import create_app

app = create_app()

@app.get("/orders")
async def list_orders():
    db = app.state.db
    async with db.session() as session:            # 通用文本 SQL 会话
        rows = await session.query_all(
            "SELECT * FROM t_order WHERE status = :status ORDER BY id DESC",
            {"status": 1},
        )
    return {"orders": rows}
```

ORM 模型查询用 `orm_session()`（见下节），模型继承 `Base`（`from web_infra.capabilities.db import Base`，来自 `mysql_base.py`，惰性导出——仅在访问时导入 SQLAlchemy，最小安装 `import web_infra` 不触发）。

## 3. 会话生命周期：session() / orm_session()

`SessionScopeMixin` 提供统一的 `session()` 上下文管理器（`MySQLDatabase` / `SqliteSessionFactory` / `MongoDatabase` 均实现）：

```
进入 → 创建会话 → 业务代码 → 退出时 commit（异常则 rollback）→ close 释放连接
```

**`session()`（通用会话，文本 SQL）**：

```python
from web_infra.capabilities.db import DatabaseSessionInterface

async with db.session() as session:            # type: DatabaseSessionInterface
    await session.execute(
        "INSERT INTO t_order (order_no, status) VALUES (:order_no, :status)",
        {"order_no": "SO20260818001", "status": 1},
    )
    row = await session.query_one(
        "SELECT * FROM t_order WHERE order_no = :order_no", {"order_no": "SO20260818001"}
    )
# 退出自动提交；上方任何一步抛异常则整体回滚
```

**`orm_session()`（SQLAlchemy 原生 AsyncSession，ORM 模型查询）**：

```python
from sqlalchemy import select
from web_infra.capabilities.db import Base  # 声明式基类（惰性导入）

class Order(Base):
    __tablename__ = "t_order"
    # ... 业务字段

async with db.orm_session() as session:
    order = (await session.execute(select(Order).where(Order.order_no == "SO1"))).scalar_one()
    order.status = 2
# 退出自动 commit + close
```

要点：

- 进入/退出全由框架管理，业务**禁止**裸获取连接（规范 §10.6）。
- `MySQLDatabase.orm_session` 额外做**长事务审计**：事务耗时超过 `long_transaction_threshold_seconds`（默认 5.0s）记 warning 日志并递增 `db_long_transaction_total{datasource}` 指标，仅告警不阻断。
- 长耗时外部调用（LLM 等）期间想归还连接：用 `connection_released` 上下文管理器（`session_utils.py`）：

```python
from web_infra.capabilities.db import connection_released

async with db.orm_session() as session:
    order = (await session.execute(select(Order))).scalar_one()
    async with connection_released(session):        # 结束当前事务归还连接
        answer = await model.ainvoke(messages)      # 长耗时期间不持有连接
    order.status = 3                                # 会话仍可继续执行 SQL
```

### 3.1 事务传播（REQUIRED / REQUIRES_NEW / NESTED）

默认 `REQUIRED`：已有活动事务则复用外层（内层不提交/关闭，由最外层统一提交）；无外层则新建。
对齐 Spring 语义，跨方法自动共享事务（ContextVar 事务栈，asyncio 场景替代 ThreadLocal）。

| 传播级别 | 语义 | 典型场景 |
|---|---|---|
| `REQUIRED`（默认） | 复用外层事务；内层异常标记外层 rollback-only，最外层提交前强制回滚并抛 `TransactionPropagationError` | 服务方法链共享事务 |
| `REQUIRES_NEW` | 新建独立事务（挂起外层），内层提交/回滚互不影响 | 审计日志独立落库 |
| `NESTED` | 基于外层开 SAVEPOINT，内层异常仅回滚到保存点，外层可继续 | 部分失败不影响整体的子任务 |

```python
from web_infra.capabilities.db import Propagation

async with db.orm_session() as outer:                       # 外层事务（owner）
    async with db.orm_session() as inner:                   # REQUIRED：复用外层
        ...
    async with db.orm_session(propagation=Propagation.REQUIRES_NEW) as audit:  # 独立事务
        ...
    async with db.orm_session(propagation=Propagation.NESTED) as part:          # SAVEPOINT
        ...
```

边界（务必知悉）：
- **rollback-only**：REQUIRED 内层抛异常会把外层标记为 rollback-only，即使外层 catch 住不抛出，最外层提交时也会强制回滚并抛 `TransactionPropagationError`（杜绝"内层失败外层提交"）。
- **跨任务不传播**：ContextVar 不进入 `asyncio.gather` 子任务，子任务内的事务独立（与 Spring 子线程不继承事务一致）。
- **连接池压力**：`REQUIRES_NEW` 每层占用一条连接，嵌套过深有池耗尽风险，建议限制嵌套深度。
- **SQLite**：同步参考实现同样支持三传播；`REQUIRES_NEW` 使用独立连接，`:memory:` 模式数据隔离（生产用文件库）。隔离级别对 SQLite 静默忽略。

### 3.2 事务隔离级别（数据源级默认 + 会话级覆盖）

默认值以 `IsolationLevel.DEFAULT` 表示（= `None`，即不显式注入，让数据库使用默认：MySQL InnoDB 为 REPEATABLE READ）。两级控制：

**数据源级（引擎默认）**：在命名数据源上配置 `isolation_level`（`app.db.datasources.primary.isolation_level`，或编程 `MySQLConfig(isolation_level=...)`），对连接池所有连接生效。`DEFAULT`/缺省则不注入。

**会话级（方法覆盖）**：`orm_session(isolation_level="SERIALIZABLE")`，仅在事务创建点（最外层 / REQUIRES_NEW）生效；REQUIRED 复用外层时忽略（避免污染外层连接）。

> ⚠️ **强约束**：MySQL 方言 `set_isolation_level` 内部会执行一次 `COMMIT`（`SET SESSION TRANSACTION ISOLATION LEVEL ...` 后紧跟 `COMMIT`），因此**禁止在已开启事务内设置会话级隔离级别**——会话级隔离级别只能在"新建事务、尚未执行任何 SQL（未触发 autobegin）"时传入，否则会把当前事务内已执行的操作意外提交。REQUIRED 复用外层时框架已忽略该参数（安全）。

```python
async with db.orm_session(isolation_level=IsolationLevel.READ_COMMITTED) as session:
    ...
```

选型建议：默认保持 REPEATABLE READ；报表/统计等读多写少场景可按需 READ COMMITTED 降低间隙锁；资金类强一致场景 SERIALIZABLE 需谨慎评估性能。

## 4. DatabaseManager 多数据源与租户路由

多数据源（命名池 / 混合多源 / 租户独立库）配置后，`app.state.db` 装配为 `DatabaseManager`（见 `application.py::_build_db` 与 `database_manager.py`）：

```yaml
app:
  db:
    # 方式〇（推荐）：命名数据源池 app.db.datasources（default 指向默认数据源；业务 db 无参取它）
    default: primary
    datasources:
      primary: { type: mysql, host: mysql-1, database: order_db }
      audit:   { type: sqlite, path: ":memory:" }
    # 方式一：通用混合多源（每实例带 type 字段，缺省 mysql；MySQL 与 PostgreSQL 等可并存）
    instances:
      order: { type: mysql, host: mysql-1, database: order_db }
      audit: { type: pg,   host: pg-1,    database: audit_db }   # pg 需按 §12 注册
    # 方式二（向后兼容）：app.db.mysql.instances 多租户独立库（全 MySQL，无 type 字段缺省 mysql）
    router:
      mapping: { t1: order }          # 租户 -> 数据源名 显式映射（优先）
      pattern: "tenant_{tenant_id}"   # 未命中时的命名模板（默认）
```

> 方式〇（datasources 命名池）段非空时优先，未配置 `default` 时唯一数据源自动取它、多数据源回落名为 `default` 的数据源（不存在则启动期报错）。

```python
# 按名获取
order_db = db.get("order")
async with order_db.session() as session:
    ...

# 按租户路由（DatabaseManager.route，切换前强制 T-1 租户权限校验）
conn = db.route(tenant_id)   # 无租户上下文或与当前上下文租户不一致 → PermException
async with conn.session() as session:
    ...
```

路由与安全要点（整改 T-1 / T-4，2026-08-15）：

- **T-1 越权防护**：`route()` 必须与 `RequestContext` 中的当前租户一致才放行，否则抛 `PermException`；构造参数 `enforce_tenant_check=False` 可关闭（仅测试/内部无上下文路径）。
- **T-4 租户注销**：租户删除/归档后 24h 内调用 `await db.unregister_tenant(tenant_id)`——注销路由映射 + 关闭并释放该租户连接 + 触发注入的 `cache_invalidator` 回调删除该租户缓存前缀（如 `web:*:{tenant_id}:*`）。
- 业务访问统一入口：`db.session(name=...)` / `db.orm_session(name=...)`，未配置的数据源名抛 `RuntimeError`。

## 5. 读写分离（ReadWriteRouter）

规范 S10-2：读流量路由从库（轮询），写走主库。MySQL 从库在**连接配置层**声明（`mysql_config.py` 的 `replica_urls`），路由由 `ReadWriteRouter`（轮询 + 线程安全）负责，从库名为 `replica_0..N`：

```python
from web_infra.capabilities.db import MySQLConfig

config = MySQLConfig(
    url="mysql+aiomysql://root:pass@127.0.0.1:3306/demo",
    datasource_name="order-db",                  # 池名（慢 SQL/池指标/泄漏标签）
    replica_urls=[
        "mysql+aiomysql://root:pass@127.0.0.1:3307/demo",   # replica_0
        "mysql+aiomysql://root:pass@127.0.0.1:3308/demo",   # replica_1
    ],
    replica_username="replica_user",             # 缺省复用主库账号
    replica_password="replica_pass",
)

db = MySQLDatabase(config)

# 读流量走从库（轮询 replica_0 → replica_1 → ...）
async with db.orm_session(read_replica=True) as session:
    rows = (await session.execute(select(Order))).scalars().all()

# 写流量（默认）走主库
async with db.orm_session() as session:
    session.add(Order(...))
```

降级行为（源码事实）：`read_replica=True` 但**未配置从库**或**从库不可用**时回退主库并记 warning（`mysql_read_replica_not_configured_fallback_to_primary` / `mysql_read_replica_not_available_fallback_to_primary`）；从库引擎与主库同款池参数，且同样注册慢 SQL 分级告警与连接泄漏检测。`ReadWriteRouter.route(operation)` 支持 `"read"` / `"write"` 决策，可单独复用。

## 6. 多租户 SQL 注入（TenantQueryFilter / TenantAwareMixin / TenantGuard）

多租户由 `app.tenant.enabled: true` 开启（默认关闭），启用后 `app.tenant.strict`（默认 true）控制强隔离模式。核心是**租户条件自动注入**，业务代码禁止裸写 `AND tenant_id = ?`（规范 §8 红线）。

**模型侧**：租户表继承 `TenantAwareMixin`，自动注入 `tenant_id` 列（`VARCHAR(64) NOT NULL`，带索引）：

```python
from web_infra.capabilities.db import TenantAwareMixin, Base

class Order(TenantAwareMixin, Base):
    __tablename__ = "orders"
    id: int = ...
    # 租户联合索引声明（规范 T-5：以 tenant_id 为首列）
    __tenant_compound_indexes__ = [("tenant_id", "biz_id")]
    __table_args__ = (*Order.tenant_indexes(),)
```

**过滤侧**：`TenantQueryFilter` 挂载到会话工厂后，通过 SQLAlchemy 事件自动生效（`tenant_query_filter.py`）：

- `do_orm_execute`：SELECT 自动附加 `tenant_id = 当前租户`；UPDATE/DELETE 重写语句附加同样条件；
- `before_flush`：INSERT 自动填充 `tenant_id`；strict 模式下已有值必须与当前租户一致，跨租户写入/删除直接抛 `E2-PERM-000`；
- 无租户上下文：strict 抛 `E2-PERM-000`，兼容模式回落 `no-tenant` 占位。

**守卫侧**：`TenantGuard` 供非 ORM 场景（如文本 SQL / 数据源切换）统一校验：

```python
from web_infra.capabilities.db import TenantGuard

tenant_id = TenantGuard.require_tenant(strict=True)   # 无租户上下文抛 E2-PERM-000
async with db.session() as session:
    rows = await session.query_all(
        "SELECT * FROM orders WHERE tenant_id = :tenant_id", {"tenant_id": tenant_id}
    )
```

`TenantGuard.current_tenant()` 返回当前租户（无租户返回 `no-tenant` 不抛错）。装配由 `Application` 完成：引擎初始化后经 `MySQLDatabase.install_tenant_filter(filter)` 挂载（引擎已建则立即挂载，未建则延迟到引擎创建完成）。

## 7. 分页：PageQuery / CursorPageQuery

`PageQuery`（LIMIT offset 分页）与 `CursorPageQuery`（游标分页）位于 `page_query.py`，遵循规范 §12.3（全局统一 pageNo/pageSize）与 S10-1（**拒绝深分页**）：

```python
from web_infra.capabilities.db import PageQuery, CursorPageQuery

# LIMIT offset 分页：offset+page_size 超过 10000（PARAM_COMMON_MAX_OFFSET）直接抛 ValueError
q = PageQuery(page_no=3, page_size=20)
# q.offset == 40, q.limit == 20
PageQuery(page_no=501, page_size=20)   # 501*20=10020 > 10000 → ValueError：请改用游标分页

# 排序参数结构化（规范 §12.2：禁止裸字符串拼接；字段白名单由业务校验）
sort, order = q.order_clause()         # 如 ("created_at", "desc")

# 游标分页（深分页推荐方案）：首页 cursor=None，后续页携带上一页最后一条的排序字段值
q = CursorPageQuery(cursor="cursor-abc", page_size=20)
```

SQL 组装示例（业务侧）：

```python
async with db.orm_session() as session:
    stmt = select(Order).order_by(Order.id)
    if q.sort:                        # 白名单校验后映射为 SQLAlchemy 排序表达式
        stmt = stmt.order_by(getattr(Order, q.sort).asc() if q.order == "asc" else getattr(Order, q.sort).desc())
    rows = (await session.execute(stmt.offset(q.offset).limit(q.limit))).scalars().all()
```

注意：游标分页**不受** 10000 阈值约束（`CursorPageQuery` 无偏移校验），`page_size` 上下限（≥1 且 ≤ 全局最大 page_size）由 pydantic 统一校验。

## 8. MySQL 配置项与慢 SQL / 连接泄漏监控

`application.default.yml` 中 `app.db.mysql` 全量配置项（与 `MySQLConnectionSettings` 字段一一对应）：

| 配置项 | 默认值 | 说明 |
| ---- | ---- | ---- |
| `host` / `port` / `database` | `127.0.0.1` / `3306` / `""` | 连接地址 |
| `username` / `password` | `${APP_DB_MYSQL_USERNAME:root}` / `${APP_DB_MYSQL_PASSWORD:}` | 敏感项走环境变量 |
| `charset` | `utf8mb4` | 字符集 |
| `use_ssl` / `check_hostname` / `ssl_ca` | `true` / `true` / `""` | SSL 安全默认开启（规范 §10）；无证书环境显式 `use_ssl: false` |
| `connect_timeout` | `10` | 连接建立超时（秒）；aiomysql 0.3.x 不支持 socket 读写超时参数，故无 read/write 超时配置 |
| `statement_timeout_seconds` | `0.0` | 语句执行超时（0 不启用；>0 通过会话变量 `max_execution_time` 生效，仅 SELECT） |
| `pool_size` / `max_overflow` | `8` / `8` | 连接池大小 / 溢出上限 |
| `pool_recycle` | `1800` | 空闲回收（建议小于 MySQL wait_timeout/2） |
| `pool_timeout` | `8` | 从池取连接超时（秒） |
| `echo` / `pool_pre_ping` | `false` / `true` | 打印 SQL / 借出前 ping |
| `slow_sql_threshold_seconds` | `0.2` | 慢 SQL 告警阈值（P2 warning） |
| `slow_sql_critical_seconds` | `2.0` | 慢 SQL 严重阈值（P1 error） |
| `leak_detection_threshold_seconds` | `10.0` | 连接泄漏检测阈值（秒） |
| `instances` | `{}` | 多租户独立库（旧格式，见 §4） |

**慢 SQL 分级告警（§18.5.3）**：引擎通过 SQLAlchemy `before/after_cursor_execute` 事件计时，超阈值记录日志 + `record_slow_sql` 指标；SQL 摘要经 `_sql_preview` **脱敏**（去除引号字面量、仅保留语句骨架、长度截断 200），参数绑定值绝不进日志/指标。

**连接泄漏检测（§10.6）**：监听连接池 `checkout` / `checkin` 事件，借出超过 `leak_detection_threshold_seconds` 未归还判定泄漏，递增 `MYSQL_POOL_CONNECTION_LEAK_TOTAL{datasource}` 并告警。

**连接池指标（§18.5.4）**：`db.update_pool_metrics()` 刷新推送式池指标（health 端点统一调用），引擎未初始化时各项置 0。

其他源码事实：引擎**延迟初始化**（首次建连时才创建，`asyncio.Lock` 保护并发）；连接 `init_command` 固定 `SET time_zone = '+00:00'`（UTC 会话时区，规范 §16.1）；`pool_pre_ping` 默认开启防断连。

## 9. MongoDB 接入（Beanie）

MongoDB 默认关闭，`app.mongo.enabled: true` 后经 `MongoDatabaseRegistry` 装配（默认 `type: beanie`，Beanie + PyMongo AsyncMongoClient）：

```yaml
app:
  mongo:
    enabled: true
    type: beanie
    url: mongodb://localhost:27017
    database: app
    username: ${APP_MONGO_USERNAME:}
    password: ${APP_MONGO_PASSWORD:}
    max_pool_size: 50
    min_pool_size: 10
    max_idle_time_ms: 600000
    connect_timeout_ms: 10000
    server_selection_timeout_ms: 30000
    socket_timeout_ms: 60000
    wait_queue_timeout_ms: 10000
    heartbeat_frequency_ms: 10000
    retry_writes: true
```

使用（`app.state.mongo` 为 `MongoDatabase`）：

```python
mongo = app.state.mongo

# 1) 集合级会话（MongoSessionInterface 契约，屏蔽 Beanie/PyMongo 差异）
async with mongo.session() as session:
    oid = await session.insert_one("orders", {"order_no": "SO1", "amount": 100})
    doc = await session.find_one("orders", {"_id": oid})
    await session.update_one("orders", {"_id": oid}, {"$set": {"status": 2}})

# 2) Beanie Document 模型注册（可选；未注册时降级为集合级访问）
from beanie import Document

class OrderDoc(Document):
    order_no: str
    amount: int
    class Settings:
        name = "orders"

await mongo.register_document_models([OrderDoc])

# 3) 多文档事务（需 MongoDB 副本集；单机无副本集时 start_transaction 抛 OperationFailure）
async with mongo.transaction() as session:
    await session.update_one("accounts", {"_id": "a"}, {"$inc": {"balance": -100}})
    await session.update_one("accounts", {"_id": "b"}, {"$inc": {"balance": 100}})
```

会话契约 `MongoSessionInterface`（`mongo_session_interface.py`）为「集合名 + dict」的集合级形态：`insert_one/insert_many/find_one/find_many/update_one/update_many/replace_one/delete_one/delete_many/count/aggregate/distinct/create_index`，返回归一化（插入返回 `_id` 字符串、更新/删除返回计数）；非事务会话 commit/rollback 为空操作。连接惰性（首次操作建连），`health_check` 为 ping。

## 10. Redis 配置（RedisConfig）

`RedisConfig` 管理 redis-py 异步连接池（Redis 本质为数据库，故归入 db 模块），是缓存后端与 JWT 状态存储的底层（见 [07-缓存](./07-缓存.md)）：

```python
from web_infra.capabilities.db import RedisConfig

config = RedisConfig(
    host="localhost", port=6379, db=0,
    password=None, username=None,
    max_connections=50, decode_responses=True,
    socket_connect_timeout=5, socket_timeout=5,
    socket_keepalive=True, health_check_interval=30, retry_on_timeout=True,
)
client = await config.connect()      # 建连 + ping 校验；重复调用幂等
await client.set("k", "v")
await config.close()
```

`config.client()` 供中间件装配等**同步上下文**复用客户端（双重检查锁定，只创建一份实例）；`health_check()` / `update_pool_metrics()` 与 MySQL 同款语义。

## 11. FastAPI 依赖注入：provide_db_session

`provide_db_session(factory)` 构造一个 FastAPI 依赖，注入**生命周期已托管**的通用会话（`session_dependency.py`，内部即 `async with factory.session()`）：

```python
from fastapi import Depends
from web_infra.capabilities.db import DatabaseSessionInterface, provide_db_session

app = create_app()
db = app.state.db

@app.get("/v1/orders")
async def list_orders(session: DatabaseSessionInterface = Depends(provide_db_session(db))):
    return await session.query_all("SELECT * FROM t_order")
```

## 12. DatabaseRegistry 自定义数据库（PostgreSQL 等）

实现 `DatabaseFactoryInterface`（`create_session` / `session` / `close` / `health_check`）并注册进 `DatabaseRegistry`，即可接入 `create_app`——单库替换（`app.db.type: pg`）或与其他数据库并存（`app.db.instances` 混合多源），无需改动框架装配代码；未注册的 type 装配期抛 `ConfigError`（避免拼写错误静默回落 sqlite）。

```python
from contextlib import asynccontextmanager
from web_infra.capabilities.db import DatabaseFactoryInterface, DatabaseRegistry

class PostgresDatabase:                       # 实现 DatabaseFactoryInterface 契约
    def __init__(self, params: dict) -> None:
        self.params = params                  # 连接参数来自 app.db.pg 段
    async def create_session(self):
        ...                                   # 返回 DatabaseSessionInterface 实现
    @asynccontextmanager
    async def session(self):
        session = await self.create_session()
        try:
            yield session
            await session.commit()
        except Exception:
            await session.rollback()
            raise
        finally:
            await session.close()
    async def close(self): ...
    async def health_check(self) -> bool: ...

# 注册（模块导入即生效；同名覆盖）
DatabaseRegistry.register("pg", lambda params: PostgresDatabase(params))
```

```yaml
app:
  db:
    type: pg                 # 单库替换
    pg: { host: pg-1, database: audit_db }
```

> 说明：接入时工厂入参为实例连接参数字典（单源取 `app.db.<type>` 段；混合多源取 `app.db.instances.<name>` 实例项，`datasource_name` 由装配注入）。含生命周期/横切性质的插件（第三方 SDK 初始化与释放）建议走统一扩展注册器 `app.extensions`，二者关系见 [使用说明.md §4.3](../使用说明.md#43-统一扩展注册器插件扩展点appextensions)，完整可运行示例见 [examples/demo_datasource_extension.py](../../examples/demo_datasource_extension.py)。

## 13. 常见坑

1. **最小安装没有 MySQL**：报 `ModuleNotFoundError: sqlalchemy` 说明未装 `[mysql]` extra（延迟导入设计，业务项目需显式安装）。
2. **SSL 默认开启导致无证书环境连接失败**：开发环境显式 `use_ssl: false`（生产保持开启）。
3. **`orm_session()` 在 sqlite 上不可用**：`SqliteSessionFactory` 是同步参考实现，无 ORM 会话能力，调用抛 `AttributeError`（MySQL 才支持 ORM 会话）。
4. **深分页被拒**：`page_no * page_size > 10000` 抛校验错误，改游标分页 `CursorPageQuery`。
5. **多租户下文本 SQL 不自动注入**：`TenantQueryFilter` 只拦截 SQLAlchemy ORM 语句；文本 SQL 场景用 `TenantGuard.require_tenant()` 手动取租户并拼条件（条件必须用命名参数）。
6. **租户相关表忘加 `tenant_id`**：不继承 `TenantAwareMixin` 的表不受拦截，租户数据会被全量暴露；规范要求租户相关表必须含 `tenant_id` 且为联合索引首列。
7. **连接池耗尽 / 泄漏**：确认所有会话都走 `session()` / `orm_session()` 上下文；结合 `db_long_transaction_total`、池指标与泄漏告警排查长事务与借出不还。
8. **慢 SQL 无告警**：确认 `slow_sql_threshold_seconds` 未被人为调大（默认 0.2s 即 P2 告警）；SQL 摘要已脱敏，定位用日志中的 `datasource` 标签。
