## 1. 扩展体系总览

框架提供**两个层次的扩展入口**，职责互补：

| 扩展入口 | 契约 | 解决什么问题 | 启用方式 |
| ---- | ---- | ---- | ---- |
| **能力注册表** `web_infra.core.capability` | `Capability`（能力名/说明/框架模块/前置/业务契约） | 能力依赖链显式化：启用支付自动带出 鉴权→认证→用户 | `app.capabilities.enabled` 配置声明（校验 + 拓扑序启用）或 `CapabilityRegistry.enable(name)` 运行时启用 |
| **统一扩展注册器** `web_infra.core.extension` | `ExtensionPoint`（name/requires/build/startup/shutdown） | 有生命周期/横切性质的插件（第三方 SDK 初始化与释放、启动订阅） | `app.extensions.enabled` 配置声明即启用 |

第三层是**领域 SPI 注册表**（`DatabaseRegistry` / `CacheBackendRegistry` / `ObjectStorageRegistry` 等），按名管资源工厂，负责「纯资源替换」（如新增 PostgreSQL 数据源）。三种机制的关系与边界见 [§3.4](#34-与领域注册表的关系互补)。

## 2. Capability 能力注册表

### 2.1 能力契约（Capability）

`Capability`（`core/capability/capability.py`）是 frozen dataclass，描述一个能力的「是什么 + 随能力启用什么 + 依赖谁 + 业务侧应实现什么」：

```python
@dataclass(frozen=True)
class Capability:
    name: str                    # 能力名（注册表键，如 user / authn / authz / pay）
    description: str = ""        # 能力说明
    modules: tuple[str, ...] = ()  # 随能力启用的框架模块（启用时按拓扑序自动导入；业务实现能力为空，如 user）
    requires: tuple[str, ...] = ()  # 前置能力名（按包含关系自动启用）
    contract: str = ""           # 能力契约（SPI / 业务实现要求；业务层据此落地实现）
```

**契约与实现分离**：`Capability` 只声明「契约」（依赖关系 + 业务实现要求），框架负责校验与装配；具体业务实现（如用户系统 user-service）由业务层按 `contract` 落地，框架侧只提供接入点（`RequestContext` 身份上下文、`SocialBindingStore`、`OAuth2Client`）。

### 2.2 类级注册与拓扑闭合（DFS + visiting 栈环检测）

`CapabilityRegistry`（`core/capability/capability_registry.py`）是**类级注册表**（类属性 `_capabilities: dict` + `threading.Lock` 保护并发 register）：

- `register(capability)`：同名覆盖；能力名为空 / 依赖自身（`name in requires`）抛 `CapabilityError`；前置允许后置注册（未知前置在解析/校验时拦截）。
- `get(name)` / `names()`：查询与清单（按注册顺序）。

依赖展开核心是 `_topological_closure(names)`——**递归 DFS 展开传递前置 + visiting 递归栈环检测**：

```python
def dfs(name: str) -> None:
    if name in seen:
        return
    capability = cls._capabilities.get(name)
    if capability is None:
        unknown.add(name)            # 未知能力计入 unknown，不中断展开
        return
    if name in visiting:             # 环：name 已在当前递归栈
        cycle = tuple(visiting[visiting.index(name):] + [name])
        ...
        return
    visiting.append(name)
    for requirement in capability.requires:
        dfs(requirement)             # 先展开前置
    visiting.pop()
    seen.add(name)
    chain.append(capability)         # 前置在前，目标最后（拓扑序）
```

- 环检测基于**当前递归栈（visiting）**而非全局 visited：只有真正构成环的路径才报告，环路径按栈内片段 `visiting[index:] + [name]` 输出（如 `("a", "b", "a")`）。
- `seen` 保证已处理能力不重复入链（去重保序）。

### 2.3 resolve / validate / enable 语义

| 方法 | 语义 | 失败行为 |
| ---- | ---- | ---- |
| `resolve(name)` | 按包含关系展开传递前置，返回 `CapabilityResolution`（目标能力 + 拓扑序能力链 chain + 去重后的待导入框架模块 modules） | 未注册 / 依赖循环抛 `CapabilityError` |
| `validate(enabled)` | 装配校验，返回 `CapabilityValidation`（`ok` / `unknown` 未知能力 / `circular` 循环链路 / `closure` 完整闭包 / `chain` 拓扑序）。**缺前置不视为失败**——按包含关系自动补足 | `ok=False` 时由调用方给出明细 |
| `enable(name)` | `resolve` 通过后按拓扑序自动 `importlib.import_module` 各框架模块（幂等） | 同 `resolve` |

```python
from web_infra import CapabilityRegistry

resolution = CapabilityRegistry.resolve("pay")
assert [c.name for c in resolution.chain] == ["user", "authn", "authz", "pay"]  # 启用支付自动带上前置
assert resolution.modules == ("web_infra.capabilities.security", "web_infra.capabilities.payment")

validation = CapabilityRegistry.validate(["pay"])
assert validation.ok and validation.closure == frozenset({"user", "authn", "authz", "pay"})
```

### 2.4 内置依赖图：user → authn → authz → pay

`builtin_capabilities.py` 导入即注册全部内置能力（`register_builtin_capabilities()` 幂等）：

| 能力 | 框架模块 | 前置 | 契约要点 |
| ---- | ---- | ---- | ---- |
| `user` | 无（业务实现） | - | 用户系统：注册/登录/资料/绑定；框架侧接入点 `RequestContext` / `SocialBindingStore` / `OAuth2Client` |
| `authn` | `web_infra.capabilities.security` | `user` | 认证：JWT 签发/校验、Token 存储、三方登录、OAuth2 |
| `authz` | `web_infra.capabilities.security` | `authn` | 鉴权：`PermissionGuard` RBAC |
| `pay` | `web_infra.capabilities.payment` | `authz` | 支付：渠道 SPI + 回调 + 骨架兜底 + 对账/冲正/风控 |

平级能力（无前置）：`ai`（`web_infra.capabilities.ai`）、`mq`、`storage`、`registry`、`config`（`web_infra.infra.config`）、`db`、`cache`、`search`（`web_infra.capabilities.search`，无前置，全文检索 SPI + ES 生产实现）。

核心依赖链的语义：**「你是谁」→「你能做什么」→「你付钱」**——认证依赖用户系统才有意义，鉴权依赖认证，支付依赖鉴权。启用 `pay` 时闭包自动含 `user/authn/authz`，无需逐一声明。

### 2.5 create_app 装配钩子：app.capabilities.enabled 校验

`Application._setup_capabilities`（装配顺序第 ② 步）读取 `app.capabilities.enabled`：

```python
enabled = self.settings.get("app.capabilities.enabled") or []
if not enabled:
    return                                            # 默认 []，不启用任何可选能力
validation = CapabilityRegistry.validate(enabled)
if not validation.ok:                                 # 未知能力 / 循环 → ConfigError 快速失败
    ...
    raise ConfigError("能力装配校验失败：...", key="app.capabilities.enabled")
for name in enabled:
    CapabilityRegistry.enable(name)                   # 按拓扑序导入框架模块
```

```yaml
app:
  capabilities:
    enabled: [pay]   # 自动启用 鉴权(authz)→认证(authn)→用户系统(user)（业务实现由业务层提供）
```

> **默认状态**：`app.capabilities.enabled` 默认空（`[]`），业务可选能力链（user / authn / authz / pay）默认全部关闭，需按需启用。框架内置模块能力（config / db / cache / mq / storage / registry / ai）的框架代码随核心安装即可用（内存/本地实现开箱即用），在 `enabled` 中声明仅用于显式装配校验与依赖展开。

### 2.6 业务自定义能力

业务层按同一机制登记业务能力并声明依赖：

```python
from web_infra import Capability, CapabilityRegistry

CapabilityRegistry.register(Capability(
    name="order",            # 业务能力名
    description="订单域（业务实现）",
    requires=("pay",),       # 依赖支付 → 自动带出 authn / user
    contract="订单业务由业务层实现",
))
CapabilityRegistry.enable("order")   # 或 yml 声明 app.capabilities.enabled: [order]
```

## 3. Extension 统一扩展注册器

### 3.1 扩展点契约（ExtensionPoint）

`ExtensionPoint`（`core/extension/extension.py`）是插件协议对象（frozen dataclass）：

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `name` | str | 扩展点名（注册表键，与 `app.extensions.enabled` 匹配） |
| `description` | str | 扩展点说明 |
| `requires` | tuple[str, ...] | 前置扩展点名（按拓扑序先启用；未知/循环装配期快速失败） |
| `build` | `ExtensionBuilder \| None` | 装配期构建器，签名 `(options, ctx) -> 实例`；`options` 为 `app.extensions.<name>` 配置段，`ctx` 含 `{"settings", "components"}` |
| `startup` | `ExtensionHook \| None` | 启动钩子，入参 build 产物（同步/异步皆可） |
| `shutdown` | `ExtensionHook \| None` | 停机钩子，入参 build 产物（同步/异步皆可） |

注册规则（`ExtensionRegistry.register(extension, overwrite=False)`）：**同名默认拒绝**（抛 `ExtensionError`，显式 `overwrite=True` 才覆盖，避免误覆盖内置/已注册条目）；扩展点名不能为空、不能依赖自身；`get`（未注册返回 None）/ `names` / `unregister`（静默）。

### 3.2 声明即启用与拓扑序构建

`Application._setup_extensions`（装配顺序第 ④ 步，组件之后、中间件之前）读取 `app.extensions.enabled`：

1. `ExtensionRegistry.validate(enabled)`：未知扩展点 / 依赖循环 → `ConfigError` 快速失败；缺前置自动补足（闭包展开）。
2. 按 `validation.chain`（拓扑序）逐一 `build`：`entry.build(options, ctx)`，`options` 为 `app.extensions.<name>` 配置段，`ctx = {"settings": ..., "components": ...}`；无 `build` 的扩展点实例为 `None`。
3. 实例挂 `app.state.extensions`（name → 实例），同时保存 `_extension_chain`（拓扑序清单）供生命周期编排。

```yaml
app:
  extensions:
    enabled: [my_plugin]      # 声明即启用（默认 []，业务按需声明）
    my_plugin:                # 扩展点配置段，透传给 build 的 options
      endpoint: https://example.com
```

```python
from web_infra import ExtensionPoint, ExtensionRegistry

def build_client(options, ctx):
    # options: app.extensions.my_plugin 配置段；ctx: {"settings", "components"}
    return SdkClient(endpoint=options.get("endpoint"))

async def close_client(client):
    await client.close()

ExtensionRegistry.register(ExtensionPoint(
    name="my_plugin",
    description="第三方 SDK 插件（启动初始化/停机释放）",
    build=build_client,
    startup=lambda client: client.connect(),   # 同步/异步皆可
    shutdown=close_client,
))
```

### 3.3 生命周期编排

`Application._lifespan` 中（详见 [01-系统架构.md §4](./01-系统架构.md#4-生命周期)）：

- **启动**：`_run_extension_startups` 按 `_extension_chain` 拓扑序调用 `startup(实例)`（前置先启动）；
- **停机**：`_run_extension_shutdowns` 按**逆拓扑序**调用 `shutdown(实例)`（后启先停），且**先于框架组件 close**——插件可能依赖框架组件（如 Redis 客户端），先用完再关底层；
- 钩子同步/异步皆可（返回 awaitable 自动 await）；钩子异常不吞，启动失败即应用启动失败。

```ascii
装配期    build（拓扑序，after 组件 before 中间件）
启动期    startup 钩子（拓扑序：parent → child）
停机期    shutdown 钩子（逆拓扑序：child → parent）→ 框架组件 close
```

### 3.4 与领域注册表的关系互补

- **领域注册表**（`DatabaseRegistry` / `CacheBackendRegistry` / `ObjectStorageRegistry` / `MessageQueueRegistry` / `ServiceDiscoveryRegistry` / `SearchEngineRegistry` 等）：按名管**资源工厂**，装配期实例化（如 `app.db.type=mysql`）；适合**纯资源替换**（新增 PostgreSQL 数据源、自定义缓存等），已支持混合多源并存。
- **扩展注册器**（`ExtensionRegistry`）：管**插件协议对象**（build/startup/shutdown 生命周期 + 依赖顺序）；适合**有生命周期/横切性质的插件**（第三方 SDK 初始化与释放、启动订阅、定时资源）。

两者互补不冲突，插件可自行选择接入路径。冲突避免规则（与框架生态一致，不引入平行体系）：同名默认拒绝、命名带命名空间（如 `datasource.postgres`、`sdk.loki`）、契约只进不退（钩子均可选）、延迟启用（未在 `enabled` 声明不实例化）。

## 5. 自定义扩展完整步骤示例

### 5.1 新增一个数据库类型（PostgreSQL）

走**领域注册表**（纯资源替换）。实现 `DatabaseFactoryInterface` 契约（`create_session` / `session` / `close` / `health_check`），可选能力 `session_factory`（SQLAlchemy 异步会话工厂，供 `SqlAlchemyModelConfigStore` 复用）、`install_tenant_filter`（多租户）、`orm_session`：

```python
# my_pg_database.py（create_app 前 import 即注册，幂等）
from contextlib import asynccontextmanager
from typing import Any, AsyncGenerator

from sqlalchemy import text
from sqlalchemy.ext.asyncio import async_sessionmaker, create_async_engine

from web_infra.capabilities.db import DatabaseRegistry


class PgDatabase:
    """PostgreSQL 数据库工厂（DatabaseFactoryInterface 最小契约 + 可选 session_factory）"""

    def __init__(self, host="localhost", port=5432, database="app", username="postgres", password=""):
        self._engine = create_async_engine(f"postgresql+asyncpg://{username}:{password}@{host}:{port}/{database}")
        self._session_factory = async_sessionmaker(self._engine, expire_on_commit=False)

    @property
    def session_factory(self) -> Any:
        """SQLAlchemy 异步会话工厂（可选能力：供框架组件复用）"""
        return self._session_factory

    async def create_session(self) -> Any:
        return await self._session_factory()

    @asynccontextmanager
    async def session(self) -> AsyncGenerator[Any, None]:
        """进入创建会话，退出自动提交（异常回滚）并关闭"""
        async with self._session_factory() as session:
            try:
                yield session
                await session.commit()
            except Exception:
                await session.rollback()
                raise
            finally:
                await session.close()

    async def close(self) -> None:
        await self._engine.dispose()

    async def health_check(self) -> bool:
        try:
            async with self._session_factory() as session:
                await session.execute(text("SELECT 1"))
            return True
        except Exception:
            return False


def build_pg(params: dict[str, Any]) -> PgDatabase:
    """数据库工厂（DatabaseRegistry 工厂签名）：入参为 app.db.pg 段或 app.db.instances 实例参数"""
    return PgDatabase(**{k: v for k, v in params.items() if k != "datasource_name"})


DatabaseRegistry.register("pg", build_pg)   # 注册后 app.db.type: pg 即可装配
```

```yaml
# application.yml
db:
  type: pg
  pg: { host: localhost, port: 5432, database: app, username: postgres, password: ${APP_DB_PG_PASSWORD:} }
```

或**多源并存**（`app.db.instances` 每实例带 `type`，装配为 `DatabaseManager` 按名获取），详见 [SPI-Extensions.md §4.2.1](../SPI-Extensions.md#421-自定义数据库接入与使用示例两种方式)。

### 5.2 自定义缓存后端

实现 `CacheBackendInterface`（`get`/`set`/`delete`/`exists`/`set_empty`/`is_empty`），注册进 `CacheBackendRegistry` 后按 `app.cache.type` 装配：

```python
# my_cache.py
from web_infra import CacheBackendInterface, CacheBackendRegistry


class MyCacheBackend(CacheBackendInterface):   # Protocol 结构子类型，无需继承
    async def get(self, key): ...
    async def set(self, key, value, ttl=None, ttl_jitter_seconds=None): ...
    async def delete(self, key): ...
    async def exists(self, key): ...
    async def set_empty(self, key, ttl=60): ...
    async def is_empty(self, key): ...


CacheBackendRegistry.register("my_cache", lambda settings: MyCacheBackend())
```

```yaml
app:
  cache: { type: my_cache }
```

未注册的 type 装配期 `ConfigError` 快速失败（`_resolve_registry`）。

### 5.3 自定义日志输出通道

实现 `LogSinkInterface`（`create_handler(options) -> logging.Handler`，框架统一挂载格式器与脱敏过滤器），注册进 `LogSinkRegistry`，在 `app.logging.sinks` 声明即启用：

```python
# my_log_sink.py
from web_infra.infra.logging import LogSinkRegistry


class HttpLogSink:   # LogSinkInterface 为 Protocol，方法签名匹配即可
    def create_handler(self, options=None):
        return MyHttpLogHandler(**(options or {}))   # options 为 app.logging.sinks.<name> 配置


LogSinkRegistry.register("elk", lambda options: HttpLogSink())
```

```yaml
app:
  logging:
    output: console
    sinks:
      elk: { url: http://log-collector:8200 }
```

未注册的通道名在 `configure_logging` / `create_app` 装配期快速失败（`ValueError` → `ConfigError`）。

### 5.4 自定义搜索引擎

实现 `SearchEngineInterface`（索引生命周期/写入/删除/关键词检索，全部 async），注册进 `SearchEngineRegistry`（与 `CacheBackendRegistry` 同构）后按 `app.search.type` 接入：

```python
# my_search.py
from web_infra import SearchEngineRegistry, SearchEngineInterface, SearchQuery


class MySearchEngine(SearchEngineInterface):
    async def create_index(self, tenant_id, index_name, *, mappings=None, settings=None): ...
    async def delete_index(self, tenant_id, index_name): ...
    async def index_document(self, tenant_id, index_name, doc_id, document, *, refresh=False): ...
    async def bulk_index(self, tenant_id, index_name, documents, *, refresh=False): ...
    async def delete_document(self, tenant_id, index_name, doc_id, *, refresh=False): ...
    async def search(self, tenant_id, query: SearchQuery): ...


SearchEngineRegistry.register("custom", lambda settings: MySearchEngine())
```

```yaml
app:
  search:
    enabled: true
    type: custom
```

### 5.5 业务能力注册（订单能力依赖支付）

业务层登记业务能力并声明依赖，随 `app.capabilities.enabled` 校验并启用：

```python
# my_capabilities.py
from web_infra import Capability, CapabilityRegistry

CapabilityRegistry.register(Capability(
    name="order",
    description="订单域（业务实现）",
    requires=("pay",),            # 自动带出 authz → authn → user
    contract="订单业务由业务层实现",
))
```

```yaml
app:
  capabilities:
    enabled: [order]   # 闭包 = {order, pay, authz, authn, user}
```

## 6. 能力契约与业务实现分离

两个扩展入口遵循同一原则：**框架只负责契约（SPI）与校验/编排，具体实现由业务层提供**。

- **Capability**：框架声明 `user→authn→authz→pay` 依赖包含规则并校验装配（未知能力/循环快速失败），`contract` 字段向业务描述"该能力业务侧应实现什么"；框架侧只提供接入点（SPI + 装配校验），不提供用户系统、认证、支付的业务实现（支付渠道如微信 `WeChatPayProvider` 由业务按 `PaymentChannelTemplate` 契约接入）。
- **Extension**：框架只负责注册、依赖校验与按序调用钩子，`build`/`startup`/`shutdown` 的具体逻辑完全由业务插件提供。

好处：技术栈不锁定（业务可替换任意 SPI 实现而不改框架代码）、能力可裁剪（未启用的能力不加载）、依赖关系显式（启用能力自动带上前置，缺失依赖装配期即暴露而非运行期才炸）。
