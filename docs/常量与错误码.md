# 常量与错误码总览

> 框架常量与错误码的唯一权威清单。业务代码（含两个脚手架）新增常量/错误码前**必须先查阅本文档与错误码注册表**，防止冲突或重复定义。

## 1. 常量分类总览

常量按域分类管理（规范 §5.3），每个分类一个常量类，值唯一权威来源为分类常量类，`web_infra.infra.constants` 重导出保持一致。

| 前缀 | 分类 | 常量类 | 错误码大类 | 说明 |
| ---- | ---- | ---- | ---- | ---- |
| `HTTP_` | HTTP 状态码 | `HttpStatusConstant` | — | 值复用 starlette.status，业务禁止散落状态码字面量 |
| `AUTH_` | 认证/权限 | `AuthConstant` | E2 | JWT、请求头、Scope、权限点 |
| `INFRA_` | 基础设施 | `InfraConstant` | E3 | 超时、重试、连接池、Nacos、MQ、缓存 Key 模板 |
| `PARAM_` | 参数 | `ParamConstant` | E1 | 分页默认值、阈值 |
| `SYS_` | 系统 | `SysConstant` | E5 | 日志级别、错误码大类、成功码、匿名/系统用户 |
| `BIZ_` | 业务域 | `BizConstant` | E4 | 预留空壳；业务域常量由各业务模块自行定义 |
| — | 缓存 Key | `CacheKeyBuilder` | — | 缓存 Key 模板统一生成，禁止手写拼接 |

引用方式（统一从 `web_infra.infra.constants` 导入）：

```python
from web_infra.infra.constants import AuthConstant, InfraConstant, HttpStatusConstant, CacheKeyBuilder
```

## 7. 缓存 Key 模板（CacheKeyBuilder）

统一按 `web:{module}:v1:{biz}` 模板组织（§5.7），动态段运行时注入，业务禁止手写拼接。

| 模板常量 | 模板 | 用途 |
| ---- | ---- | ---- |
| `AUTH_TOKEN` | `web:auth:v1:token:{user_id}:{jti}` | 用户令牌 |
| `AUTH_USER_TOKENS` | `web:auth:v1:user_tokens:{user_id}` | 用户令牌列表 |
| `LOGIN_FAIL_COUNT` | `web:auth:v1:login_fail_count:{username}` | 登录失败计数 |
| `LOGIN_LOCK` | `web:auth:v1:login_lock:{username}` | 登录锁定 |
| `LOGIN_IP_FAIL_COUNT` | `web:auth:v1:login_fail_count_ip:{ip}` | IP 登录失败计数 |
| `LOGIN_IP_LOCK` | `web:auth:v1:login_lock_ip:{ip}` | IP 登录锁定 |
| `DISTRIBUTED_LOCK` | `web:common:v1:lock:{key}` | 分布式锁 |
| `CAPTCHA` | `web:common:v1:captcha:{captcha_id}` | 验证码 |
| `MODEL_CONFIG` | `web:common:v1:model_config:{code}` | 模型配置缓存 |
| `IDEMPOTENCY_OCCUPY` | `web:idem:v1:occupy:{key}` | API 幂等占用（§12.6） |
| `IDEMPOTENCY_RESULT` | `web:idem:v1:result:{key}` | API 幂等结果（§12.6） |
| `MESSAGE_IDEMPOTENCY` | `web:mq:v1:msg_idem:{key}` | 消息消费幂等（§9.2） |

TTL：`AUTH_TOKEN_TTL_SECONDS=7200`、`LOGIN_FAIL_TTL_SECONDS=1800`、`LOGIN_LOCK_TTL_SECONDS=1800`、`MODEL_CONFIG_TTL_SECONDS=300`。

> 业务模块自定义缓存 Key：按 `web:{模块}:v1:{业务}` 模板在**业务模块自己的常量类**中定义，禁止与上表重复。

## 8. 错误码体系

### 8.1 格式与分类（规范 §4）

格式：`E<大类>-<子类/域>-<3位编号>`，成功码 `S0000`。

| 大类 | 语义 | 默认 HTTP | 日志级别 | 可重试 |
| ---- | ---- | ---- | ---- | ---- |
| S | 成功 | 200 | INFO | — |
| E1 | 参数 | 400 | INFO | 否 |
| E2 | 认证/权限 | 401（PERM→403） | INFO | 否 |
| E3 | 基础设施 | 500（LOCK→423） | ERROR | **是** |
| E4 | 业务域 | 422（COMMON→404/409） | WARNING | 否 |
| E5 | 系统 | 500 | ERROR | 否 |

- 统一抛出约定：业务代码统一 `raise 错误码.to_exception(message=...)`，域专属异常（`ParamException`/`PermException`/`AuthException`）仍用构造函数。
- 边界收敛：出网响应 E3/E5 收敛为大类前缀码 + 大类默认文案（`E3`→"服务暂时不可用，请稍后重试"、`E5`→"系统繁忙，请稍后重试"），其余透传（§4.6.1）；服务端日志保留完整错误码。
- 反查：`CommonErrorCodeEnum.of(code)` / `AiErrorCodeEnum.of(code)`；注册表 `ErrorCodeRegistry.get(code)`。
- 登记：支付域错误码（E3-PAY/E4-PAY）定义于 `web_infra/capabilities/payment/payment_error_code.py`，随模块导入自动登记注册表（`ErrorCodeRegistry.register`）；支付为可选能力，仅显式 `from web_infra.capabilities.payment import ...` 引入时登记（不随 `web_infra` 顶层导入触发）。

### 8.4 搜索引擎错误码（SearchErrorCode）

> 搜索引擎错误码域前缀 `SRCH`（`src/web_infra/search/search_error_code.py`，模块导入即登记注册表）。
> 基础设施调用类 E3-SRCH（可重试）/ 业务状态类 E4-SRCH（不可重试），与支付错误码 E3-PAY/E4-PAY 同分层规范。

| 常量 | code | 默认文案 | HTTP | 大类 | 可重试 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| `SEARCH_ENGINE_ERROR` | `E3-SRCH-000` | 搜索引擎调用失败 | 502 | E3 | 是 |
| `SEARCH_INDEX_ERROR` | `E3-SRCH-001` | 索引操作失败 | 502 | E3 | 是 |
| `SEARCH_NOT_CONFIGURED` | `E4-SRCH-001` | 搜索引擎未配置/未注册 | 422 | E4 | 否 |
| `SEARCH_QUERY_INVALID` | `E4-SRCH-002` | 检索参数非法 | 422 | E4 | 否 |
| `SEARCH_INDEX_NOT_FOUND` | `E4-SRCH-003` | 索引不存在 | 404 | E4 | 否 |

- 索引命名常量（`SearchConstant`）：真实索引名 `{index_prefix}_{tenant_id}_{index_name}`（全文）与
  `{index_prefix}_{tenant_id}_vector`（向量）；`index_prefix` 默认 `web`（`app.search.index_prefix` 覆盖）；
  默认业务索引名 `default`；分页默认 `size=10`、上限 `100`；高亮标签 `<em>`。

## 9. 新增/变更规范（防冲突）

1. **先查文档再定义**：新增常量/错误码前，先检索本文档与代码（`Grep`）确认不存在同名/同值定义。
2. **错误码**：新增业务错误码在**业务模块自己的错误码枚举**中定义（继承同一 `ErrorCode` 结构），编号段按域分配（如订单域 `E4-ORDER-xxx`），并同步登记注册表（`ErrorCodeRegistry.register`）。框架只维护通用（E1/E2/E3/E5 通用位）与 AI（E4-AI）错误码。
3. **常量**：框架级常量按前缀归入对应分类常量类；业务模块常量（权限点 `AUTH_PERM_*`、缓存 Key、MQ Topic）在**业务模块自己的常量类**中定义，禁止修改框架常量类。
4. **HTTP 状态码**：一律引用 `HttpStatusConstant`（值复用 starlette.status），业务代码禁止散落状态码字面量。
5. 修改框架常量/错误码后，同步更新本文档与对应测试（规范一致性要求）。
